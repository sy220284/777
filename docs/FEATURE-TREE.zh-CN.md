本清单是随代码维护的功能索引，系统架构约束仍以 [架构 3.0](ARCHITECTURE.md) 为准。

- **何时更新**：新建、删除、重命名、拆分、合并、迁移功能或子功能；调整归属、用户可见入口、运行方式、共享能力或平台边界；有关 PR 合并、关闭或替换时。
- **更新依据**：先核对最新主线及所有未合并 PR 的实际改动和生产装配，再与当前架构、功能归属和代码位置交叉验证；不把文件名、UI 文案、待办计划直接当作已交付能力。
- **状态规则**：主线已有的功能按正常节点展示；仅存在于未合并 PR 的变化标注具体 PR 编号；合并后移除对应“待合并”状态并按主线重核；关闭未合并的变更从清单移除或依据实际替代 PR 重新标注。
- **同改同核**：此 Markdown 与 [交互式树状图](FEATURE-TREE.zh-CN.html) 是同一份功能清单的两种视图。更新时逐项比对节点名称、上下级关系、PR 状态、代码定位及整体数量，不得只修改其中一份。
- **验证边界**：任何宣称“已完成、已实现、可运行”的判断都必须有对应实际代码与运行／测试依据；未做完整验证时仅陈述能力归属。不得以此清单替代架构审计或设备验收。

## 本轮实现定位与验证边界

- `RecoveringDocumentFile` 持久记录待恢复状态；FAIL_CLOSED 消费者重复读取、重建对象和恢复前写入均拒绝空历史初始化。保留原损坏内容，不自动猜测恢复结果。
- `DurableFileCommit` 与 `JournalDocumentFile` 提供先同步快照和备份、再清空 WAL 的提交顺序；Memory 与 Automation 各自维护 codec、归约及调度水位。故障注入证明阶段中断可恢复，不冒充真实掉电测量。
- Persona/Gallery 热读取先核对文件戳及已验证状态；导入、重置、备份变化、损坏恢复会重新验证。
- `TurnContextPlacement` 共享上下文放置算法；Work 保留完整技能规则及超限拒绝。`LocalHistoryCompactor` 仅保留压缩机制，摘要分别归 Chat/Work 策略。
- 团队事件 codec、纯 reducer 和运行命令分离；工作组合根将后台工具、智能体操作及邮箱恢复归还 Work 服务。模型请求保留唯一入口，使用参数对象及配置冻结阶段。
