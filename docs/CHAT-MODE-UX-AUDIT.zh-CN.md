# 聊天模式：产品与用户体验链路审视（2026-10-10）

> 基准：777 主线与 PR #604 V4 人物重构。属于代码与产品流程审计，未进行真人用户测试或真实模型长聊实验。该文档只评估 Chat，不包含 Work 的实施任务。

## 用户想得到的体验

用户进入聊天后，应能够明确知道“在跟谁说话、处于哪一条故事、人物知道什么、刚才做过什么”，随时修改角色、撤销失误、找回过去聊天、重开分支或继续下一场景。人物表现应来自自身经历与真实互动；关系、注意力、行动、长期记忆不能靠预设回复表演。聊天可以自然提供网页事实与图片输入，但失败不能吞消息或把隐形后台状态当作成功。

## 已有实现与验证边界

- **入口与人物**：通用聊天与绑定人物两条路径；人物编辑器采用核心身份 + 16类事实 + 世界书，21名预设。V4 人物事实由 Chat 持有；角色即时情绪、目标、关系、记忆由运行时持有。
- **上下文**：ChatTurnRunner 与 CharacterRuntimeProjector 产生稳定/动态提示；ChatContextAssembler 去重并裁剪；知识边界应依据故事阶段过滤。世界书按关键词、剧透等级和阶段召回。
- **连续互动**：ChatContextState、ChatCharacterState、人物日记/记忆选择器承担近期场景、共同经历、个人关系及较久历史；聊天后状态整理属于独立请求，失败有延后重试/恢复路径。
- **故事与恢复**：图集独立保存人物、故事、对话历史和阶段信息；归档及恢复使用会话存储与事件日志，不应从一条故事借用另一条的隐私或剧情知识。
- **群聊**：独立群成员状态和发言组织；关键需要验证多人物信息隔离、剧情阶段和单聊同源的规则。
- **模型操作**：前台请求与历史压缩、模型路由、图片输入、失败/取消和后台请求独立；能够触发 AI 补全、人物检查和用户下一句建议。

这些是代码支持的能力清单；不能由此宣称真实模型质量、恢复率、耗时或设备 UI 已全部通过。

## 产品问题分级（按用户损失）

| 级别 | 用户实际感受 | 代码发现/调整 | 后续验收 |
|---|---|---|---|
| P0 | 人物提前知道尚未发生的秘密 | 阶段事实和世界书联合过滤；后台旧快照不得回写故事阶段 | 单聊、群聊、主动消息、角色检查和重启后跨阶段一致 |
| P0 | 改好的人物设定又变回来或无意合并 | 显式编辑以快照为准；同名合并要求V4核心身份；世界书跨阶段ID唯一 | 删除、重命名、导入、二创同名、后台延迟保存组合测试 |
| P1 | 人物越来越空泛或答不出原作细节 | 预设不截断旧世界书；关联事实按需召回，不放大稳定提示预算 | 21名预设的具体问答、同义换词、反例与长聊 |
| P1 | 用户无法知道某条资料是否可靠 | 人物详情显示原作/作者设定/推断/待核实与阶段；稳定关键事实优先可信来源 | AI错误引用、用户修正、模型反事实提问 |
| P1 | 设定操作很复杂 | 基本项与高级项分层；支持直接选择已有剧情阶段 | 首次建卡、编辑3条事实、二创修改、保存退出/返回 |
| P1 | 记忆找不到或串故事 | 已有显式/隐式召回和日志隔离，相关检索依赖词面线索 | 换词指代、相似无关话题、纠正后失效、不同角色隔离 |
| P1 | 调整模型后编辑/重发报错 | 有会话所有权、回合边界和失败恢复实现 | 模型档位/温度变化后重生成、编辑消息、流式断线与恢复的真实回放 |
| P2 | 联网给出过时答案 | 新闻和即时问题不缓存；原作考据短期缓存 | 相同问题跨时更新、断网、明确禁联网 |
| P2 | 后台整理无感知，人物偶尔状态异常 | 后处理与主回复分离且有失败重试 | 用户可理解的待处理/失败/恢复提示，不阻塞正常消息 |
| P2 | 群聊人物知道彼此私事 | 成员拥有自身动态状态，知识边界不能共用单一剧情范围 | 两个不同阶段人物、多故事共存、私密日记不外泄 |

## 已知未闭环的问题

1. **旧字段仍未全部删除**：PersonaProfile 依然保留旧性格、旧生活、世界简介等历史成员，预设、合并、分享、纠正规则、部分旧测试仍引用。已停止V4 AI与新版编辑器继续写入这些隐藏字段；最终移除前必须把信息无损映射到人物事实或世界书，并将独立行为设置保留在运行控制所有者。
2. **故事阶段的生效时间**：归档设置与当前正在进行的聊天会话是两条状态路径。现已保证下一次归档不会被旧会话覆写，但修改图集后是否立即影响正在进行的对话，尚需实际UI/会话联动验收；用户应看见清晰的生效反馈。
3. **剧情阶段与剧透等级**：现阶段阶段字符串采用精确匹配，尚非时间线图或自动阶段推进；需要真实角色故事样例检验多个连续阶段的召回效果。不能把用户可查看的资料等同于人物自己已经知道的事实。
4. **端到端证明**：CI单测仅证明覆盖的程序规则；仍需从真实建卡→聊天→保存→重启→换故事→发送→查看人物表现完成 Android 16/17 设备验收；联网、模型配额、长请求断流依赖真实服务环境。

## 当前优先路线

先保证设定真实性与持久化一致性，再确保长聊连续性及操作恢复，然后优化首次使用、输入负担、反馈可解释性。避免为“安全”直接禁用原有正常操作，也不要通过增加每轮模型调用来弥补人物资料召回不足。

验收需要区分：逻辑/单测通过、设备路径通过、真实联网/模型体验通过三种证据。最终状态以 PR 最新 Head 的 CI 为准。
