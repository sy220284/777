# Work 可靠执行与工具恢复升级（2026-10-11）

## 所有权与边界

本次遵守架构 3.0，继续使用 Session EventLog、Work 现有状态投影、LocalToolOutputStore、LocalToolRouter 与 TokenUsageAnalyticsStore。未引入新的独立任务状态库、授权边界或第二套执行入口。

## 已落地

1. **工作区说明**：系统管理的 `.dsh/tools/777-runtime-guide.md` 随安装/启动时的资产同步更新；已有用户 `README.md` 永不覆盖。Work 运行提示优先指向管理指南。
2. **工具发现**：保持 `#621` 已修复的保守自动激活；显式搜索改为分层证据评分。工具名精确匹配始终压过描述、能力族命中；目录仍从实时注册表取得，不设武断条数上限。
3. **工具原文**：`tool_output_read` 可在私有保留的结果中以 `query` 进行 UTF-8 字面量流式检索，返回位置用于 `start_byte` 定位。按会话隔离；超长原文不必整体送给模型。结果淘汰后给出明确的不可恢复提示，模型历史不再承诺永久可恢复。
4. **活跃结果引用**：Work 从原有历史与可信检查点派生当前需要的调用 ID，存储为会话私有的哈希引用清单，在容量淘汰时优先保留；设备重启后仍保留引用优先级，但不能超越磁盘配额。
5. **Work 检查点**：用户输入可以提供当前决定；用户明确宣布**此前所有方案/决定作废**时，记录来源事件水位，当前决定替代旧检查点决定，压缩与解析会保留此水位。模糊提到“旧方案”不会清空其他已确认决定。旧版无水位的检查点仍可读取。
6. **回归**：补充工具匹配排序、跨块多字节原文搜索、结果淘汰与会话隔离、明确废弃旧决定及不误清空、系统指南升级保留用户内容的测试。Android 16/17 的人物图集旧文案断言同步到当前界面文案。

## 不越界的事项

- 不把搜索性能、Token 缓存比例、进程退出或 Android 扩展未连接直接视为代码故障；缺少重复测量的项目先保留实测。
- 不覆盖 #623 已合并的 MiniMax 型号预算政策；型号和订阅方案额度仍以真实服务商返回为准。
- 可写持久团队成员的冷恢复仍遵守原副作用安全边界，不在未知副作用情况下自动重放写入。
- `LocalToolOutputStore` 的私有保留配额仍生效；本轮增加有界原文搜索和准确恢复状态，没有以取消空间约束换取表面可靠性。

## 验收

按 `docs/VALIDATION.md` 对实际 PR HEAD 跑 CI，包括模型工具回归、Android 16/17 仪表测试及相关静态门禁。工具结果跨字节边界、中文/emoji、清理和跨会话访问均需覆盖。长期 100+ 步模型实测、未连接的外部设备能力和模型在线 Token 校准，仍需对应真实设备或服务商环境证据，不能以单元测试冒充。
