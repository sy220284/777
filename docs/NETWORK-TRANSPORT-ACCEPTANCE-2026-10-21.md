# 777 网络连接稳定性与响应速度验收

本次在 PR #801 的基础上修复已定位的外围网络读取缺陷，保留 #801 的模型终态及 MCP 断线语义。

## 连接策略

- **短请求**：GitHub 仓库浏览和官方模型目录有明确的总期限，凭据请求不跟随重定向。
- **长请求**：模型 SSE 和媒体生成使用读空闲期限，不因整个生成耗时而过早强制终止。
- **安全重试**：GitHub 只读请求允许有限重试，写操作一经发送不得自动重放；模型/MCP 原受理证据继续决定续接与重试。
- **响应读取**：GitHub 浏览最大 2 MB，官方模型目录最大 512 KiB，媒体 JSON 最大 32 MiB，按收到的字节而非字符串长度限制；图片/视频下载保留原有文件限额和断点恢复。
- **取消**：GitHub 仓库浏览、连接器 API、ChatGPT JWKS 等取消应同步取消底层请求，不能继续提交过期结果。
- **代理**：保留现有 SSRF、DNS 固定、VPN Fake-IP 和 HTTP 代理边界，不能为提速绕过目标验证；PAC/代理故障须设备实测后再变更路由。
- **MCP**：现有工具调用必须保持“不自动重放潜在副作用”的语义。服务级私密认证和跨代理握手属于独立接入工作，需要安全凭据配置入口，禁止在模型可见工具参数里输入令牌。

## 回归矩阵（验收要求，非已执行成绩）

| 场景 | 必须验证 |
| --- | --- |
| 普通 Wi-Fi/蜂窝 | 模型首字节与总耗时，GitHub 浏览、媒体生成、更新下载 |
| VPN Fake-IP/系统 HTTP 代理/PAC | SSRF 边界无回退、错误分类与实际联网效果 |
| DNS/TLS/429/5xx | 明确区分不可重试和短暂故障，失败时无死循环 |
| 取消页面或任务 | HTTP Call 关闭，未完成的远端结果不再写入 UI |
| 模型 SSE 中断/MCP tools/call 断联 | 保留部分结果与受理证据，不重复计费或写入 |
| 超大响应/视频断点/下载中断 | 响应按字节限额终止，已有文件保留正确状态 |
| GitHub POST 在服务端已执行但响应丢失 | 网络端重试次数为零 |
| Android 16/17 设备 CI | 按真实测试结果记录，而非按提交成功推断通过 |

评价改善应基于同一网络环境下的 P50/P95 首字节时间、取消完成耗时、失败率和连接复用率。没有设备测量前不宣称固定的性能提升百分比。
