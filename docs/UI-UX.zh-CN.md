# UI / UX

本文描述当前主线的界面与交互原则。当前默认前端按 777 移动端交互规范组织页面层级、组件密度、导航、浮层与动效；保留自身业务模型、数据和功能入口，由 Compose Design System 承载基础视觉与交互规范。[澄境（Clear Realm）主题](design/clear-realm-theme.md) 仅保留为历史视觉参考，不再作为默认 UI 权威事实源。

核心目标：

```text
主任务优先
+ 低认知成本
+ 状态明确
+ 反馈及时
+ 专业能力按需展开
+ 性能稳定
```

当前客户端界面设计范围只覆盖手机。所有页面首先以单列手机布局成立，不为平板、大屏或分栏模式额外增加布局分支。


## 产品结构

777 的本机界面以两种模式为核心：

```text
本机 Harness
├─ 聊天模式
└─ 工作模式
```

两种模式共享 Agent 运行底座，但拥有独立 UI 状态投影和信息密度。

当前产品只保留 Android 本机运行模式，聊天与工作共享本机 Agent 底座。

## 移动端前端规范

本轮 UI 复刻直接以 参考 Android 安装包 与参考截图校准页面结构、视觉层级和操作路径，777 的业务状态与执行链继续由现有 Feature 持有。逐项证据与验收状态见 [复刻验收记录](design/reference-ui-parity.md)。

前端组件、页面结构、信息层级、排版、交互状态与动效遵循统一的移动端规范。实现时以用户操作体验和场景适配度为判断标准，Design System 只负责承载基础颜色、字体、间距和通用容器，不再反向要求所有业务页面长成同一种卡片。

执行顺序：

```text
页面结构 / 专用组件行为
→ 映射 777 已有功能
→ 保留清晰的页面层级与专用组件身份
→ 接入 777 状态与数据
→ 对照 APK 复核视觉、交互与状态
```

约束：

- 基础背景、文字、分隔、焦点和主操作遵循黑 / 白 / 中性灰与蓝色交互基线；状态色只表达真实成功、警告和错误。
- 普通列表、标题栏、Sheet、Dialog 可以共享基础壳层；Composer、Agent 集群、工具执行、文件、项目 / 工作区、模型、人物等核心场景必须使用适配自身场景的专用组件，禁止继续用同一套 GroupCard / CategoryRow 只换文字。
- 图标以高频操作及核心能力的信息层级为准：高频动作和核心能力允许专用单色图标；不再强制所有入口套 Feather 风格。仍禁止用彩色功能图标盒制造分类。
- Composer 是核心产品组件，必须按输入、附件、能力选择、发送、停止、运行、Agent 集群等真实状态改变形态。
- 动效按场景表达“正在工作”：搜索、思考、工具执行、Agent 招募 / 运行 / 完成等状态可拥有专属反馈；页面基础转场继续保持克制。
- 文件、项目 / 工作区、工具、模型、Agent、人物保留各自的信息结构和视觉身份；页面统一感来自底层排版和交互规则，不来自把业务内容压成同一种卡片。
- 外部产品的 WebView / 内置浏览器跳转功能不纳入 777 当前实现范围；777 自身 Agent 联网、Web 工具等执行能力照常保留。
- 777 原有业务能力、状态模型和安全边界继续保留；前端入口和页面组织遵循统一的信息架构，不为了界面调整删掉 777 已有能力。

777 功能与移动端前端入口对应关系：

```text
会话历史       ← 本机 Chat / Work 会话
项目 / 工作区   ← Workspace / 会话文件 / 结果
定时任务       ← Tasks / Automation
技能 / 插件     ← Tools / Skills / MCP / GitHub / Webhook
Work            ← 运行中心 / 工作执行
设置           ← 模型、记忆、外观、权限、诊断
人物相关       ← 人物图集 / 群聊 / 角色日记（仅 Chat 场景）
```

## 聊天模式

聊天模式优先保持“人物 + 对话 + 当前状态”。

主界面只常驻：

- 当前人物 / 群聊上下文。
- 会话标题。
- 必要运行状态。
- 消息内容。
- 输入。
- 附件。
- 发送 / 停止。

低频能力通过菜单、Sheet、Dialog 或设置页进入。

### 人物行为调节

聊天顶部提供轻量人物入口。

点击后打开 `CharacterBehaviorTuningDialog`，不增加独立页面层级。

可调：

- 亲密距离。
- 状态延续。
- 主动性。
- 表达开放度。
- 人物变化。
- 情绪余韵。
- 互动新鲜度。
- 原设遵循。
- 关系节奏。
- 关系阶段锁定。

设计要求：

- 默认自然值可直接使用。
- 用户无需理解内部参数模型。
- 当前状态用短标签和滑杆直接表达。
- 弹窗关闭后回到原对话位置。
- 调节参数不伪造共同经历或关系事实。

## 工作模式

工作模式优先显示“目标 + 执行 + 阻塞状态”。

主流程包含：

- 任务输入。
- 计划模式。
- 审批。
- Ask User。
- 执行状态。
- 后台任务。
- 主 / 子代理。
- 工具执行结果。
- 停止 / 继续。

低频诊断进入运行中心或设置，不长期占用对话正文。

### 能力可发现性

用户能够主动调用、能理解结果、会影响下一步行动的能力必须有可见 UI；内部恢复、投影、缓存与执行标识继续留在诊断层。

最终落位：

- 运行中心负责 Agent / 后台任务 / 执行进度。等待用户消息的 Agent 独立进入“需要你处理”区域并置于当前目标/进度之前；普通后台任务留在当前状态之后，待处理 Agent 直接提供续跑输入。
- “启动后台子代理”保留为运行中心顶部动作，任务输入使用 Bottom Sheet，避免常驻编辑器挤压运行状态首屏。
- 工具中心按“当前能力 / 连接与扩展”分组。代码智能、视觉、GitHub、MCP、Webhook 都提供用户可读说明，配置与低频操作进入下一层。
- GitHub 继续以 Agent 工作流为主，不额外复制完整 GitHub 客户端；界面说明 PR、Issue、Actions、仓库代码等能力以及写操作确认边界。
- LSP / 代码智能以“定义、引用、实现、类型说明、诊断、工作区符号”等用户语言展示，不直接把工具函数名作为主界面。
- Vision 说明图片、主屏与虚拟屏能力；屏幕像素离开设备前继续遵守现有逐次审批，不从工具页绕过执行链。
- Webhook 提供启停、地址、端口、令牌复制与轮换；只允许 127.0.0.1 回环监听，不提供局域网开关。
- 模型设置提供图片处理方式“自动 / 原生 / 工具”，使用已有 `LocalImageInputMode`，默认自动。
- 自动任务提供“执行完成后通知”；Chat 主动互动额外开放免打扰时间、最短主动联系间隔与连续未回复上限。
- 人物调节高级区仅在当前模型官方路由具有已核实的可调温度范围且采样参数实际生效时显示“表达变化度”；未知代理、固定温度和不支持温度的模型隐藏该项，保留模型默认采样。0 对应当前模型最低支持温度、100 对应最高支持温度；50 保持自然相处的默认位置，对 DeepSeek 映射为官方推荐的日常聊天 1.3（0..2），Gemini 对应 1.0（0..2），自然位置不显式发送采样参数，遵循 Gemini 3.x 官方建议；UI 区分模型默认与主动发送的温度值。单聊、群聊和主动互动共用同一映射，不更改其他人物参数或事实。工作及聊天的思考弹窗在原有推理滑块下增设五档温度滑块，仅标三处：工作为“严谨／自然／创意”，聊天为“呆瓜／自然／疯癫”。工作模式温度按会话独立保存，聊天模式复用人物 0～100 表达变化度，弹窗将精细数值投影到最近档，调整后通过已有角色持久化流程写回；双方读取同一数据，失败应显示提示。不支持温度的路由给出说明，思考导致采样无效时禁止虚假调节。
- Work 对话 Surface 继续保持低频状态投影，不订阅 jobs/resource 高频变化。需要关注的 Agent 状态集中到运行中心，Work 顶栏保留运行中心直达，避免后台任务持续触发整棵对话 UI 重组。
- VirtualDisplay、结构化输出等专业能力只在上下文真实存在时显示；Request Reconstruction、Session Projection、Checkpoint、execution id 等只进入技术详情/诊断。


### 工作过程

工作过程用于回答用户最直接的三个问题：“现在在做什么、刚才做了什么、做到哪一步”。

展示规则：

- 折叠态直接显示最近一步的具体语义摘要，不能只显示“处理当前步骤 / 运行任务步骤”这类模板分类。
- 计划模式同样属于工作过程：读取、搜索、检查、比较和分析时必须显示这一轮具体在核对什么、比较什么或判断什么，禁止退化为“检查相关内容 / 查找相关信息”等模板文案，也不能只显示工具类别。
- 展开态按模型执行步骤展示语义摘要；工具类别、操作数量和完成 / 进行中 / 失败状态作为次级信息。
- 当前仍在执行的最后一步必须显示“进行中”，不能把全部历史行都标成“已完成”后再另起一个模糊的处理中占位。
- 同一个模型步骤内的多个工具调用可以聚合，但不同语义步骤不得因为工具类别相同而合并成一条。
- 没有语义摘要的旧会话才退回通用工具分类。
- 对话正文不直接暴露原始命令、工具参数、完整路径、查询词或工具输出；这些细节留在诊断 / 运行中心。语义摘要使用模型已经生成的 progress 文本，并做长度与空白规整。

## 启动与恢复

- 应用启动后优先呈现稳定的本机主界面，不用全屏转圈等待 Runtime、插件和会话恢复串行完成。
- 启动准备期间可以先展示只读界面，但发送、模型身份变更和依赖未就绪能力的操作必须保持禁用，直到统一就绪边界完成。
- Runtime、插件注册、会话恢复等相互独立的初始化工作优先并行，失败必须落到可见错误状态，不能以隐藏加载状态掩盖失败。
- 可继续的后台 Agent 在应用重启、会话恢复或重新订阅后必须保留“Agent 身份 / 可发消息 / 可继续 / 待处理消息数”等用户可见状态；实时回调与恢复投影必须来自同一状态映射，禁止恢复后退化成普通后台任务。

## 发送反馈

本机发送只有三种结果：

```text
已开始
已排队
已拒绝
```

UI 必须明确区分：

- 当前正在处理。
- 会话正在切换。
- 队列已满。
- 模型未配置。
- 发送已真正进入运行链。

被拒绝的输入保留在草稿中。

不能出现“看起来发送了，实际没有进入队列”的状态。

## 输入区与“+”入口

聊天与 Work 共用同一套输入区交互规则：

- 输入框作为页面底部主交互面，常态保持紧凑，不长期展开第二排工具。
- “+”是统一能力入口；图片、文件、技能 / 工具、智能体团队以及只在当前模式可用的能力从这里进入，不在输入区四周平铺大量按钮。
- 发送使用右侧主动作；运行中切换为停止 / 排队语义，图标、禁用和 loading 状态必须与真实发送状态一致。
- 模型、模式、Plan、自动审批等开关使用轻量标签、分段或 Sheet，不创建彩色功能按钮组。
- 附件缩略图、选中能力与临时模式都必须可在发送前移除；发送被拒绝时原草稿和附件保持。
- Composer 展开 / 收起约 190ms，透明度约 120ms，保持无回弹；IME 展开时不改变主动作位置语义。

## Agent 集群

Agent 集群继续共用 Work 主界面，不新增独立一级页面。交互遵循多智能体协作流程，并映射到 777 已有 Agent Teams 语义：

```text
主界面 “+”
→ Agent 集群
→ 输入区切换“给 AI 团队派个活…”
→ Lead 生成并行任务 / 匹配与招募助手
→ 输入区上方出现紧凑集群状态条
→ 点击状态条打开 Agent 集群 Bottom Sheet
```

集群执行方式作为 Work 持久消息元数据保存；模型请求临时注入 Lead 指令，普通下一轮输入退出集群模式。用户正文和记忆输入保留原文。助手返回结果后任务保持进行中，Lead 核验并显式结算后才更新完成进度、解锁依赖。

主界面集群状态条只承担高频事实：

- 当前处于任务生成、助手招募、运行、等待依赖、完成或失败中的哪一阶段；
- 正在运行的助手数量；
- 已完成任务 / 总任务进度；
- 优先展示最多两个正在工作 / 正在启动的助手及其当前任务，其余成员显示数量提示；
- 阻塞与失败等需要关注的状态。

Agent 集群 Bottom Sheet 承担详细观察和必要干预：

- 助手列表、职责、当前工作和运行状态；
- 共享任务、负责人、依赖关系和阻塞；
- 选中助手后在同一 Sheet 内展开运行输出，不进入另一页面；
- 支持给 active 助手追加消息；
- 支持停止单个正在运行的助手；
- 支持停止全部正在运行的助手，并显示二次确认与消耗不可撤销提示。
- 团队恢复、助手停止中、停用与解散应显示真实状态，不被旧任务状态覆盖；无法接收消息的助手禁用发送。
- 运行输出支持在同一面板展开和复制当前保留内容，并明确历史保留范围；任务可展开同时查看负责人、依赖、冲突与完整说明。
- 继续处理和异常处理入口生成可编辑的团队请求草稿，保留已有输入，用户发送后由 Lead 核验并处理，不直接重放任务。
- 当前团队助手执行检索、分析与审查等只读工作，文件修改由 Lead 处理，面板应明确这一能力边界。

状态文案采用用户语义：等待开机、思考中、已完成、已停止、已下班、任务失败。Task DAG、revision、mailbox、Checkpoint 等实现术语不得进入普通界面。

视觉与动效继续服从统一前端规范：

- 集群入口、成员与任务统一使用单色 Feather 线性图标；
- 蓝色只表达选中、进行中和主操作；
- 集群状态条与成员展开使用 `DsAnimations.composerReveal` / `composerFade`，保持短时长、无回弹；
- 只有真实运行 / 招募状态允许持续状态呼吸；完成、停止与失败立即静止；
- 面板使用统一 `DsBottomSheet`，停止全部使用 `DsDialog`，不得再发明另一套浮层。
- 面板先展示任务进度、助手与团队任务；团队动态置于其后，常态展示最近三条，可展开查看最近十二条，避免动态挤占主要操作。
- 选中的助手以主题蓝色浅底与细描边表达焦点，展开区按职责、输出与消息操作分区；已完成任务恢复中性色，蓝色继续表示正在进行的工作。

[集群页面交互预览](design/agent-cluster-preview.html) 与 [渲染效果图](design/agent-cluster-preview.png) 是演示数据原型，覆盖浅色 / 深色、展开、异常、停止确认与 Lead 草稿；它不连接真实任务，也不替代 Android 实机验收。

## 会话与侧栏

侧栏承担：

- 新建会话。
- 当前会话。
- 历史会话。
- 会话搜索。
- 运行方式。
- 设置 / 管理入口。

原则：

- 高频会话操作靠前。
- 设置和诊断靠后。
- 当前上下文始终可辨认。
- Chat / Work 切换只切换侧栏内容，不自动收起侧栏；选择具体会话或进入独立功能后再关闭侧栏。
- 不把低频管理按钮长期堆在聊天正文顶部。

当前侧栏采用统一的稳定骨架，Chat / Work 只替换模式相关入口：

```text
应用标题 + 新建
→ 搜索
→ Chat / Work 分段切换
→ 当前上下文
→ 场景快捷入口
→ 置顶 / 最近会话
→ 工作区 / 任务 / 工具
→ 设置
```

Chat 场景快捷入口优先显示人物图集、群聊、定时互动 / 任务、角色日记；Work 场景优先显示运行中心、工作区、任务、工具。所有入口继续调用 777 既有业务能力，不新增重复的业务页面。

补充要求：

- 当前上下文卡负责让用户一眼辨认“正在和谁聊 / 正在处理哪个工作会话”，并显示人物故事线、模型或运行状态等轻量信息。
- 置顶会话必须有独立“置顶”分组和明确图钉标识，不能只改变排序而不说明原因。
- Chat 历史保留人物头像和群聊身份；Work 历史使用运行/任务语义图标与状态，不复用人物头像式表达。
- 模式快捷入口使用单列紧凑导航行；每行允许名称、一句说明和一个状态/数量，整行至少 48dp 可点击。说明文字在窄屏或大字体下允许扩展到两行，避免关键功能含义被截断。历史会话继续占据侧栏主要可滚动空间。
- 侧栏功能图标统一采用 24 单位网格、2 单位圆角描边、无填充的单色线性符号；同一侧栏禁止混入 Material 填充图标或另一套笔画语言。
- 图标负责快速识别，文字负责消歧；不得仅靠图标表达高风险或不可逆操作。

一级功能页继续复用同一侧栏宿主：

- 人物图集、角色日记、工作空间、运行中心、任务、工具和设置都不能通过替换侧栏宿主或全屏 Dialog 截断侧栏手势。
- 手机端一级功能页均允许右划打开侧栏；首次从侧栏进入一级功能时记录当时所在页面作为返回锚点。
- 连续通过侧栏切换人物图集、角色日记、工作空间、运行中心、任务、工具、设置等一级功能时，替换当前侧栏功能页，不把每次查看都追加到返回栈；返回一次直接回到最初打开侧栏时的页面。
- 页面内部的显式跳转继续遵循真实页面栈：从功能 A 内进入功能 B 后先回 A；从主界面直接进入功能页则回主界面。
- 一级功能内部的详情、编辑、预览、子目录等二级层级先消费系统返回；退回一级根页面后必须释放返回所有权给侧栏宿主：左边缘右划打开侧栏，右边缘返回、返回键和三键导航按来源锚点退出。被远程等独立宿主复用的页面可由独立宿主继续接管根层返回。
- 侧栏自身的搜索、批量选择等临时层级同样先消费返回：先退出当前临时状态，再下一次返回关闭侧栏，禁止一次返回跨越两层。
- 选择具体会话视为切换主上下文；只有底层确认接单后才清空功能页栈、关闭侧栏或消费通知 / 任务跳转请求，切换被加载态或并发会话事务拒绝时保留原界面和用户意图。
- 新建会话、人物故事会话和删除会话同样以真实接单 / 删除结果驱动界面收口，禁止先关闭弹窗、清导航或清选择状态后再假定底层一定成功。
- 未建立群聊时，群聊入口先完成成员选择，确认后一次创建可用群聊；取消不产生空群聊会话、不改变当前页面。

### 人物图集

人物图集采用低噪声的单列手机列表，不再使用大立绘双列卡片作为主浏览方式。

默认页：

```text
当前对话人物（仅在未保存 / 有更新时出现）
→ 人物标题 + 添加 / 管理
→ 搜索
→ 置顶
→ 其他人物
```

规则：

- 人物头像使用紧凑头像规格，列表行承担主要点击区域；禁止用 200dp 以上立绘卡占据首页主要空间。
- 人物行最小高度 64dp，头像保持轻量，名称、身份和必要元信息最多占两层文字。
- “添加人物”进入独立的页内二级视图；新建、导入和预置人物不与“我的宝贝们”长期混排。
- 预置人物点击“快到碗里来”后留在当前列表，不进入详情；成功后按钮原地显示“已抱走”，可继续添加其他人物。
- “管理”进入明确管理态：显示复选框、置顶按钮和拖动手柄。
- 用户手动排序按稳定人物 ID 持久化；新人物追加到既有顺序末尾，删除后自动清理失效 ID。
- 置顶人物独立显示在顶部，但仍保留置顶组内部的手动顺序。
- 搜索状态不允许拖动排序，避免在过滤结果中产生难以理解的全局顺序变化。
- 多选删除必须二次确认，并明确会同时删除人物故事记录。
- 长按可以作为进入管理态的快捷方式，但所有管理能力必须同时有可见入口，不能只依赖长按。
- 人物详情默认只展示紧凑人物头、当前关系 / 故事和主操作；人物资料、导出、删除等低频管理收进“人物资料与管理”。
- 人物形象图首次打开即按图片方向元数据自动转正并居中展示；不依赖手动旋转、偏移或透视校正。详情页始终以正向相片作为初始和唯一展示姿态。

### 子页面空状态

任何可独立进入的手机页面都必须覆盖：

```text
Loading
→ Error（说明 + 可恢复动作）
→ Empty（原因 + 下一步）
→ Content
```

禁止只有标题栏和大片空白。

- 工作空间为空时说明文件会在什么条件下出现。
- “涉及文件 / 产物 / 会话文件”分别解释各自来源。
- 运行中心没有任务时仍提供“启动后台子代理”主动作，并说明启动后会展示执行状态、待处理消息和结果。启动入口常驻在顶部动作区，任务输入使用按需 Bottom Sheet，避免新建操作长期挤占运行状态首屏。
- 日记、任务、工具等已有空状态继续沿用同一原则。
- 空状态只保留一个最有价值的主动作，避免再堆卡片或功能介绍。


## 设置首页

设置首页按用户任务直接分流，不再保留“通用 / 外观与会话”中间层：

```text
模型
├─ 模型设置
└─ 模型价格与消耗
   ├─ API 价格
   └─ 消耗计算

体验
├─ 个性化与记忆
├─ 外观与阅读
└─ 会话
   └─ 聊天流式过滤
```

“模型”集中模型配置与成本信息，“体验”只承接用户使用偏好；“会话”负责会话排序和聊天过滤入口。
应用用户界面只维护中文默认资源，不再暴露应用内或 Android 系统级语言切换入口。

## 设置菜单与页面层级

- 设置首页保持四个可辨认的分组：体验、模型、系统、维护。分组使用独立中性底板与细分隔线；每一行使用完整点击区，左侧同一规格的图标容器，右侧最多一个简短状态和导航箭头。
- 一级菜单只显示入口名称与真正有用的动态状态。解释性长文案、预览、开关、输入和密集参数属于下一层，避免首页连续出现两行说明和长串运行值。
- 高级页是四个二级入口：智能体设置、项目配置、本地会话存储、运行与诊断。详情在同一设置页面容器内导航，返回先回到高级菜单，再回到设置首页；所有权限与操作的原实现保留。
- 外观与阅读页面直接展示主题、配色、阅读与排版、背景图四组调节控件和实时预览，禁止再打开子级设置页面；页面整体可纵向滚动。配置区保留原始即时生效、参数持久化、图片选取与移除逻辑，表单统一使用可读的内边距。
- 菜单组块使用轻表面与 14dp 语义圆角，设置条目至少 56dp 高；不使用逐行独立大卡片或彩色图标块挤占屏幕，长状态在尾部截断且不得压缩标题和点击区。

## Page / Dialog / Sheet

手机端按任务深度区分承载方式。交互优先级：

- **完整页面**：持续浏览、文件预览、批量管理、编辑含多个层级的资料；使用应用侧栏宿主承载，保持页面返回栈。
- **底部弹层**：新建会话类型、人物快速选择、提问选项、重命名、单项编辑、诊断和短时配置。选项使用整行可触发的标题+说明结构，避免大按钮与说明分离。
- **长表单弹层**：滚动正文限制在可见视口内，保存 / 恢复等关键操作固定在底部；提交过程中禁用关闭与拖拽隐藏，失败后保留草稿。
- **居中确认框**：仅保留删除、终止、撤销权限等必须确认后果的决策；取消安全退出，结果使用就地反馈。
- **全屏查看器**：图片放大、文件产物及其他需要沉浸阅读的内容独立呈现，返回时恢复原会话位置。
- **日期与时间选择**：统一使用应用内原生 Compose 底部弹层，分步选择日期和时间；本地时区正确换算，禁止选过去的执行时间。



完整页面用于持续浏览和管理：

- 人物图集与人物详情。
- 角色日记。
- 工作空间与文件预览。
- 运行中心。
- 任务中心。
- 工具中心。
- 设置。

Bottom Sheet / Dialog 只处理短时局部动作：

- 人物快速切换与群聊成员。
- 人物行为调节。
- 群公告。
- 修改消息。
- 主动互动等参数较多的 Sheet 让设置区域独立滚动，保存 / 取消保持在底部可见，避免用户修改后还需回到底部寻找提交操作。
- 会话动作。
- Plan Review、审批与 Ask User。
- 模型选择、连接信息和低频编辑。

规则：

- 需要列表浏览、搜索、排序、批量管理或多步详情的能力使用完整页面，禁止塞进狭窄 Sheet 后形成“点进去只有一小块内容”的空洞体验。
- 浮层解决一次局部任务，关闭后保留原页面位置和草稿。
- 高风险操作必须给出明确后果。
- 需要用户决定的审批 / 提问保持靠近当前任务。
- 操作成功、失败等瞬时结果优先使用 Toast / 就地状态反馈，不把结果文本埋在长页面末尾。
- 默认视觉规格统一收敛：行圆角约 10dp、菜单约 12dp、内容块约 14dp、Dialog 约 16dp、Composer / 消息气泡约 18dp、Bottom Sheet 顶角约 20dp；业务页禁止自行新增更大的装饰圆角。
- Dialog 只使用轻微约 0.985 → 1.0 的淡入缩放，阴影保持极弱；Bottom Sheet 使用短 grabber、无额外标题工具栏；菜单保持轻边界、零 tonal elevation。

## 视觉

当前界面遵循统一 Design System，并以黑白灰层级、蓝色交互强调、单色线性图标和紧凑信息密度作为默认视觉基线。

要求：

- 优先使用项目已有颜色、间距、圆角、字号和按钮组件。
- 不在业务页面随意创建新的视觉语法。
- 主要信息保持清楚的层级差。
- 卡片只用于真实分组，不用卡片堆砌制造层级。
- 状态色表达状态，不承担装饰作用。
- 同一操作菜单中的图标使用一致的视觉语言；会话动作弹层底色与所在主界面表面保持同源，避免形成孤立色块。
- 主导航、侧栏和高频功能入口优先使用项目内 Feather 线性图标体系；新增图标沿用同一 24 × 24 网格、2 单位圆角描边与无填充规则，避免 Material / Feather 混搭。
- 浅色 / 深色都必须保持文本和控件可读性。

### 系统通知与应用身份

- 通知只使用 Android 规范的单色 small icon 作为状态栏 / 通知模板图标。
- 不用 LargeIcon 重复模拟应用头像；LargeIcon 仅用于通知内容真正需要的联系人、媒体等内容图。
- 启动器普通图标与 roundIcon 使用同一视觉资产和同一版本身份，避免不同系统入口显示不同旧资源。
- 更换应用身份图标时使用新的 launcher 资源 ID，并保留原地升级验证，降低厂商系统图标缓存造成的新旧图标混用。

### 自定义背景与阅读

设置首页直接提供独立的“外观与阅读”页面；自定义背景开启后继续沿用同一页面调整阅读与背景表现：

- 字号在 Android 系统字体缩放之上再叠加应用内倍率，范围 90%–130%。
- 字体粗细作用于全局语义文字，包括聊天、设置、侧栏、按钮、菜单、Dialog 与 Sheet，并保留标题、正文、说明和强调之间的层级。
- 组件透明度覆盖自定义背景上的卡片、输入区、阅读层、顶部栏、侧栏、Sheet、Dialog 与 Menu；主操作/危险按钮继续保持明确实色，不同 Surface 保留各自可读性安全范围。
- “智能对比保护”默认开启，继续分析背景亮度、对比度、饱和度与细节密度，在复杂背景下提高可读性。
- 用户气泡与助手阅读层在自定义背景下都必须有可辨识的细边界；两者正文使用同一字号与行高，角色差异通过对齐、容器和颜色表达。
- 设置页普通标题、说明和数值遵循左侧文字、右侧控件/数值的统一对齐方式；说明文字不使用无意义居中。

## 触控与无障碍

- 所有独立可点击、可切换、可展开的交互目标至少提供 48dp 触控区域；视觉图标本身可以更小。
- 文本操作、分段选择、菜单项、展开箭头和卡片点击都遵守同一触控下限，不用 20–36dp 的视觉尺寸直接充当点击区域。
- 大字号下不遮挡核心操作。
- 输入法展开时输入区仍可操作。
- 长标题可截断但不能挤掉关键按钮。
- 状态不能只靠颜色区分。
- Dialog / Sheet 必须有清楚的关闭路径。
- Android 返回操作优先关闭当前浮层，再离开页面。

## 动效与状态反馈

动效用于解释“发生了什么”和“页面去了哪里”，不用于装饰。

- 页面层级进入 / 返回使用统一的短位移 + 淡入淡出，方向与导航栈一致。
- 进入下一层时，新页面只从右侧约 10%–12% 宽度进入，旧页面只反向离开约 5%–6%；返回完全反向，禁止大幅整页横移造成“页面漂浮”。
- 同级一级页面切换只保留 4–8dp 级轻位移 + 淡入淡出，约 150–170ms；不能套用完整 push / pop 动画。
- 页面动效参数统一由 `DsAnimations` 提供，页面不得各自内联另一套 tween / spring 时长。
- Predictive Back 必须消费手势 progress：真正返回上一层时页面随手势轻微右移，最大位移约 32dp；取消手势使用无回弹收束动画平滑复位。
- 左边缘手势继续遵守产品既有侧栏语义；只有 `POP_FEATURE` 返回路径驱动页面 Predictive Back 位移，避免侧栏手势和页面返回同时运动。
- Loading 必须优先表达正在等待的对象；整页等待使用人物、文件、工具、设备、执行等对应语义图标，不统一退化成无说明转圈。
- 上传百分比、流式生成、单项进度等已有明确进度含义的场景可以继续使用进度指示器。
- 只有真实 Loading 或真实 Running 状态允许持续运动；Done / Failed / 历史记录完成收束后保持静态。
- 实时 Work 步骤只让当前执行项轻微呼吸，不让整个列表同时闪动。
- 页面已有可用内容时，后台刷新保持内容稳定，只弱化刷新入口或显示局部状态，避免整页遮罩和闪白。
- 空态、错误态和加载态都走公共组件与 Design System，禁止页面各自硬编码另一套视觉语法。

### 流式回复和思考过程

- Chat / Work 的回复正文均使用同一 Markdown 阅读体系：正文保持主文字对比度，标题和加粗明显高于辅助元数据；代码块、表格与引用块取当前浅色/深色界面的中性表面色，避免孤立的青绿或低对比度灰块。
- 普通引用块正文保持主文字颜色和清晰竖线；显式 `[!IMPORTANT]`、`[!WARNING]` / `[!CAUTION]`、`[!NOTE]`、`[!TIP]` 使用清晰的语义标题和状态色，但不把普通引用误标为警告。
- Work 展开步骤按时间顺序将用户可见的语义说明与随后工具执行结果并为一个步骤；不重复显示“运行任务步骤”“检查相关内容”等空泛类别。无语义说明的遗留工具记录可使用安全的类别兜底，但不显示原始工具参数、内部路径和私有推理。
- 步骤图标使用统一 Feather 细线描边、18dp 视觉尺寸；当前步骤用主题强调色，完成步骤静止；失败状态在折叠及展开时都可辨识。成功步骤不重复挂“已完成”标签。
- 流式消息即使 Markdown 代码围栏暂未闭合，也应持续正常阅读；原始消息、工具结果和失败状态必须完整保留在底层记录及运行中心。
- Work 思考阶段采用细线完成图标、运行态简洁图标、失败警告图标；运行中默认展开，结束后默认收起；只要用户手动展开或收起过，本次任务内不再自动覆盖其选择。折叠的最近步骤必须保留较早的重要失败节点。
- Chat 与 Work 共用流式跟随能力，仅在读者位于尾部且未主动滚动时跟随，阅读历史不得被自动抢回尾部。
- 回答正文支持长按选取部分文字；代码块使用独立横向滚动，单行长命令和日志不强制自动折行；成功的原始工具调用在主回复中收敛，失败和执行中状态仍可追踪。
- Work 持久化事件与临时流式预览重合时只展示未提交的新增文本，防止同一段话在屏幕上出现两次。

## Compose 性能

UI 设计同时受性能约束。

当前规则：

- Chat / Work 使用独立状态投影。
- streaming preview 不进入整棵 aggregate state。
- 使用 `distinctUntilChanged` 避免无关更新。
- 历史消息分页的前台展示额度只按用户真正看到的对话计算：用户消息与最终助手回复计入额度，reasoning、tool、progress、system 等后台/内部消息不得挤占前台对话数量。
- Runtime 原始消息窗口继续保持有界；前台历史独立从 Session Event 增量补齐，短会话直接补足完整可见对话，长会话向上浏览时自动加载更早对话，只有加载失败才提供显式重试。
- 长列表不一次物化全部历史。
- 低频设置不进入高频对话状态。
- Dialog 自己承担局部状态和装配，避免继续膨胀 `LocalHarnessScreen`。

### Harness 合流约束

- 运行中心与 Agent 交互只消费主线 Harness 的结构化能力投影；Durable Inbox、Cold Resume、Session Projection 与 Agent Teams 继续以 #491 合入后的主线实现为唯一事实源。

### 会话推理与工具执行详情

- 加号菜单中的深度思考按会话保存。Chat 会话从未手动选择推理档位时，默认使用当前模型支持的快速档（DeepSeek 关闭思考，必须保留基础推理的模型使用其最低档）；Work 未选择时仍保留模型默认档位。用户手动选择的档位优先，手动恢复“默认”时不发送推理覆盖参数；不支持调节的模型不注入未知参数。
- GPT-6 Astra / GPT-6.1 Sol 的快速档仍保留基础推理，不能显示为彻底关闭思考。工具与协议不兼容的路线不开放切换。
- ChatGPT 套餐路线仅使用账号绑定的官方 Responses 配置与已确认的模型能力。未知模型保持默认；真实账号调用结果与模拟请求构造验证分别报告。
- 工作过程折叠摘要优先显示最近失败阶段，数量区分语义阶段与工具操作。人物心声的增量标记只在流式阶段隐藏，异常最终文本保留可见。
- 任务进度的工具行可打开原入口内的详情弹层，展示参数、结果、错误码和声明/开始/结果事件序号。列表预览有界，完整持久化记录按事件序号和调用身份从同一 Session EventLog 按需读取；不增加持久日志或页面。
