# 模型级上下文与执行预算（补充优化）

## 设计边界

根据模型型号与官方路由确定**运行预算**，再结合当前 Android 内存压力调节模型可见历史的字符上限。缓存敏感模型优先维持稳定的模型请求前缀。真正的计费、套餐消耗和可用额度始终以服务商账户为准，客户端没有“无限额度”的推断。

本轮沿用现有 \`LocalHistoryBudget\`、\`LocalPromptCachePolicy\`、\`LocalWorkExecutionBudget\`、Work Checkpoint/工具结果恢复；没有建立另一套平行历史或 Token 账本。

## 当前策略

| 路由 / 型号 | 聊天及 Work 历史字符预算 | Work 压缩目标 / 触发（占输入操作上限） | Work 执行片模型请求数 | 同时待决请求的估算 Token 预算 |
|---|---|---|---:|---:|
| MiniMax 官方 M3、M3.1 Flash Preview | 基线 2.0 倍，依内存压力收缩，最高 160 万字符 | 20% / 30% | 256 | 1,000,000 |
| MiniMax 官方 M2 / M2.1 / M2.5 / M2.7 系列 | 基线 1.4 倍，依内存压力收缩 | 30% / 48% | 160 | 512,000 |
| 其他官方路由与任意第三方代理 | 保持现有设置 | 沿用已有独立缓存策略；普通默认 28K / 36K | 128 | 512,000 |

- M3 官方预设窗口 1,000,000 Token，当前操作输入上限约 800,000；Work 投影目标约 160,000，触发约 240,000。M2.x 官方预设窗口 204,800，操作输入上限约 163,840，投影目标约 49,152，触发约 78,643。**这些是运行参数，不代表服务商允许的实际套餐剩余额度。**
- 聊天模式不运行 Work 的 128/160/256 次执行片预算；它共用按模型分配的 \`LocalHistoryBudget\`、输出预留、真实路由输入硬上限及内存压力保护。
- 执行片切换会按当前**主代理型号及路由**重新确定共享预算；主代理和同一 Work 的子代理仍共同消耗执行片配额。切换回未知/自定义模型会恢复默认值；旧执行片的在途请求不会丢失累计账本。
- 扩大 \`pendingWorkTokens\` 是提高**并行待决请求的估算占位**；这些数值不计入真实 Token 账本，也不改变模型服务器的上下文限制或设备级并发槽位。
- 本轮策略仅匹配官方域名加已知模型名称。第三方镜像、名称未知的模型、没有可靠公开窗口的路由，不推断获得 MiniMax 宽松预算。
- 官方 Token Plan 可通过订阅专用密钥用于第三方工具，但按套餐享有使用额度及并发限制。现有本地模型档案没有可靠的订阅/按量计费模式识别字段，因此目前宽松预算依据**官方型号与路由**，并不声称识别了套餐密钥；按量计费的 MiniMax 官方账户同样可能采用这些上限，用户应自行留意服务商使用量。

## 通用修复

1. \`LocalWorkspace.glob\` 支持常见的 \`**/*.{md,json,yaml,yml,txt}\` 扩展名选择；异常花括号改作字面量，不再抛出正则表达式语法异常。
2. 前台服务正常销毁造成通知设置读取协程取消时，不再作为异常日志重复上报。
3. 执行片策略切换延续原有共享账本、在途请求占位和续接状态；没有取消守卫和重复执行防护。

## 本轮未修改与后续验证

- 现有估算器依旧是 UTF-8 字节/3 的保守估算。本轮使用更高、按模型区分的压缩阈值减少过早折叠，**尚未**实现基于服务器实报 Token 的通用在线动态校准。
- Work 新近工具结果的内联展示与默认恢复页提升到 8 KiB（恢复页正文最多 7,936 字节，预留元信息字节），旧结果继续压缩为较短预览；完整结果按需通过 \`tool_output_read\` 恢复。
- Android 系统限制的 \`ForegroundServiceStartNotAllowedException\` 以及复杂网络断线的重连/续轮尚未修复，需要真实手机状态复现，避免用硬重启或重放副作用绕过操作系统限制。
- 代码回归侧重模型策略、历史预算、执行片重置与 glob。仍需升级 APK 后在真机测试 100+ 步多子代理长任务、后台切换与 Chat 长聊，验证压缩次数、缓存命中率和最终完成度。

## 12GB / 16GB 安卓手机资源分档

Android `ActivityManager.getMemoryClass()` 是应用 Java 堆分级，不是整机物理 RAM。新版启动时通过 `MemoryInfo.totalMem`、`availMem`、`lowMemory` 和 `isLowRamDevice` 评估物理内存、当时的可用内存及系统低内存告警；与 Java 堆限制取交集，不根据单一内存值盲目提高并发。下表以可用 RAM ≥2 GiB 且应用堆档足够为条件：

| 标称设备内存 | 并发模型请求 | 代理资源槽位 | 终端槽位 | 虚拟屏槽位 |
|---|---:|---:|---:|---:|
| 12 GB | 8 | 10 | 6 | 3 |
| 16 GB | 10 | 12 | 6 | 3 |

- 不再为低于 12GB 的设备设置独立性能档；检测到低于目标等级的设备只启用最多 3 路模型请求的保守兼容配置。此回退是防止旧设备失稳的安全保障，不作为独立推荐档位。
- 系统当前可用内存 1～2 GiB 时最多 4 个模型请求槽位，512 MiB～1 GiB 时最多 3 个，低于 512 MiB 或 Android 报告低内存时最多 2 个；应用堆不足会进一步压低预算。
- 没有获取到物理 RAM 的环境保守回落到应用堆分档。资源调度器控制实际同时执行的任务，不代表 10 个请求会全部立即发送，也不保证服务商允许对应并发或额度。
- 首次资源额度由启动内存快照确定；之后在新的资源租约申请时及系统内存/温度事件到达时重新评估内存、CPU 余量、温度与省电模式。并不持续启动后台轮询任务。降额只限制新租约，不取消已在执行的任务，设备恢复后再放宽。
- 主代理与子代理默认均为 512 步，用户配置范围上限为 1,024 步，仍使用已有「有效进展」驱动的自动动态扩步，不是绝对总任务上限。
- 只读任务图最多 128 节点，调度并行度按当前代理资源额度决定、最多 8；Agent Team 同时运行或预留成员上限 24，任务板最多 512 项。代理资源槽位和团队成员数是不同概念。
- 保持同一 Work 的共享请求配额和跨执行片持久化检查点；工作预算只是执行片上限，不是任务终生消耗上限。

## 12GB / 16GB 手机的上下文与后台任务补充升级

- **RAM 感知上下文字符预算**：在内存压力为 LOW、应用 Java 堆等级足够时，12GB 与 16GB 设备的普通历史字符预算分别为 900,000 与 1,100,000 字符。同步提升最近历史尾部与摘要容量；系统压力为 MEDIUM/HIGH 时分别收缩到 82%/65%。整机 RAM 未知、低于目标设备或应用堆不足时回落至原保守档位。主代理与子代理使用相同分档规则。
- **模型 Token 窗口独立**：字符预算是设备端历史存留上限，不会推高未知模型默认的 192,000 操作输入 Token 上限，亦不放宽已知模型的上下文窗口、输出预留与服务商配额。Work 原有的模型级早期压缩阈值按请求成本/缓存策略继续运行。
- **后台任务并发不再固定为四路**：Android 后台 JobManager 启动上限使用与共享资源调度器同一 RAM/堆/低内存快照，健康设备中 12GB 为 10 槽、16GB 为 12 槽；运行中随着共享调度器的代理额度一起降低或恢复新任务准入，已启动任务不被撤销。子代理仍需额外获得 AGENT 资源租约、模型请求仍需获得 MODEL_REQUEST 租约。任务总记录上限及恢复验证规则不变。
- **分层工具输出**：刚生成的 Work 工具结果最多直接展示 8 KiB；旧结果仍收缩为较短预览，完整正文由私有工具结果存储按需恢复。默认恢复页不超过新内联额度且准确返回下一 UTF-8 字节偏移，以避免回读跳字。Chat 工具结果仍受独立历史预算控制。
- 进程级共享调度器现在支持在运行中原子升降各资源池额度。监听 Android `onTrimMemory` 与热状态变更；Android 16 支持时读取 `SystemHealthManager.getCpuHeadroom`（0～100%），并遵守系统最小采样间隔；不支持时以真实内存、温度及省电模式决定额度。现有模型请求、代理、终端、虚拟屏与语言服务器统一获得可调整的租约，已获得的租约不会被强制撤销。

## 2025—2026 旗舰芯片动态性能适配

- 不根据「骁龙/天玑」品牌、主频或 NPU TOPS 直接放大额度，而根据 Android 实际反馈统一调度；避免为不同芯片维护硬编码设备白名单。
- 云端模型请求主要受网络、服务商限流与内存限制影响；普通 CPU 余量不足只降低本地代理、终端、语言服务及虚拟屏的**新任务准入**，不直接砍掉远程模型请求。严重热限制时模型请求也最多降低至 4／2 路。
- 本地任务在 CPU 余量低于 30%／15%、温控等级升到中度／严重／危急或系统省电模式开启时分级降额。随着设备恢复，新任务可以再次获得正常额度；原 12GB／16GB 上限不会被越过。
- Android 原有前台执行 Service、唤醒锁、Work 运行状态及持久化检查点继续承担后台执行。动态调度只改变任务准入，不伪装为解除 Android 后台服务启动限制；未经确认的外部副作用不可自动重放。
- 验收须覆盖 12GB 和 16GB 真机：并行模型／本地工具混合负载，温度升高与恢复，内存吃紧与恢复，灭屏与切出应用后任务及界面进度恢复。代码单测不能替代真机后台行为与散热测试。
