# 网络访问与最小必要校验规范

## 目标

功能编码以**正常运行、功能本身完善、用户体验**为首要目标。只有实际授权、明确风险或协议要求需要时，才增加安全限制和检查。默认允许正常模型 API、网页搜索、代理/VPN、MCP 和远程 Agent 配置；用户明确关闭网络或施加管理限制时按现有策略执行。

## PR #895 问题总结

| 问题 | 根因 | 整改方向 |
|---|---|---|
| 网页重复解析、重复准入 | 业务入口在 URL 解析器外又解析相同地址，叠加共享 HTTP 策略 | URL 交给 Resolver 一次解析，调用者在 DNS 前通过回调确认准入 |
| 搜索客户端重复域名检查 | 固定官网搜索在业务适配器重复实现全局 OkHttp 目的地策略 | 搜索复用共享客户端；认证请求继续禁止重定向 |
| MCP 一次操作多次验地址 | 连接入口、客户端工厂、工具调用、工作进程分别检查 | 建连时验证格式；创建真实连接和执行 RPC 时核对动态策略 |
| stdio 被 HTTP 域名名单误拦 | 误将任意子进程视为可按 HTTP 域名名单限流的请求 | 域名名单不拦本地 stdio；显式全局网络关闭仍生效 |
| 模型余额重复验同一域名 | 供应商策略已包含网络目的地检查 | 同一操作只调一次组合策略 |
| 模型路由隐式路径重复 | profileForRoute 已检查，resolveRoute 再次检查 | 隐式解析复用已有检查；显式/继承模型在实际执行前复核 |
| 远程 Agent 配置与探测重复准入 | 静态配置保存和动态连接授权混为一谈 | 离线可保存设置；真实探测/运行时检查授权，撤销及时停止 |

## 架构职责（同一逻辑只有一个 Owner）

- `LocalManagedExecutionPolicy` 是动态网络/模型管理要求的唯一事实来源；通过文件版本可失效快照避免每次都重读 JSON，同时在配置改变后重新加载。功能模块直接复用它，不再复制域名白黑名单合并规则。
- 应用共享 OkHttp 负责初始 HTTP 请求与库内部跳转后的目的地管理检查。**初始请求与内部跳转分别有意义**，不要为减少行数破坏逐跳验证。
- `LocalWebTargetResolver` 独占 URL 规范化、语法解析、DNS 解析、公网/SSRF 判断、DNS 固定和代理路由；策略回调在 DNS 前执行。代理 Host 与原始域名的请求标记也由 RequestRoute 统一提供给抓取、下载、诊断；跳转新网址时重新调用 Resolver。
- `LocalWebDiagnostics` 复用同一个解析器与准入回调，诊断动作在探测之前获得当前策略，不另造一套网络准入规则。
- 模型服务在配置选择和真正发出带凭据请求时执行职责清晰的检查，不对一个已验证的目标重复检查相同规则。
- MCP 客户端建连时校验静态 URL；worker 内 `LocalMcpNetworkAdmission` 在实例初始化时仅解析一次地址，OPEN/REQUEST 时复核动态策略，不在每次 RPC 重建解析结果。IPC 本地凭据更新、关闭等操作不做额外网络准入。
- stdio MCP 可执行本地任务；HTTP 域名白黑名单无法精确约束任意外部进程的网络访问，此能力边界必须向用户如实说明。全局网络显式关闭时按当前策略处理。
- 远程 Agent 管理配置可以离线保存；运行时身份、授权版本、TLS/凭据验证、撤销后停止由现有运行边界负责，无需在 UI、配置入口重复检查。

## 保留的独立必要保护

1. 网页抓取的 SSRF 防护、DNS 固定、直连 `Proxy.NO_PROXY`、系统代理 HTTPS 的 SNI / TLS 证书及主机名校验。
2. Android 与系统库标准 TLS；模型密钥不进入日志；带凭据的请求不向其他域名自动转发。
3. 已经建立的连接若目标变更，需要重新校验；用户取消任务或撤销远程授权后不得继续有副作用的执行。
4. 非幂等请求不在结果未知时自动重放；明确的大小、资源和协议边界继续适用。

## 新增安全策略/防御代码的审查门槛

动手前先逐项回答：要完成的用户功能是什么？具体现有失败证据是什么？谁已经拥有这个校验？平台或库是否原生提供？在执行边界校验一次能否解决？新增限制会误拦哪些合法输入、代理、端口、长任务和本地插件？如何证明正常路径有效？

无法明确举出独立风险、唯一 Owner 与正常使用情形，就先不要新增策略层。不要为了显示“更安全”而复制检查、随意加白名单、过小的超时、沉默兜底、平行网络客户端或无必要的审批。新增机制需要体系层统一评审后复用，不允许各功能自己造相似组件。

## 验收范围

- 模型 API 正常配置、连接测试、模型目录、推理、余额查询；显式受限时按策略提示。
- 网页搜索/抓取/诊断可用；代理/VPN、自定义端口与合法 HTTP/HTTPS 可用；跳转后的 SSRF、DNS 固定仍正确。
- HTTP MCP 和本地 stdio MCP 可用；域名名单不误拦本地 stdio；网络关闭后按当前策略拒绝受控网络操作。
- 远程 Agent 离线配置、在线探测、TLS 和授权撤销正常。
- 使用已有单元测试、编译、Android 运行测试核验正常路径、拒绝路径和连接恢复；避免新增无必要的重复门禁。

## 长期执行原则

**先把功能做对、做完整，再针对实证风险补最少必要的限制；架构统一维护一个 Owner、一套规则，业务入口直接复用。**
