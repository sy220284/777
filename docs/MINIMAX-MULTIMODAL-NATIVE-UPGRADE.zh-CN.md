## 界面方案（跟随 777 已有设计系统）

1. **设置根页／模型与体验**：当前选中的有效 API Key 模型来自 MiniMax 官方时，在“模型用量”后面显示“MiniMax 套餐额度”。进入后仍按同一选中模型账户查询；切到其他服务商立即隐藏入口并返回根页。国内／国际官方地域使用当前所选模型的原地域，不跨账号也不复用别人的密钥。套餐配额按周／当前周期显示；按量账户显示余额；失败、空数据和不在套餐均有明确状态。
2. **聊天框加号**：拍照、图片、文件保留原来的顺序和行为，选中官方 MiniMax 模型时额外显示“MiniMax 创作”。其下图片、视频、配音和转写共用一个底部弹层。用户可选择图片比例，打开图片下载链接；视频提交后保存会话内任务编号、主动查询进度；配音生成 mp3 后调用安卓分享与保存；转写结果可直接进入当前会话输入草稿。
3. **工作模式**：不在“+”面板重复整个智能体工具配置；复杂视频参考输入、视频资产编排、批量导出继续由工作会话的作业流承担，未来接入原有运行中心及作业成果目录才属于完整持久化任务能力。
4. **视觉规范**：沿用 `DsBottomSheet`、`DsQuickActionTile`、`DsButton`、`DsTextField`、`AppSettingsSection`，中文字串放入 `res/values/strings.xml`，继续复用深浅色、点击区域和系统权限方案。无多余一级首页入口。

## 借鉴到原有实现的方法

- **按能力展示**：从所选真实模型配置和官方服务商规则派生按钮可见性，防止任意代理或非 MiniMax 账户误触发付费接口。
- **账户身份单源**：生成图片、视频、TTS、ASR 与套餐额度都复用 `LocalModelCredentialResolver`，UI 不能读取密钥；跨账号执行不从全局账户读默认凭据。
- **结构化服务商错误**：先判 HTTP，再判 `base_resp.status_code`；返回缺失字段及时失败，不把空响应当生成成功。
- **新旧额度格式**：`*_usage_count` 在 API 不同版本可能表示“剩余”或“已用”，须用权威剩余百分比交叉校验；两种解释都不匹配时只展示百分比，不能凭猜测显示伪剩余次数。
- **视频任务的事实状态**：区分排队、进行中、失败和成功；文件下载地址只有在查询 `Success` 并拿到有效 `file_id` 时才展示。
- **媒体文件安全**：统一由 Android SAF 选择录音；TTS 输出缓存 URI 经 `FileProvider` 按单次分享授权；不使用 `file://` 和任意绝对路径。
- **计费事实单源**：Token Plan、按量余额和本机消耗来自不同接口／账本，不相互抵扣推断。图片、音频、视频可能采用独立计费，入口明确提示。

## 交付证据与尚需实测

当前 PR 已有以上原生代码、设置入口及按键连线。项目 CI 编译／静态检查通过之前，不宣称 APK 功能完成；未持有用户的真实 MiniMax 密钥，不能把 mock HTTP 测试当成云服务端到端成功。

**需要真实服务商验证：** 国区／国际区账号兼容、Token Plan/余额不同密钥形态、实际图片与视频计费、不同中文音色、50 MB 边界录音、回调网络中断、长视频任务完成链接的有效期。

**本 PR 仍需升级的体验：** 视频任务只保存到会话界面状态，跨应用冷启动的永久任务列表、后台通知、成果库与成本账单尚未接入既有运行中心；图片返回 URL 交由系统查看/保存，还没有写入 777 自有持久成果库；生成媒体费用不能从文本套餐剩余额度推算。这些限制应在真实任务 Owner 下统一接入，避免另建一套低质量运行中心。

**Figma 状态：** 已创建设计文件 `777 · MiniMax 多模态能力与额度查询`（https://www.figma.com/design/Qm3VsLp5CyRdWb8XKtiher），但后续编写时 Figma Starter 计划的 MCP 调用次数已耗尽；当前文件并非已完成的可编辑设计稿。当前 Compose 实现直接使用仓库现有组件和本节布局方案，不能将空 Figma 文件当已交付设计。
