# 777｜「澄序」整体 UI 重新设计方案

> **设计状态**：第二轮从零重构的视觉方案、8 类页面 HTML 交互原型及多条件截图已完成；Android Compose 生产界面尚未改动。  
> **对应仓库**：`sy220284/777`，原生审计基线 `main@b8a55d139cdc819162a1f5749e0c67032821b496`，2026-11-17。  
> **设计依据**：「独立艺术指导与整体审美 V5.6」D01–D12，总纲、跨维度搭配与完整体验规范。  
> **旧方案处理**：原 PR #945 的 ORBIT / EDITORIAL / COMMAND 三方向全部退出本次实施候选；新方案不沿用旧暖米色/杏色 UI、巨幅蓝色目标卡或荧光深色监控台。

## 1. 为什么整套重做

此前三方向虽然风格有区别，但把 777 当成了设计概念展示项目：工作区过于像仪表盘，部分主视觉面积过大，聊天区内容不足以撑起真正的产品感，不同场景之间的页面语法仍较相似。UI 的艺术表现压过了用户实际要完成的任务。

此次重做以三个真正影响体验的矛盾为核心：

1. **聊天与工作具备不同的认知节奏**：聊天长时阅读、感受语气；工作反复判断目标、执行状态、交付内容。共用导航与组件语义，按任务使用不同的信息结构。
2. **777 功能非常多，但手机屏幕非常有限**：让用户的当前动作拥有第一优先级，次级能力保持清楚、容易找到。把真实对象、状态和下一步放在同一阅读路径里。
3. **展示效果与长期使用必须同时成立**：首页应漂亮、有特色，但长时间查看文字、打开键盘、放大字号、执行复杂任务时，视觉设计仍然稳定而易读。

### 一句话设计命题

**让复杂能力自然归位，让内容与行动成为画面主角。**

### 设计个性

`清晰`（准确但不冰冷） × `轻盈`（细节丰富、减少不必要的视觉板块） × `有生命力`（在人物和操作状态中体现情绪） × `可信`（状态、授权与结果可核对）。

取舍：取消大面积“营销主视觉卡”、模板式仪表盘和纯装饰英文小标；保留极少量真正有识别意义的符号、几何细节和动态反馈。

## 2. 视觉方向：「澄序」

### 2.1 形式语言

- **空间**：界面背景平静，主内容占据屏幕主要区域。信息使用可扫描的共同对齐线，少量留白用于建立组间关系，而非制造大片空白。
- **字形**：中文采用清晰现代的系统友好字体，标题字重与正文形成可识别差异。长文正文优先排版舒适；不拿英文标签或超大标题弥补内容不足。
- **色彩**：使用洁净的冷白、深墨文字、清晰的深青绿作为交互强调。色彩面积依据语义分配：行动和当前状态少量使用高显著色，文本区域保持中性。
- **形态**：统一线性图标的笔画重量、视觉中心和圆端表现；功能区主要以分组、薄边界和对齐形成空间，而非卡片墙。
- **材质**：低频展示可以增加轻量背景和半透明层次。日常文本和工具页使用可靠的实体背景；复杂图片/壁纸进入后保持足够对比度。
- **识别性**：`7·7` 的小型几何标记和精细的深青绿操作标记形成产品记忆点。界面的核心特色还来自 Chat/Work 两种截然不同的阅读节奏。

### 2.2 初版视觉变量（需在 Compose 落地后根据真实设备再校正）

| 语义角色 | 亮色 | 深色 | 作用 |
|---|---|---|---|
| 页面底 | `#FFFFFF` | `#172429` | 长时间阅读的主要底色 |
| 辅助底 | `#F2F6F6` | `#16282D` | 搜索、轻分组、低权重背景 |
| 强文字 | `#17272B` | `#EFF7F5` | 正文与页面主信息 |
| 弱文字 | `#65767B` | `#9BB2B3` | 状态次文、辅助说明 |
| 分界线 | `#E2E9E9` | `#293D40` | 低存在感的边界 |
| 当前行动 | `#167B71` | `#61D8BF` | 主要按钮、选中、焦点与进度 |
| 低强调面 | `#ECFAF6` | `#1B3835` | 可选操作与状态辅助 |
| 执行中关注 | `#EF7659` | `#F29B82` | 正在运行节点，避免与成功态混淆 |
| 通过/完成 | `#0B8C72` | `#68D7B2` | 结果成功；同时配文字与图标 |
| 错误/风险 | `#D44B57` | `#FF8491` | 需说明影响和恢复入口 |

采用“基础色→语义色→组件状态”的三层映射，不把角色色直接散落到页面源码。颜色值为提案参考，不强制用户外观偏好，也不移除现有自定义壁纸、主题与强调色功能。

### 2.3 字体、比例和间距

- 中文正文：默认 14–16sp；长文 15–17sp，并由用户阅读偏好控制。小型时间或元信息可短暂采用较小字号，必须在放大文字与真实亮度条件下验证。
- 标题：明确区分全局导航标题、内容主标题、模块标题和说明；同页避免两次完整重复。
- 间距：常用内容间隙 6/10/14/20/28dp，结合光学视感调整。组内更紧、组间更松。
- 操作热区：使用 Android 合适的触控尺寸，图标物理尺寸与交互区域独立处理。
- 形状：小控制区通常 10–12dp，柔和容器 16–20dp；通过组件角色和内容密度选择，不对所有元素设统一圆角。
- **200% 文字放大**：优先缩减展示性标题、移除重复信息、改组布局；正文与动作文字必须仍可读、可滚动、可操作。演示原型中 140% 及以上会让展示性标题退场，把高度交给真实内容。

## 3. 页面架构与任务路径

### 3.1 主要导航重组（设计提案）

移动端底部 `对话 / 工作 / 能力 / 我的` 四个可预期的入口；保留侧栏中的最近会话、人物、文件、任务及其原有页面深链。工具、文件、任务各自归属对应的 Feature 模块。不同入口最终到达现有 Route，不改变底层业务数据所有权。

- 对话：以真实聊天信息、人物和输入框为中心。人物可从当前对话标题进入。
- 工作：当前目标、步骤、正在执行的状态、阶段成果、继续指令构成一个直接闭环。任务、工作文件从工作上下文进入。
- 能力：发现、搜索、查看与管理工具/技能/插件/连接，区分“查看详情”“启用/安装”“已连接”。
- 我的：个性化、账户、模型、存储、设备权限、通知及运行诊断。

导航深度目标以“三层即可找到常用目标”为体验指导，结合真实内容；系统 Back、侧栏返回来源和模态层撤销应始终按当前上下文工作，不额外强加阻断用户操作的限制。

### 3.2 页面逐项设计

**Chat — 对话**：打开已有会话后显示真实对话内容，顶部可切换当前人物，用户与助手信息通过位置和浅层背景区分。长文段落直接在主画布上阅读；引用、生成产物和扩展内容使用按需显现的次级层。输入区有当前模型/思考档位及附件入口。首次使用则显示简洁、可直接点击的启动选项，避免“大面积空白+一个 CTA”。

**Work — 工作**：当前项目卡只表达项目身份、简要目标与进度。执行步骤以原生列表与连续节点构成时间关系；执行中、等待确认、成功、失败明确分别标注。阶段成果以文件实体呈现、可打开和回溯。输入区保留工作指令、附件、模型等关键上下文，特殊状态支持暂停和恢复。取消巨大的目标面积和单纯装饰性仪表格。

**能力中心**：一个明确的搜索区 + “发现能力/已添加”模式，不叠加多排重复筛选。条目直接显示能力名、用途、类型及真实启用状态；进入详情后再进行外部连接与授权。能力状态保留失败、重试与取消。

**定时任务**：一次扫描能看到任务名、执行频率、下一次时间、状态；任务详情中提供编辑、运行历史、暂停/恢复。避免详情标题与顶栏重复。新建任务先填目标，再决定时间与通知，信息结构与真实调度器一致。

**工作区文件**：搜索、路径、最近文件和直接操作共处清楚的工具页；打开/导入/预览/多选时显示相应对象和进度。支持长文件名、权限拒绝、重复命名和真实文件大小。

**人物图集**：当前人物的视觉表达适度增强；列表中仍要保留名字、性格和可直接继续对话的操作。图片美感服务人物性格，避免人物页与普通设置列表完全同形。

**设置**：按功能语义分组的列表 + 搜索，条目可一眼看到用途和当前值。查找之后能正确定位设置，并能够从目标页按返回来源恢复。

**权限**：以所需功能作为授权入口。明确区分“未授权”“已前往系统设置”“系统授权中/已授权但服务未连接”“已连接”。实际状态只来自 Android 系统和能力服务。用户可以略过暂不需要的授权，之后从相关功能按需继续。

## 4. 操作状态设计

| 状态 | 视觉表达 | 用户可以采取的动作 |
|---|---|---|
| 空内容 | 真实功能目的、一个可用主入口、必要的快捷建议 | 开始对话/任务/导入 |
| 读取/执行中 | 与当前对象紧邻的文字状态和轻量指示 | 查看详情、可取消时取消 |
| 等待审批 | 醒目的待决策说明，列出执行后果和作用范围 | 同意、拒绝、返回 |
| 已完成 | 结果与真实产物链接，明确下一步 | 查看成果、继续工作 |
| 已失败 | 错误原因、已保留内容和恢复办法；只在需要时使用错误强调色 | 重试、查看详情、撤销 |
| 弱网/模型不可用 | 不遮蔽现有内容，保留未发送草稿 | 更换模型、重新连接、重试 |
| 空权限 | 说明用途与原因，按需进入系统授权 | 授权、稍后再说 |
| 大字号/小屏 | 展示性标题让位，内容纵向重排 | 所有必要任务仍可操作 |

## 6. Android Compose 实现映射

**基础层（系统优化而非局部修修补补）**

- `app/src/main/java/com/shenyan/designsystem/foundation/ShenyanFoundation.kt`：增加新版语义令牌/主题映射。保留已有用户外观偏好值，定义视觉角色而不是基于历史风格继承旧默认色。
- `app/src/main/java/com/shenyan/designsystem/components/ShenyanBasics.kt`、`ShenyanMaterial.kt`、`ShenyanMaterialColor.kt`：整合按钮、列表、工具栏、弹层、点击热区和壁纸背景对比度；半透明仅在确有空间语义时采用。
- `app/src/main/java/com/labteto/dshmobile/ui/theme/Type.kt`、`Theme.kt`、`Spacing.kt`：明确文字角色、动态放大布局和主题；保留现有字体子集生成链路，不能破坏离线构建。

**主容器与功能页**

- `app/src/main/java/com/labteto/dshmobile/ui/screens/local/LocalHarnessScreen.kt`：整合新的导航框架与现有 Feature Route/Back 语义；避免为新视觉另建业务状态。
- `LocalConversationSurface.kt`、`LocalConversationComposer.kt`、`LocalConversationHeaders.kt`：聊天真实内容、工作执行状态和输入区独立排版；保留已有发送/停止、审批、附件、焦点与键盘处理。
- `app/src/main/java/com/labteto/dshmobile/ui/screens/tools/ToolsScreen.kt`：能力发现与已安装的页面层次；独立详情与安装授权状态。
- `app/src/main/java/com/labteto/dshmobile/ui/screens/tasks/TasksScreen.kt`、`TaskEditorComponents.kt`：列表、真实调度状态与任务编辑；时间表达以设备本地设置处理。
- `app/src/main/java/com/labteto/dshmobile/ui/screens/local/LocalWorkspaceFilesDialog.kt`、`PersonaGalleryOverviewV3.kt`：各自适配文件工作流与人物表达。
- `app/src/main/java/com/labteto/dshmobile/ui/screens/settings/SettingsScreen.kt`、`PermissionSetupFlow.kt`：设置和系统授权的状态分离与直达导航。

**保留的能力与不改变的边界**

- 不新增远端服务，不修改模型调用、任务调度、权限授权或 GitHub 等插件的后端协议。
- 不人为限制附件大小、不阻断下载或导入、不覆盖现有用户偏好。
- 后台服务、运行时和插件的内部细节按任务显露，无需在前台展示整个内部架构。
- 升级与代码 PR 的发布应单独通过 Android 真实环境验收；设计稿中的示例状态不会被当作真实授权状态。

## 7. 验收与证据

**已完成（离线原型）**

- 8 类功能页面有真实内容示例；存在抽屉、底部导航、搜索、输入、发送、人物切换、能力状态及权限演示交互。

- 自动化实测抽屉导航、发送文本、搜索、权限视觉状态切换；100%、140%、200% 字号下的展示标题按空间重排。
- 截图已复核：聊天、工作、能力、任务、文件、人物、设置、权限八页及深色 Work、320dp/200% Work。

**尚需进入生产验收（仅在实际修改 Kotlin 后适用）**

1. 编译与运行实际 Android Compose，核对 320/360/390dp、分屏与折叠、浅/深、系统字体 100/130/200%。
2. 实际系统导航栏、状态栏、输入法与 Android Back，不出现按钮遮挡、焦点丢失或输入区跳动。
