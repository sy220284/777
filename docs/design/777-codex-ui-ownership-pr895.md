# 777 · Codex 对齐能力与原生界面归属审计（PR #895）

审查日期：2026-11-13。基于分支 `feat/codex-capability-alignment-20261112`，追踪 `docs/audits/codex-777-capability-alignment-20261112.md` 29 项范围。本表将“有源码”“能操作”“验证通过”分开判定。**现有实现不自动视为验收完成。**

## 交互归属规则

- **界面操作（A）**：用户需要选择对象、管理内容、发起任务或查看成果；在既有 Chat／Work／工具／文件／设置中提供直接入口。
- **情境呈现（B）**：运行过程本身在后台，但权限、进度、失败、撤销、费用或结果必须在原任务区域呈现；按需打开抽屉或底部弹层。
- **后台能力（C）**：引擎自动承担；通过已有工作状态、审计记录或错误提示反馈，不创建一张独立的技术配置页面。

应用导航保持不超过三级：顶层入口 → 功能列表 → 详情／任务弹层。复用 `SyTopBar`、`SyResponsiveSheet`、`SyButton`、`SySwitchControl`、`StateDot`，优先操作卡片、搜索与状态反馈；避免安装后先填写大量参数。

## 已实现能力的 UI 复查结论

**已有正确归属（继续原位完善）**：会话分区、消息队列、运行中调整、模糊搜索、技能目录/安装/分享、文件变化自动刷新。

**后台归属正确，无需新页面**：生命周期 Hooks、Code Mode 引擎、文件变化订阅、工具审计。保留透明回执、审批和失败状态即可，避免在工具首页增加“开发者开关矩阵”。

**尚缺关键用户入口**：远端 Git 差异（目前可由工具调用，但用户无法在工作区直观比较）；技能升级/恢复（本轮已增加界面入口）；其余尚未实施的项目、语音、导入等按上表交互方案进入下一轮开发。

## 技能详情：最优交互（已按 Compose 现有组件接入）

页面路径：`工具 → 技能 → 已安装技能详情`。

1. 技能名称、功能说明、自动调用开关；顶部仅显示本地已知信息。
2. **已固定的 GitHub 版本**：显示前 12 位提交号；点击“检查更新”才联网，避免每次打开工具页发起大量请求。
3. 有新版本时展示明确目标版本，点击“升级”先给出确认弹层。后台完成下载、包校验和整体替换，保留上一版本；失败显示原因。
4. 有上次版本时展示“恢复上一版本”，确认后可恢复；恢复操作也保留当前版本，用户可再次切换。
5. 分享来源、分享完整 ZIP、编辑和删除继续使用原有详情操作，完整包分享采用 Android FileProvider URI。

验收需覆盖：有/无更新、源记录篡改、远端分支变化、非法 ZIP、技能 ID 冲突、符号链接、保留版本、恢复前后文件一致、Android 16/17 弹层及实际操作。**本轮源码提交后的 CI 与设备验收应单独记录结果。**

## MCP 追问体验（本轮新增）

用户仅在当前 Work 工具确实提出追问时看到弹层，不需要预先填写 MCP 专用表单或前往插件配置页面。顶部明确显示服务名称及提问原因；普通字段采用原生输入和单选，提交与拒绝、取消分开；安全敏感操作只允许 URL 模式，显示目标域名，点击确认才调起设备浏览器。每一次答复保留原工具调用及服务身份，进程/会话取消时终止等待。完整设备验收与旧协议兼容性仍须依据最新测试结果核定。

## 诊断报告体验（本轮新增）

入口保留「设置 → 诊断」与「环境信息 → 导出」两处，统一先生成同一份脱敏报告，弹出支持滚动全文检查的预览层。只有点击「保存此报告」才打开 Android 系统文件保存界面，点击「选择应用分享」才打开分享面板，由用户指定接收方；点取消直接退出。提交到官方反馈服务须等有可信服务端协议、用户授权和真实回执后再接入。
