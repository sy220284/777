# 落地前必须解决的工程根因

> 来源：并行会话对生产代码的审计（G1–G7）。这些是事实与根因，与视觉方向无关，V9 路线图继续沿用。


并行会话的代码审计给出了 7 条与视觉无关、但会决定落地质量的根因，V9 路线图一并吸收：

| # | 根因 | V9 的处理 |
|---|---|---|
| G1 | 状态色靠中文文案判定（`statusText.startsWith("执行异常")`） | P0 先把状态改为 phase 枚举驱动，颜色与文案解耦；`semantic.status.*` 令牌只描述语义，不描述文案 |
| G2 | 10 个设计系统组件零调用、45 处裸 `material3.Surface` | P1 起建立"组件归位表"，棘轮基线从 45 逐面递减，每 PR 报数 |
| G3 | 三套左右边缘基准（22 / 14 / 26dp） | P0 令牌层定 `pageGutter` / `sectionGutter` 两个常量，全页只引用它们 |
| G4 | 输入区 320dp 下 48dp 失守（5×48 + 间距 > 可用宽度） | P2 输入区在 320dp 下次要动作收为横向滚动 chip，不压缩命中区 |
| G5 | 中文正文回落系统字体（`contentFont` 只挂 Outfit） | P0 字阶层明确 `body` 必须绑定 Noto Sans SC 子集，字体产物进构建 |
| G6 | 遗留 `DsColors` 仍有 4 个消费文件 18 处 | P0 列迁移表，明确先后顺序，不允许新增消费点 |
| G7 | 两条 M3 scheme 构造路径（换色卡与默认路径字段不一致） | 依赖并行会话 PR #938 的单一构造器，不重复实现 |
