# 神言 V6.4 视觉与材质设计规范（待实施设计目标）

> **性质：设计修订方案，不等同于已上线实现。** 基准代码为 `sy220284/777@02544aa4`（2026-11-13）。生产事实依照 [V6.3 当前实现](V6-CURRENT-IMPLEMENTATION.zh-CN.md)，本文件定义下一轮视觉升级及可验证的验收条件。
> **范围：** Android 原生手机界面、三主题、L1–L5 材质、文字、交互、控件、动效、壁纸、可访问性和性能；不改变七条业务主路由、不恢复已退役入口。本轮只修改设计文档。

## 1. 体验目标与判断标准

视觉方向为“暖墨·精密玻璃”：温润材质、干净阅读、精密反馈、明确空间。整体质感应来自内容排版、光影连续性、边缘细节与动效节奏，而非玻璃/阴影数量。

- **内容先于容器。** 聊天和工作时间线使用连续的阅读流；只有真正的可交互对象、信息分组及悬浮操作需要显式底板。无意义的连续嵌套卡片应合并为留白、分割线或标题。
- **空间层次只保留必要的差异。** 背景、栏、卡片、浮层遵循同源画布。暗主题以暖灰为基，哑光黑使用实心材质。没有业务状态时不添加呼吸灯、扫光或持续飘动。
- **专业能力有辨识度。** Chat、Work、Tools、Tasks、Workspace、Persona、Settings 可采用不同的布局节奏、图标及状态动效，但共享基础字体、几何、色彩和反馈规则。
- **动态质感必须可信。** 运行、等待、审批、进度、完成与失败都由真实状态驱动；动画只是状态的表现，不模拟进度百分比或工具调用。
- **性能与无障碍同级。** 透明度、模糊、阴影都应有成本预算；低端机和系统减少透明度时以清晰的层次降级，不以牺牲文字可读性换通透。

## 3. 三主题的光、色和表面

采用 [V6.3 当前 ARGB 色板](V6-CURRENT-IMPLEMENTATION.zh-CN.md#2-三主题--材质--透明度) 作为现有色彩基线：暖纸的纸张基底及琥珀强调，烟熏主题的深棕灰层次，哑光黑的低反射层次。系统跟随无独立第四色板。

- 暖纸：使用温暖的浅中性色；白色高光仅作为局部光照，禁止整个屏幕叠白导致纸面发灰或分区割裂。
- 烟熏玻璃：避免纯黑叠透明导致脏灰；将低亮度背景、暖色边缘光和易读的文字作为主要空间线索。
- 哑光黑：L1–L5 完全实心，不执行背景模糊；用明度、低强度描边和排版表达层级，不硬加玻璃高光。
- 成功、警告、错误使用语义色和图标/文字共同表达。功能分类可通过形状和文案区分，谨慎使用大面积彩色图标容器。

### 3.1 色彩与文字对比

- 正常文字（包括辅助说明、按钮文字、输入提示以及重要状态文字）按实际合成背景目标 **≥4.5:1**；大号粗体文字与具有明确操作含义的非文字图形目标 **≥3:1**。装饰性纹理和不可操作的图形不按文字计算。
- 强调色是容器颜色，不是固定字色。`onPrimary` 应由强调色、按下态、暗亮模式以及最终不透明填充共同求解；不能固定所有浅色主题色卡使用白色前景。
- 壁纸和玻璃下，以控件实际所在区域的最终叠色像素计算对比度，覆盖最大亮暗值与纹理极端点。优先保护当前真实存在的阅读文字；仅用作装饰的强调色不应被错误纳入所有容器的最小对比计算。
- 文字缩放与粗细尊重 Android 系统及用户偏好。重点检查中英文混排的字体回退、标点、行高、粗细和数字列对齐；不为追求“设计稿像素”牺牲可阅读性。

## 4. L1–L5 材质语法：先说职责，再说效果

以下“当前参数”来自 [ShenyanMaterial.kt](../../../app/src/main/java/com/shenyan/designsystem/components/ShenyanMaterial.kt)。设计目标调整须在组件层统一实现，不允许页面级反复硬编码。

| 层级 | 使用场景 | 当前模糊 / 默认阴影 | 推荐的表现与原则 |
|---|---|---|---|
| L1 分区 | 内容分组、轻控件区域 | 0dp / 0dp | 优先留白、细分隔；不额外模拟一层玻璃 |
| L2 栏 | 输入承载、工具栏、导航承载 | 24dp / 2dp | 局部柔化真实对齐背景；不在栏内重复铺整块实心背板 |
| L3 卡片 | 需要聚合信息的内容卡 | 0dp / 1dp | 以内边距、层次和单次边缘定义对象；默认保持文字清晰 |
| L4 浮层 | 菜单、弹窗、Sheet、文件预览 | 32dp / 16dp | 共享语义层级，但按用途区分分隔感、边缘、阴影和视觉密度 |
| L5 实心层 | 高对比、降透明、复杂嵌套 | 0dp / 0dp | 使用本主题实体表面，优先安全阅读，哑光主题始终保持实心 |

**优化建议：** 现有 L4 一刀切使用 16dp 阴影偏重。下一轮引入语义外观策略（不是第六层）：小菜单可采用约 8dp 的轻抬升，底部 Sheet 约 12dp，重要确认 Dialog 约 16dp；具体值在视觉验收后确定。不同大小和密度的浮层应有不同的边缘对比，不把它们画成相同的悬空卡。

**边缘设计：** L2 与 L4 可保留一条柔和轮廓光；顶部高光不得和描边、内容底板层层加亮。只有较大的悬浮容器需要可感知的顶部光线；小型按钮、Chip 和列表行默认使用更轻的边缘。高光不得改变布局测量。

**嵌套与分层：** 普通内容控制在一层主要容器内；出现两层嵌套时先检查是否可以用内容间距替代。三个及以上连续透明表面、系统减少透明度、对比无法达标时采用 L5 或语义实心表面，不重新引入“全屏白板”。

## 5. 壁纸、区域取色和透明度策略

保留当前 `AppBackgroundHost → SySceneBackgroundSurface → SyMaterialSurface` 的同源场景结构。动态壁纸只由根背景层维护视窗裁切与颜色取样；弹层背景使用相同窗口坐标，避免背景突然跳跃或把相邻卡片文字透出来。

### 5.1 推荐的求解顺序（设计目标，尚未实现）

1. 从实际控件区域获得背景样本及极值，确定真实正文/按钮图标所用的语义前景色；合成顺序与 Compose 绘制顺序一致。
2. 由用户透明度偏好产生理想 Alpha，再按该控件真实承载的文字与图标求安全下限；最后在**真实最终合成结果**上复测。无法达到目标时转为 L5 并选择可读字色。
3. 颜色优化以保留壁纸色相为前提，首选柔和局部遮罩、对比安全的同色系填充；避免所有彩色壁纸被算法一律改成灰白。
4. 检测到安全下限限制透明度时，外观设置应解释“为保证文字清晰，当前背景会增加遮罩”，让滑块呈现真实生效范围；用户可调整但不产生隐性失效。
5. 背景切换、窗口裁切改变、IME 出现及侧栏/菜单移动时刷新正确位置的采样。`SyTextField`、Chip 等普通平台控件需和材料容器使用一致的真实区域坐标，不长久固定中段取色。

### 5.2 模糊的真实感和性能

- 只有 L2/L4 在需要且具备正确场景背板时执行背景模糊；模糊仅作用于背景层，前景字、图标、图片主体保持锐利。`Modifier.blur` 模糊自身层，不能误称“模糊已绘制的兄弟元素”。
- 同一场景只渲染一次底图并以对齐坐标复用；不为每张列表卡建立独立实时模糊图层。避免用多层透明颜色替代真实景深。
- 在低性能或省电场景，可降低模糊采样成本、缩小参与模糊的表面范围，最终必要时退到语义不透明背景，同时维持正确的阴影和文字层级。
- 自定义壁纸的对比度校验需使用纯白、纯黑、高饱和、细碎文字纹理、暗亮交错和用户照片等测试图，不以单张渐变壁纸作为全部通过依据。

## 6. 几何、字体、控件与组件视觉

- 几何维持 `SyMetric`：48dp 最小点击区域，9/13/18/24dp 语义圆角，间距 2/6/10/14/22/34/54dp。图标可用 20–24dp，但其交互目标仍满足 48dp。组件优先按内容功能适配，而不是把全部元素统一做成一个大圆角。
- 正文字体重在长时间阅读。聊天/工作文字保持稳定行距、段落节奏、代码块和引用区别；中文与拉丁字体的组合必须在系统放大字体下检查，避免混排基线飘移。
- 主操作按钮只在确有明确主要动作时出现填充。次级动作、行操作和菜单项优先轻表达。表单先显示必要输入，复杂参数折叠到相应详情。
- 图标遵循 24×24 网格与 1.75 线宽的当前资产规范，大小型控件采用光学居中修正。图标颜色按实际底色取对比安全的前景；发送/停止图标不能无条件固定为白色。
- 卡片边缘、选中高亮与按压态不应一次叠加描边、底板、阴影和光晕四种强调。按业务重要程度选择最有效的一两种反馈。

## 8. 动效：强化微交互，不制造虚假忙碌

现有 `SyMotion` 是唯一基础时长与缓动来源，具体参数见 [动态体验规范](V6-MOTION-EXPERIENCE.zh-CN.md)。保留轻快导航，同时增加与内容有关系的微动效：输入焦点/展开、发送到消息、人物卡选中、插件安装、工具调用、任务状态与成果出现。

- 按压 70ms、选中 150ms、同级 140ms、前进 260ms、返回 220ms、Dialog 220ms、Sheet 280ms、侧栏 180ms，均为当前实现基线；设计增强应复用相同 `SyMotion` 入口。
- 短交互追求快；持续工作使用局部、低频、有语义的反馈。只对当前运行的步骤使用运动，已完成/失败立即收束；明确百分比必须来自真实业务。
- 系统减少动效时，全部非必要时长归零，状态语义与可操作性保留。连续操作和快速返回不得因动画丢失状态或重置滚动。

## 10. 推荐的实施顺序

1. 修复按钮前景对比、动态材质最终合成对比和位置取色一致性（用户可读性优先）。
2. 将 L4 的菜单/Sheet/Dialog 语义外观参数统一到设计系统；消除重复边缘与亮色盖板。
3. 优化消息、Work 执行、工具/技能、设置的排版与高级感，保留现有功能和导航层次。
4. 增加与真实状态同步的微动效，并用 Android 设备记录核实手感与性能。
5. 令设计规范与原生令牌同步生成或比对，Figma/Canva 视觉资产可用时再做在线组件映射。
