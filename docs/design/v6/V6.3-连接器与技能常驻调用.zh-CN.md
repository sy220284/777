# V6.3 · 连接器与技能常驻调用（PR #731）

状态：**Android 原生实现已提交，设备视觉与交互闭环待 CI/实机验收**。遵循 UI3.0 架构边界与 V6 同源材质；保留主线原有加号栏、模型切换、工作/聊天模式和权限系统。

## 设计目标

参照用户提供的聊天输入框截图：输入区可直接看见当前使用的连接器、技能及其品牌标识。用户手动选中即固定；下一轮、继续任务、切换会话或重启 APP 后仍默认提供，直至手动取消。不要求模型再次搜索该来源。新选择可与原选择并存，不自动替换。

固定表达的是**用户任务偏好**，不是跳过授权、保证连接成功或强制把每个消息发送给每项工具。模型使用固定来源完成相关任务；无关任务不滥发外部请求，执行仍由现有工具注册、授权和运行权限裁决。

## 页面与交互规范

| 状态 | 页面呈现 | 可执行操作 |
|---|---|---|
| 未选择 | 输入框上部有紧凑「＋ 选择连接器或技能」 | 点击展开统一 V6.3 场景弹层 |
| 已固定 | 横向可滚动的标签行：16dp 来源图标、单行名称、关闭符号 | 点击标签取消固定；多个条目可并存 |
| 选择弹层 | 搜索框，分组「已连接的服务 / 已安装技能」 | 勾选或取消；搜索本地实时能力目录 |
| 已断线/技能已卸载 | 保留已选条目，标记不可用 | 可以手动移除，不能假装工具已连接 |
| 凭证错误/审批拒绝 | 复用原有审批、错误与诊断组件 | 反馈具体原因，不自行重试高风险写入 |
| 工作持续执行 | 本轮已固定工具在运行时注册表里优先匹配并送入模型 | 权限、连接状态与可选工具 token 预算照常生效 |

### 视觉与尺寸

- 复用已有 `SyConversationComposer`、`SyPopupMenu` 与 V6.3 文字、间距、材质 Token；不用新的全屏底板和不透明悬浮层。
- 工具品牌图标：GitHub 与 Figma 使用本地矢量资源；普通 MCP 连接器用统一中性网络标识；技能使用统一图书图标。图标是信息来源，不以颜色作为唯一状态依据。
- 标签尺寸由真实内容决定，采用 15dp 图标、紧凑边框圆角、横向滚动；输入框键盘区和发送按钮尺寸不变。
- 触摸控件保持适当的可点击面积；弹层可随 IME/小屏幕滚动。320/360/393/412dp 和字体放大须真机验证。
- 展示当前真实的已注册服务和已启用技能，不创建假插件商店条目。

## 状态、数据和权限

- `LocalPinnedInvocationStore` 保存用户选择到设备 `noBackupFilesDir` 的原子替换本地文件，禁止云端同步，恢复时忽略无效条目。
- `LocalToolsUiFacade` 是 UI 读写入口；界面不直接依赖内部存储与工具注册。选择变化用 StateFlow 立即反馈。
- `LocalToolExecutionCoordinator` 每次 Work 任务重新审查实时工具注册和 GitHub 配置；固定的 GitHub/MCP 工具 schema 优先装入，但任何执行仍按 Harness 原有审批。
- `LocalWorkSkillActivation` 在每轮按需将固定技能内容注入运行上下文，不永久写入历史，禁用或卸载时安全退化。
- Chat 人设对话模式目前不接入 Work 工具执行；此页面的固定调用功能首先服务 Work 模式。后续将两种会话的功能职责统一规划，避免混淆角色模式与工具能力。
- GitHub 技能安装从公网 GitHub Contents API 读取单个技能目录，使用已存在的本地 ZIP/metadata 导入器验证。官方 `openai/skills` 的 curated 目录有浏览入口。其他第三方仓库须显式选择 URL。

## 验收矩阵（全部不可用“代码已写”代替测试）

1. 固定 GitHub → 连续两轮短消息「继续」→ 工具仍在当轮 schema 中；移除后不继续激活；断开凭证不能伪装已连接。
2. 固定 MCP「figma」→ 只优先真正注册且 family=MCP 的 `mcp_figma_*`；不同 MCP 服务或伪造同名前缀不得混入。
3. 固定多项技能 → 每轮加载有效规则；用户本轮明确命令优先；单项卸载或关闭可调用后安全退化。
4. 退到工具页、重启、切换工作会话 → 固定来源展示一致；无效条目允许人工移除。
5. GitHub 在线目录与链接安装 → 真实 SKILL.md，遇到目录过大、路径非法、网络断线、重复安装则给出可恢复错误；现有资源留存。
6. Android 16/17、三主题、键盘遮挡、系统返回、字体放大、屏幕阅读器及减少动效完整回归。
7. 运行 CI 静态门禁、Architecture 3.0、JVM/Android 单元测试和 APK 构建；任何失败必须记录来源、是否历史基线、是否本 PR 引入。
