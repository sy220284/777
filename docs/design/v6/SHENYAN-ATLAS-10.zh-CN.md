# 神言原生组件库 · 十类交互图集落地

> 本文对应 2026-11-19 的十张 UI 图集设计评审。
> 权威代码仍为 `com.shenyan.designsystem`（视觉与组件）和 `ui/shenyan`（应用弹层与聊天适配）。
> 本变更在原生 Compose 中实现，业务状态和副作用由调用 Feature 继续持有。

## 落地设计规则

1. **风格多样，语言一致。** 配色由主题/壁纸/调用方选取，统一计算文字对比与选中状态，不固定成一种暖金风；保持蓝紫霓虹之外的丰富色彩搭配。
2. **易用性。** 操作目标至少 48dp、输入状态与加载状态可辨认；响应式弹层支持需要时的部分展开；半屏面板的滚动与底部操作区分开。
3. **动效。** 使用唯一的 `SyMotion` 时长和缓动。按压先响应，之后展开/切换；跟手滑动由手势位移驱动，超过阈值或速度满足条件时归位。尊重 `LocalSyReduceMotion`。
4. **安全。** 滑动只展开操作，不触发实际删除/发送等副作用；危险操作继续使用明确确认回调；撤销在调用方确实可以恢复时才展示。
5. **内容。** 空状态、等待、失败、完成和禁用属于不同真实业务状态。骨架屏用于实际等待数据，不模仿已经完成的数据。
6. **跨端与可访问性。** 保持中文、系统字号缩放、TalkBack 状态描述、键盘/导航栏安全区和横屏大屏适配。输入发送与媒体按钮的状态继续由调用方拥有。

## 关键验收

- 典雅白与磨砂黑双主题在不同系统字体缩放下可读；九套强调色的文字对比至少 4.5:1。
- 单个组件的默认、焦点、按下、禁用、加载、成功和错误状态具备真实视觉与文字反馈。
- 表单日期、多选、数字步进值由外部状态控制，关闭弹层时不会悄悄提交。
- 底部弹窗的返回、下滑、屏幕边缘、IME 与内容滚动路径正常。
- 长按菜单保留触点定位，手势揭示不自动执行危险动作。
- 快速连续点击、动画中断、系统减少动态效果时，状态与事件没有重复或丢失。
- 用户无需引入云端服务；UI 全部在本机 Compose 渲染。

## 参考图集到原生设计规则的落地（本轮强制验收）

- **01 基础组件：** 主次按钮有明确层级，按压 85 ms 先响应，交互色联动 `SyHostColors`/权威 `SyColors`，在真实背景上保持文字对比。
- **02/03 弹层：** 以 28dp 标准圆角、承载卡片的语义材质、导航栏与输入法安全区、滚动正文与固定操作区处理遮挡。
- **04 手势：** `SySwipeActionRow` 跟手拖动、释放后归位；长按菜单保留触点定位；破坏性操作需主动点击二次确认。
- **05 消息反馈：** Toast、Snackbar、持续 Banner 分离；成功、等待、失败分别使用不同的语义色与状态文字。
- **06 加载：** 只有实际进行的任务使用连续动画；骨架用于真实数据等待；反馈遵守系统减少动效偏好。
- **07 引导：** 手势翻页、页码、首次使用引导遵守原生屏幕尺寸和大字号自动排版。
- **08 表单：** 大字号时标签与值自动改为上下排布；图标、圆角、分组和底部操作区采用同一神言规范。
- **09 媒体：** 播放器由业务状态驱动；迷你播放器、进度及全屏入口不各自实现第二套视觉。
- **10 聊天：** 输入组件遵守键盘、安全区和多行高度；按钮状态、文件行、操作菜单采用同一 48dp 触控标准。

### 改进落地的共同视觉语言

十张设计图展示的风格各不相同，组件系统从中提取可验证的共同规律：
1. 字体具备标题、正文、辅助信息的清晰分级；阅读内容保持舒适行距，导航文字不因字号放大而截断。
2. 圆角有明确层级：10dp 小组件、14dp 操作组件、20dp 卡片、28dp 弹层。手势或上下文优先遵守触点和系统惯例。
3. 留白不再套用相同数值：分组卡 16dp 水平/14dp 垂直留白；快捷操作同时呈现独立图标容器、标题和触控目标。
4. 动效来自状态变化及真实手势，按压先响应；路径切换平稳可中断；需要减少动效时缩短至零时长。
5. 配色动态协调：在实际主题、壁纸和用户所选强调色上计算语义色，避免蓝紫霓虹作为默认视觉；成功、失败和危险使用稳定的可读状态色。

### 迁移范围与守卫

- 旧页面仍在用的 `DsType`、`DsShapes`、`DsAnimations`、`DsMetrics` 和 `Ds*` 视觉主题投影已在源代码中迁移至 `SyType`、`SyShapes`、`SyAnimations`、`SyHostMetrics` 和 `SyHost*`。
- 应用仍保留既有的 `DshTheme` 入口和历史外观选择键（用户配置数据不需要迁移）。
- `.github/scripts/check-ui-design-system-boundaries.py` 阻止旧视觉类在生产 UI 中再次引入。
- 组件底层由 `com.shenyan.designsystem` 实现，宿主 `ui/theme` 只负责宿主字体和外观设置的投影；不建立第二套绘制系统。



## 真实业务接入与原生验收

- 十类图集采用原生 Compose 组件；聊天、工作、任务、工具、人物、文件、设置和首次引导共享视觉语法。业务页面需要保留原来的保存、删除确认、权限与恢复逻辑。
- `ShenyanAtlasVisualCaptureTest` 在 Android 模拟器计划生成 **58 张原生 PNG**：双主题十类图集 20 张、九套强调色 18 张、四种已打开的弹层 8 张、三段吸附 6 张，以及玻璃静止、按住拖动和松手 6 张。弹层截图使用设备屏幕像素，包含独立窗口和遮罩。执行入口为 `tools/ui/run-native-ui-audit.py`，截图、录像和测试日志随 `777-ui-videos-and-results-*` 工件保存。
- 正式入口接住图集交互：单聊角色纠正使用真实撤销提示，工作任务首次读取使用骨架，首次执行时间与周期复用神言日期和数字控件，用量趋势接入可取消的自定义日期范围。
- `ShenyanAtlasInteractionTest` 与真实页面回归共同检查操作。设备测试通过后还需逐张对照十张原始设计图，记录布局、颜色、玻璃材质、遮罩、动效和无障碍偏差；截图存在仅证明采集成功。
- 生产组件门禁 `.github/scripts/check-ui-design-system-boundaries.py` 对真实业务入口进行检查，避免仅在调试图集中实现而业务页面未迁移。

### 交互缺口复核

- 待执行消息默认打开半屏，在手机上可选择或拖动至 50%、75%、100%。按住消息把手拖放，同一会话快照仍有效时松手才提交，拖到边缘可滚动。上移和下移仍可使用。
- 文件成果从真实操作名单生成径向菜单。小屏、放大字体、危险操作及不适合圆周布局的项目数使用列表。两种布局调用相同的打开、保存与分享入口。
- 工作任务的下拉动作调用真实列表刷新，通过一个在途请求防止重复刷新。
- 视频使用神言播放条。双击两侧跳转十秒，左侧滑动调节当前窗口亮度，右侧滑动调节播放器音量。退出播放或切到后台时还原窗口亮度。
- 双主题基础图每轮先恢复默认流体杏。光学设备测试同时检查静态边缘与按住时的像素变化，截图在松手前采集一帧。额外设备用例验证队列松手提交、径向动作、下拉刷新及本地测试视频跳转。
