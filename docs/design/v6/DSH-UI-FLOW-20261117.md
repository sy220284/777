# DSH 参考体验优化：当前实现与验证

本轮以 DSH Go v1.1.0 与 777 main@be89abc 的代码评估为依据。沿用 Compose、架构 3.0、本机 Chat / Work 分工和暖色视觉，业务配置、授权、安装和执行继续由原 Feature 持有。

## 用户可见变化

| 场景 | 当前实现 |
|---|---|
| 输入 | 展开时直接显示模型名称和实际思考档位；规划与团队派发有文字状态；基于窗口、输入法及字体行高分配可见行数，长文本仍可滚动 |
| 输入动效 | 收起按键与展开工具行共享同一个 Transition，保留同一编辑器与草稿，继续响应系统减少动画设置 |
| 设置 | 全局搜索支持标题、常用说法、中英文别名、全角输入；结果打开原设置页，定位并高亮实际条目；返回保留查询及列表位置 |
| 设置维护 | 页面标题和搜索消费同一份页面索引；条目锚点附在实际设置控件，跟随真实布局，不保存易失真的滚动坐标 |
| 文件 | 选择模式和文件路径作为一份界面状态恢复，作用域包含会话、项目根目录、分类、目录和入口请求；刷新保留选择，完整目录快照才核对移除项，未返回的分页不被当成文件消失 |
| 能力目录 | “发现／已添加”与用途分类独立组合；搜索常驻；已登记连接、本机能力、已安装技能仍走真实目录与原操作链 |
| 弹层 | 普通弹层默认明确遮罩；没有自定义标题操作时提供关闭按钮，继续遵守原 dismissEnabled 和业务取消回调 |
| 长详情 | 正文大标题与顶栏标题随滚动连续交接，固定底部动作保留；同一阶段只暴露一份标题语义 |
| 工作会话 | 点击顶部当前任务摘要直达已有工作记录与交付入口；公开任务状态、成果与原有菜单使用同一回调 |

## 材质取舍

普通底部弹层现行默认采用 SySceneBackgroundSurface，对齐并绘制根场景。它与 DSH 的背板模糊实现有不同成本来源；本轮保持现有采样方式。动态模糊切换需要同设备测量后再决定，不为一个尚未量化的瓶颈增加另一套材质状态。已落实输入区转场协作与弹层层级，保留既有场景动效。

## 验证路径

- JVM：输入高度分配、设置匹配与索引覆盖、目录筛选组合、选择刷新和跨项目恢复，以及应用全量测试。
- Android：SettingsSearchUiTest 验证别名直达和实际锚点；LocalConversationComposerRegressionTest 验证当前模型文字与草稿；LocalWorkspaceShareSelectionUiTest 验证页面重建后的多选；既有目录与弹层交互继续回归。
- tools/ui/run-native-ui-audit.py 已包含设置搜索与设置导航恢复，后续同类改动沿用该路径。
- 同 SHA 的 CI、设备结果和构建结果在 PR 记录，不把测试代码存在当成设备测试通过。

本地运行器测试曾因宿主缺少 Landlock ABI 失败（AgentWorkspaceEnvironmentTest 七项、AgentTlsBackendTest 一项）；对应生产实现未改动，测试与隔离机制保留，由仓库 Linux CI 环境复验。
