| L1 分区 | `#4DEDE6DA` | `#1A302B27` | `#FF181819` |

| L5 实心 / 深层保底 | `#FFF1E8DC` | `#FF35312D` | `#FF29292B` |
| 文本主色 | `#3A342D` | `#F5F0E8` | `#F5F0E8` |

通用强调色在 `SyColors`：primary `#E8A87C`、按下 `#D9926B`、mint `#7FBFA8`、lilac `#B9A0D4`、warning `#E0A458`、danger `#D9705F`。成功/警告/错误必须结合文字和真实状态表达，不能只靠色点。哑光黑材质全实心，不应为模拟玻璃而模糊壁纸。

**材质层级**：L1 分区、L2 顶栏/承载、L3 常规卡片/选中项、L4 弹层、L5 不透明保底。原生模糊半径依次 `18 / 28 / 20 / 32 / 0 dp`；高度层次 `1 / 3 / 7 / 16 / 1 dp`。连续嵌套达到三层、系统减少透明度时使用 L5 兜底。真正背景模糊只允许模糊对齐后的 **背景层**，不得模糊文本或靠透明叠加模拟“真毛玻璃”。

**壁纸与透明度**：`AppBackgroundHost` 产生实际裁切区域采样（上/中/下），`syResolveMaterialFill` 保留壁纸色相并做最小文字对比保护；L1–L4 不强制变纯白。高级透明度 `0..1` 经 `SyMaterialPolicy.adjustment(t) = (0.5 - t) × 0.46` 再参与自适应对比；不能把调节旋钮变成无效的“假设置”，也不能用保护算法令所有透明度无差别。无壁纸、复杂高对比壁纸、壁纸切换瞬间及主题切换都要可用。加号面板的同源背景采用 `SySceneBackgroundSurface`，**不是纯白底、也不是直接看穿到聊天文本**。

## 3. 几何 / 字体 / 动效 / 触觉

`SyMetric`：触控最小 `48dp`，间距 `2/6/10/14/22/34/54dp`（xs/sm/md/lg/section/page/hero），圆角 `9/13/18/24dp`（sm/control/card/sheet），导航 push/peer 位移 `20/6dp`。不把 48dp 触控尺寸误当图标绘制尺寸；紧凑图标可以更小，点击区域不能跟着缩。排版遵守系统 sp/用户阅读字号与粗细、原生 `ui/theme/Type.kt`，而非 HTML 浏览器后备字体。严禁为追旧截图修改字体或取消无障碍扩字。

`SyMotion` 使用 `cubic-bezier(.22, 1, .36, 1)`，按压缩放 `0.985`，标准时长（ms）：按压 80、选择 200、Dialog 280、Sheet 380、层级前进 360、返回 320、同级切换 160、侧栏 280、工具展开 200、输入区展开 190/淡入 120、折叠箭头 150、颜色反馈 140、普通淡入 150、Toast 200、实时脉冲 900。用户高级节奏仅作用于允许的非必要动效，倍率 `0.7..1.3`；系统减少动画优先置零。真实工作进度、等待/已停止语义不得因为减少动画而消失。重复振动受统一间隔 `45ms` 约束，长按延迟 `420ms`/重复 `90ms`。

动画用于 **位置层级变化、按压确认与真实正在运行**，不能为了好看制造“伪运行”，也不能为已移除的工作分栏保留完成共享转场。Material3 框架内部无法控制的时序不能伪称已经统一。

## 4. 现行页面入口和布局（以七条 Route 为准）

`LocalFeatureCatalog` 现行明确只有七条顶层页面，`LocalFeatureDrawerEntry` 是更多的**动作入口**，不能混为一谈。页面和二级页必须保留真实进入和返回路径。详见 `current-ui.json` 的可机读路径清单。

| Route | Owner | 页面组织及入口 |
|---|---|---|
| `HOME` | SHELL | 聊天/工作共用整屏消息时间线；顶部侧栏菜单；底部适应输入、附件、发送/停止、模型与能力；工作待提问/审批走真实弹窗 |
| `PERSONA_GALLERY` | CHAT | 侧栏进入人物图集，人物详情/编辑及继续聊天；不恢复旧数字徽标 |
| `DIARY` | CHAT | 人物日记/知识及相关查看功能；不恢复已移除的重复人物分区 |
| `WORKSPACE` | WORK | 工作区真实文件浏览/预览/打开；成果本身也从当前会话消息卡可达 |
| `TASKS` | AUTOMATION | 自动化任务列表、编辑、执行状态；不等于已移除的独立运行中心 |
| `TOOLS` | TOOLS | 能力中心/技能/插件与工具连接；技能、插件的状态/操作要如实展示 |
| `SETTINGS` | SETTINGS | 设置首页分组和内部 SettingsDestination 导航；外观、模型、用量、记忆、权限、通知、诊断等不另增一级路由 |

设置二级页由 `SettingsScreen.kt#SettingsDestination` 定义：`ROOT, SESSION, APPEARANCE, CHAT, ACCOUNT, MODELS, MODEL_PERFORMANCE, MODEL_USAGE, MINIMAX_QUOTA, PRICING, USAGE, USAGE_LOG, USAGE_DETAIL, MEMORY, MEMORY_SETTINGS, MEMORY_MANAGEMENT, PERMISSIONS, NOTIFICATIONS, ADVANCED, SESSION_STORAGE, DIAGNOSTICS`。**检查更新是设置页的直接操作，不另画“检查更新页面”**；模型数量显示在列表标题内，而不是 ChatGPT 连接测试上方新增小胶囊。消耗入口仍可由侧栏/设置到达，但聊天输入区不再提供“管理使用额度”快捷入口或套餐状态提示。

**侧栏与导航**：主界面顶部菜单开启单列侧栏，抽屉背景与主场景全高连续，内容让开系统安全区。侧栏搜索支持会话/人物/任务/工作文件的当前可检索内容；当前聊天/工作切换不能无故重置已打开的真实子页面。会话行不提供左滑删除，统一由长按菜单执行重命名、多选、置顶和删除（删除仍需确认）；返回需依实际页面栈恢复，不能把系统边缘返回手势占用为“打开侧栏”。通用顶栏不绘制整块额外不透明背板，避免顶/底割裂。

**聊天消息**：聊天模式助手卡阅读宽度 `fillMaxWidth(.91f)`，水平/垂直内边距 `16/13dp`；复制、朗读、重新生成、历史分支等操作在正文卡**下方**，仍保证最小触控目标。原文单个换行在聊天对白中保留；工作模式和通用 Markdown 不改写换行约定。群聊/单聊共用正文渲染链；用户气泡及回合用量为弱视觉层级。

**工作消息**：没有「目标/计划/决策点/执行中/产出」五段导航、没有独立产出大卡，也没有重复“新会话”页标题。计划审阅、审批、提问、进度、成果和错误是真实业务事件，投影到时间线或对应 Dialog；运行完成不自动代表验收通过。附件/文件成果仍可打开。运行中有草稿才显示“立即调整”选择，并在草稿操作区提交调整或加入队列；关闭调整选项恢复默认排队。输入框右端始终只有一个主操作，空闲显示发送、运行中显示停止，能力操作可横向滚动而不能挤成逐字竖排；顶部不再显示独立“交互文档”快捷行，文档功能仍保留在已有业务入口。

**加号与媒体**：一级加号弹层单行四项 `拍照 / 图片 / 文件 / 多模态创作`，不再用四个大图标卡嵌套白色板；团队/共享为轻量图标文字行。不同媒体实际请求/生成/归档/失败应保留原 Feature 的身份、真实状态和可用动作，不能让设计稿预设“都已生成”。

**技能 / 插件（#711 已合并）**：主线通过不参与布局测量的 `Canvas(matchParentSize())` 修复顶部装饰性高光撑宽紧凑 `Row` 的问题。现行布局为 40dp 图标区，标题不受按钮挤压、描述独占一行区域且最多两行、卡片底部独立操作行，详情看完整说明；搜索覆盖说明，加载/安装时保留已有项，受影响动作禁用，预置技能无安装回调不显示假“添加”。Android 16/17 的自动化测试与合并门禁已通过；放大字体、实际触摸与 TalkBack 的设备视觉验收仍须单独记录。

**外观**：主题支持暖纸/烟熏玻璃/哑光黑以及系统跟随；外观页不再展示大面积演示和冗余讲解，只有短助手行+一条用户气泡阅读预览。页面尾部“高级外观”**默认折叠**，同页展开四组：色彩与背景、材质与透明度、动效与动画、组件视觉；包含环境光、智能对比、透明度、节奏、强调强度与恢复默认。壁纸模式环境光滑块不可用，不能假装对壁纸生效。设置即时保存/投影由真实设置存储承担。

## 6. 维护/防回退与验收

1. **变更流程**：先按合并后的真实 Compose 审核本次 PR 改动；如 PR 尚未合并，设计记录要显式标“待合并”，不得提前宣称已上线。修改全局 token 必须同步测试主题/壁纸/深浅色/高对比与依赖控件；修改页面入口必须同步当前七 Route + 设置二级页矩阵、原型、状态台账、退役清单。
2. **设计包**：`mobile/app.html` 只保留当前七个顶层 Route 的手机单列导航投影及必要二级/弹层交互，不再把原 38 张历史场景当作现行页面全集；SVG 图标按 Compose 真实调用映射，不能为了凑旧素材数量恢复废弃功能。可编辑 Figma 若可用也要从**这套**规范同步，不能反向覆盖。
3. **界面状态**：加载、空白、失败、离线、等待许可/审批、运行中、部分完成、已完成、取消、结果不明、历史恢复分别核对。视觉动作必须对应实际 Feature 回执；按钮禁用要基于真实不可用状态，不能任意屏蔽有意义的操作。
4. **体验矩阵**：320/360/393/412dp × 暖纸/烟熏/哑光 × 默认/放大字体、长中文标题、IME/返回、壁纸/无壁纸、默认/减少动画、触控/屏幕阅读、短卡/长卡、真实等待/失败。布局“不会挤成竖排”与状态恢复同样重要。
5. **真实完成标准**：代码合并及 CI 通过、Android 16/17 的关键状态截图或录屏对照、交互和恢复场景逐项验证、Figma 实际节点/变量与组件核对。缺一不标记“全量视觉/交互完成”；编译、浏览器截图和 HTML 点通都不是 Android 实机证明。
