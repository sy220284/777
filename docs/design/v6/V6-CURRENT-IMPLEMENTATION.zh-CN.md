## 2. 双主题 / 材质 / 透明度

源：`ShenyanFoundation.kt` 的 `ShenyanPalettes` 与 `SyColors`。以下为 **ARGB 原始基准**；显示时还有按位置取色、场景叠色、透明度及文字对比保护，因此不是静态 HTML 截图的最终像素。

| 项 | 典雅白 LIGHT | 哑光黑 MATTE |
| --- | --- | --- |
| 根画布 | `#FCFCFB` | `#0F0F10` |
| 顶栏后备色 | `#FFFFFF` | `#18181A` |
| L1 分区 | `#4DFFFFFF` | `#FF181819` |
| L2 栏 / 轻表面 | `#C2FFFFFF` | `#FF1E1E20` |
| L3 卡片 | `#E6FFFFFF` | `#FF232324` |
| L4 弹层 | `#F7FFFFFF` | `#FF29292B` |
| L5 实心 / 深层保底 | `#FFFFFFFF` | `#FF29292B` |
| 文本主色 | `#000000` | `#F5F0E8` |
| 文本次色 | `#353535` | `#D9D0C5` |
| 描边 | `#38777777` | `#1AFFFFFF` |

典雅白浅色主题以近白画布、纯白卡片和黑色文字为基础，材质层级依靠细描边、留白与轻阴影。用户自选强调色只影响操作反馈，不改变白色阅读画布；自定义壁纸保留动态取色和对比度保护。

通用强调色在 `SyColors`：primary `#E8A87C`、按下 `#D9926B`、mint `#7FBFA8`、lilac `#B9A0D4`、warning `#E0A458`、danger `#D9705F`。成功/警告/错误必须结合文字和真实状态表达，不能只靠色点。哑光黑材质全实心，不应为模拟玻璃而模糊壁纸。

**材质层级（当前代码事实）**：L1 分区、L2 顶栏、L3 常规卡片、L4 弹层、L5 不透明保底。典雅白的 L2/L4 光学玻璃以背景像素位移表现轮廓，去掉外投影与独立描边，只保留内侧定向微光。L3 默认使用低成本材质，保留更细的结构分隔。磨砂黑、已启用减少透明度、缺少同源画面或连续三层以上的嵌套使用实心语义材质。

**壁纸与透明度（当前实现）**：`AppBackgroundHost` 产生实际裁切区域采样（上/中/下），`syResolveMaterialFill` 保留壁纸色相并做最小文字对比保护；L1–L4 不强制变纯白。高级透明度 `0..1` 经 `SyMaterialPolicy.adjustment(t) = (0.5 - t) × 0.46` 再参与自适应对比；不能把调节旋钮变成无效的“假设置”，也不能用保护算法令所有透明度无差别。无壁纸、复杂高对比壁纸、壁纸切换瞬间及主题切换都要可用。加号面板的同源背景采用 `SySceneBackgroundSurface`，**不是纯白底、也不是直接看穿到聊天文本**。

## 3. 几何 / 字体 / 动效 / 触觉

> **设计目标与当前实现区分：** 优化后应按控件最终合成背景测试对比度，并使选中的强调色前景、取色区域与浮层语义外观一致；这些仍属于 [V6.4 待实施规范](V6.4-VISUAL-MATERIAL-GUIDELINES.zh-CN.md)，本节时间与材质数字只描述主线。

`SyMetric`：触控最小 `48dp`，间距 `2/6/10/14/22/34/54dp`（xs/sm/md/lg/section/page/hero），圆角 `9/13/18/24dp`（sm/control/card/sheet），导航 push/peer 位移 `20/6dp`。不把 48dp 触控尺寸误当图标绘制尺寸；紧凑图标可以更小，点击区域不能跟着缩。排版遵守系统 sp/用户阅读字号与粗细、原生 `ui/theme/Type.kt`，而非 HTML 浏览器后备字体。严禁为追旧截图修改字体或取消无障碍扩字。

`SyMotion` 使用 `cubic-bezier(.22, 1, .36, 1)`，按压缩放 `0.985`。**2026-11-13 实现时长（ms）**：按压 70、选择 150、Dialog 220、Sheet 280、层级前进 260、返回 220、同级 140、侧栏 180、工具展开 170、输入区展开 155/淡入 95、折叠箭头 130、颜色反馈 120、普通淡入 130、Toast 170、实时脉冲 900。高级节奏倍率 `0.7..1.3`，减少动效时非必要时长归零；长按延迟 `420ms`/重复 `90ms`。下一轮以丰富真实状态微动效为优化方向，参见 [动态体验规范](V6-MOTION-EXPERIENCE.zh-CN.md)。

动画用于 **位置层级变化、按压确认与真实正在运行**，不能为了好看制造“伪运行”，也不能为已移除的工作分栏保留完成共享转场。Material3 框架内部无法控制的时序不能伪称已经统一。

## 4. 现行页面入口和布局（以七条 Route 为准）

`LocalFeatureCatalog` 现行明确只有七条顶层页面，`LocalFeatureDrawerEntry` 是更多的**动作入口**，不能混为一谈。页面和二级页必须保留真实进入和返回路径。详见 `current-ui.json` 的可机读路径清单。

| Route | Owner | 页面组织及入口 |
|---|---|---|
| `HOME` | SHELL | 聊天/工作共用整屏消息时间线；顶部侧栏菜单；底部适应输入、附件、发送/停止、模型与能力；工作待提问/审批走真实弹窗 |
| `PERSONA_GALLERY` | CHAT | 侧栏进入人物图集，人物详情/编辑及继续聊天；不恢复旧数字徽标 |
| `DIARY` | CHAT | 人物日记/知识及相关查看功能；不恢复已移除的重复人物分区 |
| `WORKSPACE` | WORK | 工作区真实文件浏览/预览/打开；成果本身也从当前会话消息卡可达 |
| `TASKS` | AUTOMATION | 自动化任务列表、编辑、执行状态；不等于已移除的独立运行中心 |
| `TOOLS` | TOOLS | 能力中心/技能/插件与工具连接；技能、插件的状态/操作要如实展示 |
| `SETTINGS` | SETTINGS | 设置首页分组和内部 SettingsDestination 导航；外观、模型、用量、记忆、权限、通知、诊断等不另增一级路由 |

设置二级页由 `SettingsScreen.kt#SettingsDestination` 定义：`ROOT, SESSION, APPEARANCE, CHAT, ACCOUNT, MODELS, MODEL_PERFORMANCE, MODEL_USAGE, MINIMAX_QUOTA, PRICING, USAGE, USAGE_LOG, USAGE_DETAIL, MEMORY, MEMORY_SETTINGS, MEMORY_MANAGEMENT, PERMISSIONS, NOTIFICATIONS, ADVANCED, SESSION_STORAGE, DIAGNOSTICS`。**检查更新是设置页的直接操作，不另画“检查更新页面”**；模型数量显示在列表标题内，而不是 ChatGPT 连接测试上方新增小胶囊。“模型价格与消耗”入口位于设置首页“模型与账户”分组，模型管理页不再重复展示；消耗详情仍可由侧栏/设置到达，但聊天输入区不再提供“管理使用额度”快捷入口或套餐状态提示。

**侧栏与导航**：主界面顶部菜单开启单列侧栏，抽屉背景与主场景全高连续，内容让开系统安全区。侧栏搜索支持会话/人物/任务/工作文件的当前可检索内容；当前聊天/工作切换不能无故重置已打开的真实子页面。会话行不提供左滑删除，统一由长按菜单执行重命名、多选、置顶和删除（删除仍需确认）；返回需依实际页面栈恢复，不能把系统边缘返回手势占用为“打开侧栏”。通用顶栏不绘制整块额外不透明背板，避免顶/底割裂。

**聊天消息（#896 已合并）**：助手正文采用 `fillMaxWidth()` 全宽开放式阅读流，旧 91% 背景卡及多层底板已退役；用户消息保留独立气泡。最新助手回复显示主要操作，较早回复提供明确的 48dp 展开入口，可按需显示操作栏；长按、文本选取和内嵌链接互不抢占。原文单个换行在聊天对白中保留；工作模式和通用 Markdown 不改写换行约定。群聊/单聊共用正文渲染链；用户气泡及回合用量为弱视觉层级。

**工作消息**：没有「目标/计划/决策点/执行中/产出」五段导航、没有独立产出大卡，也没有重复“新会话”页标题。计划审阅、审批、提问、进度、成果和错误是真实业务事件，投影到时间线或对应 Dialog；运行完成不自动代表验收通过。附件/文件成果仍可打开。运行中有草稿才显示“立即调整”选择，并在草稿操作区提交调整或加入队列；关闭调整选项恢复默认排队。输入框右端始终只有一个主操作，空闲显示发送、运行中显示停止，能力操作可横向滚动而不能挤成逐字竖排；顶部不再显示独立“交互文档”快捷行，文档列表改从顶部更多菜单进入，消息内文档及编辑能力保持不变。

**加号与媒体**：一级加号弹层单行四项 `拍照 / 图片 / 文件 / 多模态创作`，不再用四个大图标卡嵌套白色板；团队/共享为轻量图标文字行。不同媒体实际请求/生成/归档/失败应保留原 Feature 的身份、真实状态和可用动作，不能让设计稿预设“都已生成”。

**技能 / 插件（#711 已合并）**：主线通过不参与布局测量的 `Canvas(matchParentSize())` 修复顶部装饰性高光撑宽紧凑 `Row` 的问题。现行布局为 40dp 图标区，标题不受按钮挤压、描述独占一行区域且最多两行、卡片底部独立操作行，详情看完整说明；搜索覆盖说明，加载/安装时保留已有项，受影响动作禁用，预置技能无安装回调不显示假“添加”。

**外观**：主题提供典雅白、磨砂黑与跟随系统，系统夜间自动使用磨砂黑；外观页不再展示大面积演示和冗余讲解，只有短助手行+一条用户气泡阅读预览。页面尾部“高级外观”**默认折叠**，同页展开四组：色彩与背景、材质与透明度、动效与动画、组件视觉；包含环境光、智能对比、透明度、节奏、强调强度与恢复默认。壁纸模式环境光滑块不可用，不能假装对壁纸生效。设置即时保存/投影由真实设置存储承担。

### 当前成熟交互的统一契约

- **阅读锚点**：`LocalTranscriptVisibleWindow` 按消息 ID 保留前台可见历史，`LocalTranscriptPagingUi` 在用户向上翻页时加载旧消息；只有用户跟随尾部时才随流式增长和 IME 变化调整位置。
- **字号决定布局**：`SyCategoryRow` 实测标题/数值文字宽度，空间不足或 `fontScale >= 1.2` 时纵排；设置菜单行也在大字号时纵排。
- **真实工作状态**：`LocalWorkTimelineStepRow` 已提供等待执行、执行中、已返回、失败、已中断、结果待确认六态，保留自然语言操作、按需查看回执和屏幕阅读状态。
- **共享导航与输入**：`LocalFeatureAnimatedHost` 持有 Predictive Back 和以路径限定的文件共享过渡；Composer 按焦点、附件、Chat/Work 和运行状态决定大小与主按钮。

完整调用关系、复用边界和已有测试源见 [V6.3 已实现交互与组件契约](V6-IMPLEMENTED-INTERACTION-CONTRACT.zh-CN.md)。

## 6. 维护/防回退与验收

## 2026-11-19 · 液态玻璃统一设计

依据仓库内 `finesse-ui` 的产品材质、组件交互状态与 `interaction-motion` 的触点即时反馈规范，从现有 Compose 组件实现，不新增网页式壳层。

典雅白采用 `#FCFCFB` 画布和黑色文字，L2 工具栏、L3 互动卡、L4 浮层使用细腻的渐变折光边界、顶部微弱透光、实际按压位置的局部柔光；普通阅读正文始终在反射层上方。磨砂黑与典雅白均使用玻璃层级；L1 做轻量分区，L2–L4 根据背景明暗自适应折射，L5 保留实心阅读底板。减少透明度、实心底板、三层嵌套与缺少同源背景时采用语义实心样式。触点反馈由同一光学层绘制，手势继续交由页面处理。减少动效时保持静态折射。L3 大量滚动卡片不执行 GPU 背景折射。L2 / L4 使用原生着色器内的轻微邻域采样。

此效果使用原生 Compose 的同坐标背景模糊与表面反射模拟，保留无壁纸/复杂壁纸自适应与文本对比度保护；未加入昂贵的实时物理折射。材质资格、透明度、嵌套、黑色主题由 `SyGlassOpticsTest` 进行 JVM 回归测试。

## 2026-11-19 · AGSL 逐像素液态光学（本轮增量）

参照视频中的透明玻璃覆盖文字、边缘放大和手势触发的曲面响应，采用 `SyLiquidRefraction.kt` 中的原生 AGSL RuntimeShader + RenderEffect。输入为玻璃下方**实际绘制的图层**：默认同坐标壁纸或环境光源，调用者通过 `SyMaterialSurface(backdrop = ...)` 可传入持续更新的自定义画面（包含动态文字、图像）。GPU 原位采样，无 Bitmap 转换或逐帧 CPU 拷贝；组件自身的正文始终在折射层上方。

每个像素按圆角矩形的有符号距离求边缘法线，再计算折射位移、轻微 RGB 波长分离、菲涅耳式边缘反光和触点处的局部厚度变化。四角半径和触点由原生布局尺寸及手势位置驱动；松手后由统一动效时长回归静态。触点监听不消费事件，底部弹层及列表的原生手势仍各自生效。默认启用 L2/L4 的 GPU 折射；滚动中的 L3 卡片保留细边，显式传入实时背景时才启用逐像素效果。降低透明度和 L5 保持实心材质；磨砂黑同样具备低反射的深色玻璃。

**画面来源边界**：Compose 不能通过 `Modifier.blur` 或 `RenderEffect` 自动读取此前绘制的兄弟控件。默认折射壁纸；需要折射聊天文字时，要将那部分文字作为与前景玻璃分离的实时 `backdrop` 传入同源图层。此实现提供了原生像素折射路径，整屏任意兄弟层捕获仍需在屏幕容器内明确拆分前后层。Android 最低 API 36，可直接使用 AGSL（系统 API 33 起支持）。

验证：`SyGlassOpticsTest` 覆盖选层规则和 shader 关键输入；需要以 Android JVM/仪器化测试和可见 GPU 帧率确认编译、效果和性能后才判定视频同级效果完成。

## 2026-11-19 · 真正的实时兄弟图层折射

`SyLiveGlassScene.kt` 以 `underlay`（实际背景页面）和 `glass`（浮动控件）两个明确图层构成：前者由 `rememberGraphicsLayer` / `drawWithContent` 在 GPU 显示列表中逐帧记录一次，后者从同一 GPU 图层读取已渲染的文字或图像，在 AGSL 中做逐像素折射。两层互不包含，避免玻璃反射被再次采样出现无限重影。尺寸、窗口坐标同步更新，手动滑动镜片会改变覆盖的字符。默认材质优先选择此共享画面，其次才是同坐标壁纸；跨窗口对话框继续取壁纸，避免跨窗口 RenderNode 误用。

调试组件实验室的「04 手势」使用这条共享 GPU 渲染链路，支持滑动镜片和刷新底层文字；`SyLiquidRefractionAndroidTest` 增加了真实同级图层像素变化验证，并纳入设备端 UI 自动巡检。

## 2026-11-19 · 聊天与工作实际消息层接入和高级光学统一

- 原生共用的 `LocalConversationSurface` 已将实际 `LazyColumn` 消息列表作为 `SyLiveGlassScene.underlay`，将滚动定位浮钮放入 `glass`。滚动中的文本实时参与折射；提示隐藏时关闭全列表 GPU 图层记录。两种模式走同一入口，避免各自复制一次绘制逻辑。
- `ConversationScrollShortcut` 改用 L4 统一圆形液态材质，外层继续保留 48dp 的点击区域。减少动效时，进出场动画直接到最终状态。磨砂黑采用深色自适应玻璃，文字保持原有对比度。
- AGSL 将局部折射、轻柔化、轻微色散、边缘菲涅耳反射与触点方向性压缩放入同一渲染器。边缘雾化最多为少量邻域采样，主阅读区保持高对比；大于 43 万像素的覆盖面停用额外邻域采样以控制 GPU 成本，仍保留单次像素位移。
- `SyLiquidRefractionAndroidTest` 对新增的 blurPx/clarity/drag uniform 做实际 RuntimeShader 建立验证；完整 UI 回归仍以 Android 36/37 的 CI、真实截图和帧率审计为准。

视觉技能审查重点：真实文本在玻璃边缘应有明确但不过火的局部位移，文字本身锐利；点击反馈快速而可中断；典雅白清澈、磨砂黑低反射；实际滚动时不能因阴影或泛白丧失内容层次。

## 2026-11-19 · 设备失败回溯：修正光学输入

发现历史 Android 36 设备日志中的 `SyLiquidRefractionAndroidTest.lensSamplesLiveBackdropOnItsOwnGpuLayer` 失败：原记录层与应用 RenderEffect 的图层分离，背景变化后捕获的像素保持白色。已将光学处理改为单一 `graphicsLayer(renderEffect)` 直接包裹实时 `backdrop()`：RenderEffect 的 `source` 即该 GraphicsLayer 的真实子内容，每次源重绘都由 Compose 自身处理，无独立帧缓存和双录制层失配。同时新增黑白条纹边缘位移设备测试，分别排除“只出现白底”和“没有真的折射”的假阳性。验收需以本次修复后的设备回归结果确认。

组件视觉巡检继续保存典雅白、磨砂黑各 10 组原生截屏及强调色对照；新增两套主题各自镜片静止、手势右拖后的 4 帧截图（`*-optics-at-rest.png`、`*-optics-after-drag.png`），并验证镜片真实移动。光学设备测试进一步以独立的不透明覆盖层隔离真实背景，只有 AGSL 对共享 GPU 图层采样成功才会观察到背景变化；同时保留条纹边缘变形验证。静态截图能检查造型、边缘、对比；连续拖动录像及帧率性能仍需通过设备巡检交付，图像外观不得由编译通过直接推断。

## 2026-11-19 · 高刷手势稳定与辅助功能

按交互动效技能「速度窗口」要求，原先每次 pointermove 的单帧位移已经替换为 48ms 窗口测量，再规范成 16ms 帧的等效形变强度。60/120Hz 设备使用同一套弯折反馈，极短间隔不会导致光学边缘乱跳；新增 JVM 单测覆盖 1ms 额外事件及长按静止回归。折射纹理层加入空的 `clearAndSetSemantics`，避免复制进 GPU 的背景文字被辅助技术再次朗读。实际页面的原始消息语义和浮钮操作仍保留。

## 透明玻璃与 Android 复验

- 镜片只渲染实时折射、薄色膜和内侧高光。透明底层按 alpha 合成；聊天列表的空白部分使用同坐标场景，避免透明像素被涂成深色。非液态阅读卡片保留轻分隔。
- 聊天手势与工作暂停阅读共用同一光学入口。快捷键隐藏或开启减少透明度时结束实时背景记录；磨砂黑与典雅白共享实时光学处理。
- Android 像素测试检查背景实时更新、边缘位移、均匀底色上的暗边与外投影。巡检另存聊天/工作滚动录像与实际窗口帧时间，截图和设备结果按当前提交核对。

## 2026-11-19 · 全背景自适应玻璃闭环改造

**范围**：两套主题均采用一套 L1–L5 材质层级。L2 工具栏、L3 可交互卡片/图标、L4 浮层与抽屉走统一动态取色与 AGSL 光学渲染；L5 保留实心阅读层，保证文字、代码、长内容和关键状态可读。普通交互控件的大小、点击回调和辅助功能语义由现有组件保持，不通过另一个皮肤系统接管。

**任何颜色的处理方式**：默认纯色、亮白、炭黑、彩色壁纸、深浅模式均生成同源场景；材质从上中下区域采样背景和局部明暗，再调节透明度及文字底色。底层实际背景像素在镜片内发生轻微位移，内侧边缘按亮度改变高光方向（白背景偏微暗折射、黑背景偏柔亮反光），形成清晰但细窄的光学边界。大面积面板关闭昂贵的额外模糊采样，保留薄镜片的边缘折射。强调色只影响操作状态，不改变画布色。

**页面接入**：聊天/工作顶部栏、底部会话输入、侧边抽屉、聊天工作切换器、次要按钮、分段选择器和非实色图标按钮共用 `SyMaterialSurface`。应用背景宿主在两种主题下均维护一份场景；深色不再被当作“减少透明度”的开关。独立跨窗口弹层继续按同坐标背景绘制；真正需要折射实时文字时，通过 `SyLiveGlassScene` 显式区分底层与浮动控件，防止复绘递归。

**验收**：JVM 检查两套主题与白/黑/珊瑚红/橄榄绿/明黄/深蓝背景上玻璃激活及实心阅读边界；Android 仪器测试确认亮暗与彩色动态背景真正改变折射输出，并阻止整面灰边或外阴影。最终结果以最新提交 SHA 的全量 CI、设备测试、截图和录像为准。
