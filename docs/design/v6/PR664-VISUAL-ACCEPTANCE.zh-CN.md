# PR #664 · V6 全屏视觉验收与缺口跟踪

> 此文件记录 **PR 分支** 的实现进度，与 `docs/design/v6/verification.json`（#654 阶段历史记录）分开。它是验收台账，**不是 38 屏截图通过的声明**。设计原始依据为 `docs/design/shenyan-38-screen-parity-audit.md` 与离线 V6 素材规范。

## 已提交的产品/实现改造

1. 统一聊天顶部/底部/侧栏、按钮及设置入口图标的 V6 三主题语义配色，用户指定强调色继续生效。
2. 通过全局背景坐标提供壁纸和三处柔光采样。玻璃层只模糊背景采样，不模糊文字；哑光、降低透明度及嵌套深度保留实色退化。
3. 侧栏检索扩展至真实聊天、任务和工作区文件，点击进入对应真实页面，不虚构索引结果。
4. 对聊天产物卡→工作区预览接入 `SharedTransitionLayout/sharedBounds`；本 PR 进一步加入相同 Work 会话下完成的目标卡→结果卡 Morph；它不能替代定时任务列表的独立身份，真实动效仍须验收。
5. 通知发送按完成、失败、需要处理、人物主动消息分组控制；免打扰覆盖跨午夜，失败/待处理继续送达。
6. 高使用频率的设置分组、外观预览、账户卡和模型资料卡改用 V6 L3 采样材质；模型/账户输入行与小型选择器改用 V6 L1 语义层，选中强调色仍独立保留。

以上是**代码实现口径**，不代表设备截图已逐状态与设计对齐。

## 验收矩阵及通过条件

每屏最低检查 **浅色 / 深色 / 哑光黑**、壁纸开关与复杂背景、大字 1.3x/1.5x、393dp/412dp、滚动/键盘/系统栏安全区、默认/选中/禁用/加载/错误态、无障碍触控与返回；有动效的屏幕还要检查正常和减少动态效果两种状态。不能从 Mock 业务数值推断实际功能不存在。

真实设备自动化能验证页面不崩溃和部分交互，**不能自动替代设计图叠图、全状态覆盖或人工视觉判定**。每屏只有在提供 `Android 版本 + 设备尺寸 + 字体倍率 + 主题 + 状态 + 截图/录屏证据 + 复核结论` 后才能标记“视觉通过”。

## 2026-10-13 · 手机端 V6 主导航第一批（PR #664）

- **仅手机（小于 600dp）**：主页顶部直接呈现设计 01 的三个空间入口。聊天为「会话／对话／人物档案」，工作为「会话／工作／文件」；中间项是当前真实会话并明确标记为选中。
- 不另造会话列表和人物数据：会话入口复用现有抽屉，人物档案进入已存在的 Gallery Detail 页面且沿用未保存人物确认，文件进入原工作区页面并清除旧文件精确跳转目标。
- **无双路由树**：实际页面仍由 LocalFeatureCatalog / Feature Contributions 管理。顶部旧菜单仅在手机启用新三项导航时隐藏，设置、工具等仍从会话侧栏进入。
- V6 视觉承托直接复用 FluidSectionNavigation，避免新增散落的颜色、透明材质、动效定时器或触控规范。测试：V6MobileHomeNavigationTest。
- 本批并非 01/38 的全面视觉验收；需要最新 Android 16/17 CI 和生产真实截图，避免以 ReadmeScreenshotActivity 的 Mock 冒充验收。
- **范围决定**：用户明确只支持手机，600/1024/1440 等原有大屏兼容分支仅保持不动，不继续专项投入，也不冒然删除相关功能代码。
