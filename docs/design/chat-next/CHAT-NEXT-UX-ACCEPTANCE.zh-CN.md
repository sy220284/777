# Chat Next · 页面状态、交互与验收契约

> 状态：**设计候选，尚未实现**。配套文件：CHAT-NEXT-PAGE-ARCHITECTURE.zh-CN.md。原生 Android Compose/V6，主线基线 969754e。此文件用于拆分实现 PR、代码审查、组件测试和设备验收，避免以静态截图替代实际使用体验。

## 一、全局交互契约

### A. 页面拥有者

| 对象 | 权威状态 | 界面读取方式 | 修改入口 |
|---|---|---|---|
| 当前会话/消息 | Session + EventLog | 现有 LocalConversationSurfaceState | Chat Send/Transcript/Session 领域 Owner |
| 人物资料/故事 | ChatPersonaGalleryStore / ChatPersonaStore | Gallery/Story UI facade | 人物与故事命令 |
| 角色状态/关系 | ChatState、ChatContext | Chat projection | 有来源的事件归并与人工修正 |
| 日记 | ChatDiaryStore | DIARY 入口 | 原有更正/停用命令 |
| 记忆 | MemoryStore + Chat 记忆投影 | 只读本轮引用回执 | Memory/Diary 归属更新 |
| 群成员/交付 | LocalGroupChatState + GroupReplyDeliveryLedger | Chat group UI projection | 群成员事务、成员交付事务 |
| 模型与真实能力 | LocalModelRuntime/ModelGateway | LocalModelPickerSheet | 模型配置及 Session 选择命令 |
| 附件 | 工作区关联文件 + 发送请求 | 附件草稿与能力检查回执 | 导入、移除、页选、发送 |
| 主动互动 | Automation Feature | TASKS + Chat 独立授权摘要 | Automation 命令 |

### B. 用户动作的稳定规则

1. 任何“发送成功”必须意味着用户原文和附件引用已写入可恢复消息源；模型执行本身仍可能等待。
2. 任何“完成”必须有相应模型/群成员交付与持久写入事实。取消、部分完成、结果未知独立展示。
3. 同一失败回合的恢复复用原请求与附件，用户可以查看上次执行与再次执行的对应关系。
4. 页面切换时保持输入、附件、滚动锚点和当前故事身份，回到聊天继续同一个可恢复对象。
5. 网络查询明确遵循本轮用户否定意图、既有授权和实际路由；网页来源对角色背景只是参考材料。
6. 群聊只发布完整交付的事实；失败或部分回复要用户明确接受后才可参与故事事实归并。
7. 模型修复、联网、状态整理、群成员请求记录实际调用消耗，界面可追溯。不可凭估算宣称实报额度。
8. 用户未启用主动任务时，界面展示可启用入口但不创建、启动或恢复任何新调度。
9. 所有建议与草稿都是可撤销编辑，不覆盖现有用户输入。
10. 后端状态与界面文案共享枚举或强类型字段，不能根据错误字符串判断“已经完成”。

## 二、每页的状态交付矩阵

下表中“恢复”均指回到可操作位置，非无条件自动重发模型请求。

| 页面 | 首次空态 | 等待/执行中 | 失败/结果未知 | 成功与恢复 |
|---|---|---|---|---|
| C00 首页 | 无模型显示配置入口；无人物可自由聊 | 配置中禁重复提交，保留草稿 | 配置失败显示原因和返回入口 | 返回同一空会话，发送原输入 |
| C01 自由聊天 | 标题、输入、合理引导 | 消息真实增量；模型/联网状态仅有需要时展示 | 保留部分文本；显示重试原回合 | 回复和消耗关联当前用户消息 |
| C02 人物聊天 | 当前角色+新故事标题 | 人物状态有意义的进度提示 | 中断不产生未经确认的剧情承诺 | 故事与记忆准确关联，重新进入位置一致 |
| C03 群聊 | 2—6 位成员和公开场景 | 当前发言者明确，其他人可静默 | 单角色失败或部分完成就地恢复 | 角色消息公开，状态归并按来源与完成度进行 |
| C04 人物图集 | 无人物显示创建按钮 | 加载本地人物列表，维持滚动 | 图片缺失有占位，更新失败保留原值 | 保存后的图库卡片与人物详情一致 |
| C05 人物详情 | 故事为空时提供“开始新故事” | 人物修改有保存状态 | 保存失败停留编辑态，不混改当前故事 | 正确进入选择的故事并保留来源 |
| C06 日记 | 无条目显示明确空态 | 筛选、搜索、修正显示进度 | 修正失效时可查看来源与重试 | 已更正日记不会被新回忆再次当成旧事实 |
| C07 聊天设置 | 无设置值时使用真实持久默认值 | 配置保存中阻止冲突操作 | 保存失败回滚并显示原因 | 回聊天后偏好从已确认设置生效 |
| S01 新会话选择 | 三个入口全部可理解 | 人物/群成员准备中保留已选 | 取消不创建空会话 | 仅确认后建立新会话，随后回 HOME |
| S02 人物故事上下文 | 未绑定人物显示选角色 | 读取当前故事真实摘要 | 故事不存在显示可行动修复 | 可切换、打开概览、创建新故事 |
| S03 事件概览 | 无已确认事件显示适当说明 | 定位来源时等待分页结果 | 来源缺失显示“历史已变更” | 来源消息定位可见，不误跳 |
| S04 消息操作 | 按用户/助手消息提供对应项 | 重生期间仅该操作受限 | 旧分支已失效则拒绝写入且可返回 | 版本与具体消息 ID 一致 |
| S05 回复恢复 | 仅失败/部分完成显示 | 恢复中显示回合与角色身份 | 恢复失败保留原部分内容 | 成功写一次交付，不增加伪用户消息 |
| S06 待发队列 | 无项目则入口不出现 | 已排队/执行中独立状态 | 某项不可执行可编辑/撤销 | 同一 ID 串行完成并正确移除 |
| S07 群成员选择 | 不足两人显示创建入口 | 调整待保存时保留用户选择 | 保存失败保持原成员和原顺序 | 已确认公开场景不丢失 |
| S08 相关记忆 | 无回执说明“本轮无相关记录” | 来源定位中可取消 | 来源失效或修正待恢复有明确提示 | 修正后下一轮不读到失效版本 |
| S09 附件确认 | 未添加文件不出现 | 导入/页选中禁止重复读取 | 模型不支持或提取失败清楚提示 | 本轮实际看到的文件范围可确认 |
| S10 模型/Work | 无模型可前往配置 | 模型切换/交接中保留原上下文 | 失败不删除 Chat 原消息或附件 | 切模型下一轮生效，Work 有目的地 |

## 三、必须一次性贯通的完整用户路径

### F01 自由聊天首次使用
无模型 → 输入草稿 → 点击发送 → 提示配置模型 → 完成配置 → 返回同一会话 → 草稿和附件仍在 → 发送成功 → 结果和模型用量可追溯。

### F02 人物多故事
人物 A → 故事甲 → 100 轮交流 → 故事概览 → “新故事”创建故事乙 → 聊天 → 回到甲 → 恢复甲的关系、场景、来源，不引入乙的私人经历；人物原档案仍共用。

### F03 历史分支改写
故事里找到一条旧用户消息 → 编辑并创建新走向 → 后续回复只对新分支有效 → 切回旧分支 → 旧人物状态、日记、时间线都与原版本一致；新分支的归并异步写入不得覆盖旧分支。

### F04 生成时继续发送
A 用户消息进入模型执行 → 用户输入 B、C → 明确加入队列 → 看到 B、C 等待状态 → 编辑 B、撤回 C → A 完成 → B 自动继续 → 队列归零。停止 A 时提示仅停止当前执行还是同时取消待发队列（默认为保留待发队列）。

### F05 部分回复
模型产生部分文字后中断 → 时间线保留阅读文本，标“未完成” → 不向正式关系/承诺写入 → 用户在原回合重试或明确接纳现有片段 → 只向确认的故事事实推进一次。

### F06 群聊单成员失败
用户点名人物 A、B → A 完整回复 → B 部分失败 → B 的失败提示和原回合 ID 有来源 → 点击“仅重试 B” → 重放本轮已公开 A 的回复作为上下文 → B 完成 → 公开事件顺序正确且不复制 A 的回复。

### F07 群聊自然参与
3 人群聊连续 30 条不同语义普通消息 → 无点名时根据语境选择，最近活跃者不永久垄断；点名 A 仅目标 A；要求全部人表达则覆盖参与成员，允许符合人物背景的沉默行为且不会假装已发言。

### F08 文件适配
附加图片和指定 PDF 页 → 选择不支持视觉输入的模型 → 发送前准确告知限制 → 选择匹配模型或 Work → 全过程文本、文件和页选不丢失。扫描 PDF/压缩包并未完整读取时清楚显示范围。

### F09 联网边界
输入“不要联网搜索”+网址 → 不发外部搜索；输入“打开这个网页分析”且网络授权开启 → 展示检索进度和来源；网络失败 → 模型回答标注未核实，而不是生成不存在的检索事实。

### F10 记忆更正
角色从过往错误推断出一条日记 → 用户进入来源并更正 → 后台持久失效处理 → 页面和新模型上下文均采用新版本 → 原始真实聊天保留以供回查。

### F11 大量草稿
至少 20 个本机会话分别写文字、添加图片/PDF → 关闭应用进程 → 重启切换各会话 → 无旧 LRU 12 上限导致的意外丢稿；发送与删除完成后，附件引用垃圾回收正常。

### F12 数据恢复
从已有版本安装升级包 → 迁移用户人物、故事、群聊、消息、分支、日记与附件 → 对每个源对象保留稳定 ID 或经过验证的映射 → 数据和可操作性与迁移前对照一致。

### F13 用户授权主动互动
用户未启用 → Chat 不新增调度；用户从明确入口开启某人物/故事主动互动 → 显示频率与免打扰 → 连续无人回应达到上限时停止继续打扰 → 用户关闭后停止对应授权。

### F14 自然表达
同一基础话题由不同原设人物回应，测试无统一慰问模板、无强制亲密动作升级、无周期性脚本化问句。人物事实准确与表达多样性分别评价，不能以增加句子长度替代自然度。

### F15 Chat → Work → 返回
用户在 Chat 请求完整分析多页扫描文档 → 当前模型/模式不足 → 选择 Work → 确认任务及附件 → Work 任务创建成功且能看到进度 → 完成后经用户选择摘要带回原 Chat → 角色故事内不把工具执行过程当成共同经历。

## 四、业务约束和 UI 对齐测试

| 关键不变量 | 后端证据 | 前端验收 |
|---|---|---|
| 一条用户请求只能对应一个原始用户交付 | 稳定 messageId/turnId 和入队日志 | 重试/恢复 UI 不多出伪用户气泡 |
| 群聊仅确认完整有效回复 | completionReason 和成员交付记录 | 部分回复标识、单成员恢复且故事不乱 |
| 新故事有独立经历范围 | experienceId + source session ids | 标题、关系、日记在正确故事展示 |
| 同一人物主设跨故事共用 | persona/gallery ID | 修改主档案在各故事一致，事件不跨线 |
| 每次联网有明确许可与原因 | 网络入口与搜索请求回执 | “不联网”零搜索调用，来源可见 |
| 草稿不会按 12 会话上限静默淘汰 | 本机会话级 draft persistence | 20+ 会话重启恢复 |
| 用户点击成功基于真实写入 | 事件日志/保存回执 | 不出现“点完像成功、重开消失” |
| 修正与分支隔离有版本约束 | generation / source IDs | 旧状态不会晚到并污染新分支 |
| 所有模拟执行态最终可归档 | durable run status | “执行中”终止后静止，可重试/可追踪 |
| 模型能力真实 | effective model route/profile | 发送前提示、实际附件处理一致 |

## 五、组件质量验收

### 统一状态

每个可交互组件至少确认：默认、触控按下、键盘/无障碍焦点、不可用、加载、成功、失败、取消。涉及模型生成或群聊交付的还要有部分完成、结果未知、恢复中。

视觉反馈、可点击性和 TalkBack 语义要同步变化。禁用态不能仍能响应按下。加载态不能把未保存的数据伪装成成功。

### 原生触控

- 48dp 触控目标；长按和滑动不得与文字选取冲突。
- Sheet 关闭和拖拽保留源列表/消息阅读位置，背景滚动被正确锁定。
- 软键盘弹起和收起不遮住发送/停止控制；宽屏/横屏不用错误的固定位移。
- 预测返回继续沿用既有 Android 宿主，取消手势不误执行保存/删除。
- 大字号不会令长模型名、人物名、群聊状态挤成逐字竖排。
- 同一帧没有多层玻璃边缘、重复厚阴影或正文后面的高亮遮挡。

### 主题/性能

- 典雅白、磨砂黑、系统跟随、多个强调色、自定义壁纸均验收。
- 极亮、极暗、高饱和及高频细纹壁纸上正文应达到实际合成对比要求。
- AGSL/动态材质在切换角色、键盘出现、滚动时与同源背景正确对齐。
- 减少透明度使用有对比的实心状态；减少动效停掉非必要动画并保持可操作。
- 验收 Android 16/17 真机中的帧率、输入延迟、内存压力和应用后台恢复，结果记录具体设备与版本。

## 六、设计审核与 GitHub 实施门槛

每个功能 PR 必须同时附带：

1. 修改的生产模块与对应的页面/组件范围。
2. 真实的操作前后状态及数据来源。
3. 失败、停止、取消、恢复的可复测行为。
4. 受影响的单元/UI/仪表测试或升级迁移测试结果。
5. 主线相关 V6 Token、入口、交互文档更新与屏幕状态对照。
6. 如有真机测试则提供设备、系统、操作录像/截图对应真实构建；没有实际执行时写明未验证。

整体验收包括前述 F01—F15、主线全部相关回归、跨人物/跨故事长聊盲测、群聊多角色、断网恢复、附件与真实模型计费记录。不以“设计图完整”“单个 PR 通过”“规范已经写好”代替 Chat Next 业务整体完成。

本文件是实施方案与验收清单，当前没有更改业务代码、没有完成真机验证，也没有启用自动任务。
