**设计主题：安静的阅读流 + 鲜明的人物身份 + 真实状态反馈。** 主聊天读者看正文、头像和输入；复杂能力只在有实际任务时出现。视觉避免统一大圆角卡片墙、浓灰边、多层阴影以及蓝紫霓虹。

## 1. 主对象、事实归属和入口

用户每天接触的主对象是“当前会话”，而人物故事的长期业务对象是“故事/经历”。具体约定：

- Conversation/Session：承载可恢复的消息、模型请求和 UI 状态。由现有 Session/EventLog 负责。
- Story/Experience：承载某位或多位人物在这一条叙事线中的事实、场景、关系和时间线。继续故事跨会话保留经历身份；新故事获得独立身份。
- Persona：稳定的人物资料、世界书和设定，按图库 ID 关联；不因总结/日记改写作者原设。
- Turn/Message：每次输入和模型回复的事务身份。排队、取消、重试、完成必须绑定同一个实际来源，覆盖附件。
- Public/Private evidence：群聊共享的是已经公开并确认的事件；角色私人经历不因同处一个聊天室自动共享。
- Derived states：人物情绪、故事回顾、日记和记忆索引，均可从有版本的来源事件重新校验/生成。

首次进入时数据来自：本机会话目录、人物图集、用户已配置模型、本机草稿。没有会话/人物/模型分别展示对应真实空状态，绝不生成假聊天记录或默认“今天的故事”。

    ├───────────────────────────────┤
    │            阅读时间线           │
    │                               │
    │  人物自然回复，全宽正文          │
    │                               │
    │              用户独立气泡       │
    │                               │

    │                               │
    │         ↡ 回到最新             │  ← 读者主动上翻不自动跳到尾部

系统输入法出现时将输入区移至键盘上方，消息列表保留当前阅读锚点。系统 Back 优先关闭键盘、Sheet、详情，然后返回上级路由；预测返回手势继续由 LocalFeatureAnimatedHost 持有。

### 4.2 C00 首次启动与空状态

- 已配置模型、无人物、无消息：顶部显示“自由聊天”，中央提供一条适度的引导文案，底部输入可立即发送；另有“选择人物”“创建群聊”两个次级入口。
- 未配置模型：主操作“配置模型”，进入现有 MODELS 设置；保存成功返回原空会话且保留草稿。
- 有人物但无故事：显示人物头像、介绍和“开始新故事”；不凭空填充历史。
- 图库无人物且选择群聊：显示“创建第一位人物”，返回后保留已选列表。
- 会话可恢复：优先展示最近可恢复的真实会话，未确认的模型执行保持原状态而不是伪造成功。

### 4.3 C01 自由聊天 HOME

主动作是文字/图片/文档输入。顶部为真实会话标题，点击打开会话信息。模型控制在输入展开后可见，默认显示简短当前模型名。消息操作允许复制、编辑、重生、使用量、联网来源与 Chat → Work。普通 Chat 不展示角色世界书、关系和人物日记。

### 4.4 C02 人物聊天 HOME

顶部左侧：人物头像、名称；下一行：**当前故事真实标题**。点击展开 S02。正文保持全宽开放式阅读，故事事件标签仅在消息确实产生经确认的重要节点时轻量提示。人物稳定身份的视觉归属来自头像、字体与语义色，避免给每个人物重新做一整套不同按钮主题。

人物头像点击后：
1. 当前人物摘要（设定、知情范围）。
2. 当前故事：继续 / 故事概览 / 选择其他故事 / 开新故事。
3. 表达偏好、人物档案（低频）。

已存在对话时切换到其他人物，会显示“与该人物开始新故事/继续其既有故事”的选择，不尝试在旧经历内直接替换人物。

### 4.5 C03 群聊 HOME

Header：群聊名称（可编辑）、成员头像最多 6、当前发言人物与人数。角色进入发言阶段时，高亮当前说话的成员头像；这是运行状态反馈，生成结束后静止。

每条公开角色发言显示角色头像/姓名和正文；同一位角色连续发言时适度减少重复头像占位。用户消息仍采用独立气泡。

群公告由 S07 管理，作为公开背景展示；群聊开始后新增人物或更换成员，应明确是否开新群聊故事、如何继承公开历史，禁止无提示覆盖原群关系。

角色静默时可以有“本轮未发言”的信息供查看，但不在每个普通回合强制展示。某个成员失败时，局部标明其交付状态和“重试此成员”，不生成新的用户文本消息。

## 5. 关键功能页面与浮层逐项交互

### S01 新会话选择 · 直接从右上角“＋”打开

三项：自由聊天 / 选择人物 / 多人聊天。自由聊天一触即建；选择人物进入现有人物图库选择流程；多人聊天进入 S07 并确认场景。用户关闭流程不生成空会话。已有内容的新建请求保留旧草稿和滚动位置。

### C04 + C05 人物图集与详情

图库继续沿用现有双列图片卡和搜索，卡面只突出头像、名字和一句身份描述。长按进入管理，不引入评分、百分比关系或旧数值徽标。详情强调“继续上次故事”“开始新故事”两个动作；故事列表按最近更新、固定收藏和搜索排序。每个故事行：标题、最后活动、最近一项确实发生的事件、当前可继续状态。人物设定分为基础资料/世界书/表达偏好，所有编辑以显式保存与失败回滚为准。

### S02 + S03 故事上下文 / 重要事件

S02：人物、故事名、当前时间地点及简洁进度，三条主要动作“继续故事”“查看故事”“开始新故事”。S03 故事概览按“此刻”“发生过”“仍未完成”排序；每个重要事件都有原始消息定位与版本。故事内容为空时不展示假剧情或情绪进度。

事件导航是消息索引的另一种视图，定位后关闭浮层并回到消息源位置，保留返回前的滚动锚点。创建新分支时使用源消息 ID 与 generation，创建成功后才切换可见路线。

### S04 + S05 消息操作 / 失败恢复

用户消息：复制、编辑后重发、定位、导出/交 Work（可用时）；助手消息：复制、再生、选择回复版本、相关记忆、使用量与媒体创作（可用时）。消息操作以来源 ID 绑定，历史分页后仍能找到对应对象。

S05 对失败回合展示“失败原因 / 已保存内容 / 本次附件 / 原执行模型 / 是否已经提交任何回复”。允许“从失败处继续（具备能力时）”“对原回合重试”“保存可读部分”“撤销本回合”四种有实际后端支持的操作；未接入的动作在实现过程中不得先画成可点击假按钮。重试必须继承原回合 ID 或建立明确关联的再次执行 ID，不向时间线添加伪造的新用户指令。

### S06 输入中队列管理

运行期间输入框仍可聚焦；主按钮显式区分“发送下一条”与“停止当前回复”。停止为独立清晰触控目标，不隐藏在发送按钮状态切换中。入队后底部出现轻量“待发送 N 条”入口。

队列详情按实际顺序展示文字预览、附件数量与等待状态，允许编辑、撤销、移动顺序（经一致性检查）；执行中的那条不可被伪装成“仍在等待”。队列为空时入口消失。发送失败不清除草稿；用户主动取消队列项时清理相应投影并保护未被其他消息引用的附件。

### S07 群成员与公开场景

沿用 GroupChatMemberPickerSheet 和 SyMultiSelectSheet，支持搜索、已选 2—6 位人物、保留顺序、创建新人物。群聊建立前允许拖动排列初始人物顺序；群聊已有消息时的成员变更按故事身份与公开事件重新确认。群公告可编辑，但清楚标为“所有成员可见的背景”，不自动构造成已发生的事件。

### S08 关联记忆面板

用户点击“本轮相关记忆”打开：按“明确事实/人物个人记忆/当前场景”分组，展示本轮实际参与的来源和简要文本。每条含“查看原文”“修正/停用”操作；人物猜测要有“个人观点”提示。无法提供实际检索回执时不虚构“读取了哪些记忆”的 UI，先在记忆 Runtime 建立轻量只读引用证据。

### S09 附件能力检查

加号一级保持“拍照 / 图片 / 文件 / 多模态创作”，对新选文件显示格式、大小、缩略图及 PDF 所选页。点发送时先检查模型能力与当前模式：
- 完整支持：直接发送。
- 仅能读取部分：告知页数/字符/文件范围和本轮能看到的内容，用户可调整。
- 必须借助工具：建议交给 Work，带上原请求和同一附件引用。
- 不支持或丢失：提示具体原因与修复操作；保留输入与附件，不让“已添加”造成“已理解”的错觉。

### S10 模型能力选择与 Work 交接

模型列表沿用 LocalModelPickerSheet，附加能力摘要：文字/图片/文件/视频、推理、上下文、是否已授权。能力缺失从模型 Runtime 的真实属性确认，未知标“未验证”，不猜测。切换模型只影响后续请求。

Chat → Work 使用确认 Sheet：说明拟执行的任务、原消息及附件引用、会带走的必要上下文、目标 Work 会话。用户确认后才创建交接；失败保留原聊天和草稿。

### C06 日记

继续复用 DIARY 路由，按人物/故事筛选，卡面展示事件摘要与人物主观内容，支持搜索、纠正、停用、查看来源；编辑成功同步使相关派生状态失效，等待恢复中的状态显示可读错误和重试。

### C07 聊天设置

只显示可理解的项目：语言与回复偏好、记忆与个性化、网络查询授权、主动互动入口、人物资料管理。高级模型温度继续归模型采样参数，不放在“人物性格”下；主动互动具体计划在原 TASKS 管理。任何开关的开/关都反馈实际持久化结果。

## 7. 动效与手势契约

- 使用现有 SyMotion token：按压 70ms、选择 150ms、Sheet 280ms、进入 260ms、返回 220ms、同级切换 140ms、输入展开 155ms。可按新增语义统一改 token，但不可在多个页面散落任意时长。
- 输入区聚焦：尺寸连续展开，键盘弹起时不挤出底部安全区；附件出现后保持文字选择范围。
- Sheet 拖拽：手指移动时 1:1 跟随，边界缓冲、方向识别、距离/速度联合吸附、取消手势恢复；背后滚动锁定，关闭后保留消息锚点。
- 群聊：当前发言头像短暂强调，流式消息显示真实增量；完成、失败、取消后立即停止脉冲。
- 故事事件：点击后跳转源消息并提供短时位置强调；手动阅读历史时不强行回到底部。
- 系统返回：优先恢复当前层，原有 Predictive Back 宿主保持所有权。横向消息操作不能抢系统边缘返回。
- “减少动画”关闭非必要位移；“减少透明度”独立使用实心表面；TalkBack 始终读出角色身份和状态。

## 8. 视觉设计语言

- **结构**：阅读流大留白；头像与正文层级明确；仅活动状态/菜单/输入器使用局部材质。
- **色彩**：继承用户当前选定主题与强调色，支持暖白、炭黑、朱红、琥珀金、橄榄绿等合理组合；避免把某组色固定给全部用户。避免蓝紫色霓虹默认色。关键状态采用语义色和文字。
- **材质**：聊天正文优先清晰，L2 用于栏/输入底座，L4 用于浮层；复杂背景采用全局区域取色与光学合成。取消大面积厚灰边、多层玻璃重复绘制、强阴影和装饰性伪折射。
- **文本**：沿用 SyType，人物名称略强于故事次标题；长正文保证行距，代码块/引用/附件有明确边界。标题过长省略，详情可读全名。
- **尺寸**：SyMetric 最小触控 48dp，图标 20—24dp；圆角按控件语义 9/13/18/24dp；注意小屏和大字号时按钮按内容纵排。
- **对比**：实际合成后的普通文本目标 ≥4.5:1，重要非文本控件与大字目标 ≥3:1；极端亮/暗/高纹理壁纸必须在 Compose 上验收。

## 9. 不新增的页面和被明确移除的设计

不增加“聊天控制中心”“独立人物数值仪表”“八种反应强度设定”“独立运行中心”“额外底部 TabBar”“重复任务与用量入口”。

退出默认回复中强制动作素材、统一人格评分和关键词触发的互动强度控制；保留作者自行撰写的人物描述和实际剧情，不通过 UI 数值滑杆塑造固定的情绪反应。

回复建议保留在低频入口，点击建议默认插入或预览，不直接覆盖用户现有草稿。

群聊重试更改为真正的原回合操作，旧“发送另一条请求重试”退出。

## 11. 页面状态和测试矩阵

所有页面至少检查：首次空态、数据已有、加载、网络/模型不可用、部分完成、失败可重试、取消、会话切换和进程重启。每个真实操作的 UI 反馈必须对应实际的持久化结果。

设备矩阵：320/360/393/412dp + 横屏；深浅主题、无壁纸/复杂壁纸；默认/放大字号；键盘打开/关闭；系统返回/预测返回；减少动效/减少透明度；TalkBack；Android 16/17。

关键端到端路径：
1. 无模型 → 配模型 → 返回同一草稿并发送。
2. 人物 A 新故事 → 长聊 → 继续故事 → 新故事 B → 回 A，验证记忆隔离。
3. 同一故事编辑历史 → 建新分支 → 切回原分支，验证时间线。
4. 连发 3 条排队输入 → 中途停止 → 恢复 → 不重复模型交付。
5. 群聊 6 人 → 某角色失败/流式不完整 → 仅此角色原回合重试 → 状态正确。
6. 图片 + PDF 指定页 + 不支持模型 → 显示差异并转 Work，附件仍可访问。
7. 禁止联网的用户请求不发出外部搜索；用户允许联网时展示来源。
8. 纠正人物日记 → 重算相关状态 → 原始消息仍可定位。
9. 跨超过 12 个会话保存文字和附件草稿，重启后全部恢复。
10. 100/300/1000 轮长聊，跨人物/群聊对照自然度、事实召回、错误恢复和实报 Token 消耗。

通过判据：没有不可达入口、假按钮、重复事实写入、未授权联网或静默丢稿；任何模型失误、运行中断均存在可解释和可恢复的用户操作。真实模型自然度需独立实测，不以规则测试代替。

## 12. 术语与文案口径

| 界面名称 | 精确定义 | 避免混用 |
|---|---|---|
| 新聊天 | 创建新会话 | 不自动等于重开现有故事 |
| 新故事 | 创建独立经历身份 | 不自动继承旧故事关系 |
| 继续故事 | 沿用明确的经历身份与历史来源 | 不改变人物作者主设 |
| 重新生成 | 为同一用户消息尝试新的助手回复版本 | 不写入新的用户消息 |
| 重试此回复 | 从原失败事务恢复或重新执行该成员交付 | 不伪装为用户新发言 |
| 保存部分回复 | 将不完整内容明确保留为可读记录 | 不自动确认为有效剧情事实 |
| 待发送 | 排队尚未开始执行的用户请求 | 不等于已经发给模型 |
| 相关记忆 | 此回合实际引用的、带来源的记忆 | 不显示推测的“模型内部回想” |
| 交给 Work | 经确认把原始请求与附件交由工作模式执行 | 不暗中调用工具 |
| 人物表达偏好 | 作者/用户的文字表述与风格倾向 | 不等于人格数值或模型温度 |

## 13. 完成定义

本候选文档完成的是 **页面与交互全量规划**：入口、页面树、空态、完整交互、设计语言、复用关系、状态、代码映射与验收均已定义。下一步实施时应先完成一致的消息事务和故事事实层，再把新组件接入原生 UI；不能把设计 PR 当作功能代码已升级或真机验收已完成。
