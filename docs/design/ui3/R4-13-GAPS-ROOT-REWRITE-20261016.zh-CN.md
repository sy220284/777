# R4 剩余 13 项：去防御式补丁的根因重构与代码闭环方案

> 2026-10-16 · 适用 PR #705 / `feat/ui-r4-pluggable`。这是**实施方案和代码缺口清单**，不是完成凭据。最终以 `R4-CODE-TASKS.json` 逐项源码与最终 HEAD 验证为准。保持 Draft、`v6.migration.accepted` 不授权，不提前合并。

## 一、验收口径与不可违反的边界

1. **本轮只做代码交付，不设置设备验证任务。** `CODE_PARTIAL` 仅表示源码缺口；Owner、UI、恢复逻辑及契约测试齐备，完成编译/单测/架构检查后，可升级为 `CODE_IMPLEMENTED_UNVERIFIED`。75/75 Renderer 与 173/173 映射仅是登记数字，不能替代行为实现。
2. **禁止防御性编程：** 不允许空数据/空接口/假成功占位，不允许 catch 后吞异常、返回伪造成功/旧快照、自动无声退回 Legacy、盲重试付费调用、复制一套 Store、靠定时器掩盖事件漏订阅、改小测试期待值、关闭测试或放宽门禁。**边界的身份、输入、权限、并发与文件校验属于业务契约，必须保留。** 未知执行结果必须作为未知结果交付，不能伪装失败或成功。
3. **单一 Owner。** MCP 连接与授权属于工具运行 Owner；文件/分享/权限属 Host 服务；Work 证据及任务结论属 Work Owner；动态内容与历史属 Session/EventLog；UiPack 只投影与提交具名操作。所有长任务共享会话、运行、请求/回执、来源版本标识。
4. **代码级可验证性：** 用 JVM/Compose 单测与契约测试覆盖正常、拒绝、取消、撤权、迟到、并发修改、序列化重建、无权访问、副作用幂等。最终 SHA 必需的编译、单测、静态和架构检查应通过。**不要求设备、模拟器、仪器测试、人工体验验收。**

## 二、13 项根治设计（不以补丁冒充完成）

| 编号 | 根因与唯一改造方向 | 达成代码完整的最小证据 |
|---|---|---|
| S-1-01 MCP 状态 | 从 HTTP ping + 2s 列表轮询，重构为 MCP Owner 主动发布**有序连接生命周期事件流**；Composer 选中是偏好，逐次授权由会话/调用 ID 的独立事件表示。断线、重连、卸载、Agent 连接变更统一订阅同一流；UI 不维护第二份状态真相。 | 远端主动断链触发订阅者更新；断链后旧选择仍是偏好但不允许执行；逐次授权不跨会话继承；包含晚到事件与重启契约测试。 |
| S-1-02 插件隔离 | 将不可信/可崩溃插件的执行域与应用核心区分：独立进程服务与 IPC 生命周期；插件状态、工具准入、外部资源释放由 PluginManager 单一事务管理，不再以 try/catch 包裹整个运行时。纯内置且共享堆内存的插件不能假称“进程隔离”。 | 插件崩溃不拖垮 Host/其他插件；工具注册原子撤下；用户显式重装后恢复；崩溃中副作用未知时绝不重放；进程终止和恢复测试。 |
| S1-05 Work 证据 | 文件摘要只能证明**当次字节版本**，不能证明完成要求。由 Work 建立不可变文件版本引用、来源工具事件、目标 ID、原始要求及用户确认的**独立核验结论**；核验器按可验证要求执行，无法自动验证则明示“仅引用/待人工确认”。杜绝提交前后文件 TOCTOU 对结论的污染。 | 更换目标绝不继承同文案的无目标旧证据；变更文件不复用旧结论；核验失败/人工未确认不显示通过；并发写入和冷恢复回归。 |
| S1-07 附件 | 只在附件 Owner 中实现导入、校验、稳定引用与类型化预览；图像/音视频使用 Android 正式解码与播放器生命周期。系统 URI 的授权状态、撤销及重新选取由 Host 管理；不把失权伪作已导入。 | 多种文件导入、预览/播放、取消、撤权、URI 恢复及跨会话隔离的代码与契约测试。 |
| S1-08 Host 服务 | 新建**统一的中立 Host 系统能力协议**：文件挑选/保存/分享/外部打开、通知/权限读取与申请、IME/焦点生命周期。所有 UiPack 通过能力与操作回执接入，Android SDK 只在 Host 实现；不让页面各自启动 Intent/维护结果。 | 每种服务有明确授权、取消、拒绝、返回/重启契约；7 路由都使用同一 Host；Host 接口、回执与状态恢复的单测/Compose 测试。 |
| S1-09 旧业务回调 | 以“谁创建状态、谁执行副作用”为准逐项移除 App Shell 内业务编排。将剩余设置、消息、媒体、文件等旧回调迁回现有 Feature Owner，再由中立 Port 驱动独立 V6；不复制旧 ViewModel/Facade 或加入过渡兜底。 | 静态扫描禁止独立 V6 反向依赖旧 Shell；旧页面回调断开后操作仍完成，失败与拒绝回执未丢；契约/回归测试通过。 |
| S3-02 导航 | Host 唯一拥有 7 路由、二级 Scene、系统深链、返回与持久导航快照；恢复时按新场景目录和会话身份重建，拒绝历史场景但保留可恢复的有效目标。UI 不自己维护并行路由栈。 | 深链/回退/多级设置/保存快照恢复一致，目标失效不跨会话错跳；用 Host 导航与生命周期单测证明。 |
| S3-06 旧 Shell 退场 | 增加可验证的**禁用 Legacy Shell 运行构建/测试入口**，经 Host 的正式准入运行全部独立 V6。旧 Shell 业务回调全部迁出后方可删除，不能靠生产默认 Legacy 来证明 V6 有效。 | 禁用旧 Shell 的编译与组合测试构造真实 V6 完整场景，逐项验证关键 Owner 操作与恢复；缺路径即失败，不回退。 |
| S4-01 工具 Schema | 可信 MCP/本地工具 Schema 必须经封闭字段类型/枚举/预算校验后投影为**只读预览或可填写表单**；执行仍单独经过当前会话工具授权 Owner。模型返回的 JSON/URL/schema 一律不能产生新执行权限。 | 对象/数组、必填/可选、枚举/多行、未知类型拒绝、金额授权、来源冲突的契约及 UI 回归。 |
| S4-02 动态媒体 | Media Owner 唯一保存下载任务、远端授权、会话归属、流式文件写入、断点与 ETag/版本校验；V6 只展示实际下载/转码/播放进度及明确的保存回执。未知收费结果不重试创建任务。 | 远端授权下载、中断续传、文件更换拒绝、跨会话读写隔离、音视频解码失败和 SAF 导出回归。 |
| S4-03 核验卡 | Work 提供类型化“未核验/核验中/可复核/已由人工确认/不通过/来源失效”及可追溯依据；卡片只订阅来源修订、任务变化和权限变化，不靠 30s 轮询保鲜。不能把模型文本或 SHA 相同认作验收通过。 | 新旧来源替换使旧卡失效、序列化/冷读可复建原证据；未经用户确认无“已通过”标记；人工确认写回独立事件。 |
| S4-07 历史恢复 | Session EventLog 是唯一历史真相；对文本/表格/图表等改动使用版本化有类型命令、原子 CAS、墓碑、逐版本升级器和增量分页；不可恢复的版本应显示明确阻断而非重放旧动作。 | 编辑/删除/分页/跨旧版本、乱序事件、崩溃恢复、重复请求和长会话预算等真实回归，不删除原数据。 |
| S4-08 敏感与预算 | 会话草稿采用按字段敏感级别定义的**存储策略**（禁止保存、会话内暂存、可加密保存），清理旧数据与事件投影；EventLog 冷恢复采用有界增量索引，UI 不无限载入历史或把密钥写 SavedState。 | 敏感值不可出现在 SavedState/日志/快照；密码字段重建后要求重新输入；长历史 O(窗口) 投影、超限真实回执与冷恢复测试。 |

## 三、执行序列：先解共享根因，再逐项关账

- **G0 构建恢复**：消除当前真实 CI 编译/断言错误，补齐可靠静态/单测验证。不得因排队/取消判定成功。
- **G1 单一 Owner**：S-1-01/02、S1-05、S1-09。先建立工具状态事件、插件故障域及 Work 证据真相，再迁移业务回调，避免新版 UI 复制旧逻辑。
- **G2 Host 一次性接线**：S1-07/08、S3-02/06。将系统服务和导航建成稳定端口，完成“禁用 Legacy”测试入口；不能先拔旧 Shell 再补 Host 能力。
- **G3 动态内容统一模型**：S4-01/02/03/07/08。先将来源/身份/版本/授权/恢复明确为同一事件模型，再增加 Schema、媒体与编辑，不让每个 Scene 自己补轮询和异常兜底。
- **G4 代码闭环**：34 项逐条核对；既有“代码完成待验证”按源码/单测/编译重核；原 5 项专项任务改为代码级检查。173 动作按 Owner、实际副作用及恢复回执落实对应回归。无需设备与人工验证。`v6.migration.accepted` 仅在功能/代码验收全通过后考虑启用。

## 四、本批已落地与仍然存在的事实

- **已写入代码**：Android Compose 测试去掉不可用的 `assertDoesNotExist` 扩展，改用实际语义节点集合为空来严格验证旧操作不可达；Work 证据历史投影阻断“无目标旧证据继承其他新目标”，并更新 JVM 回归断言。
- **未完成**：这两项修复没有让上述 13 项整体满足“代码实现完备”；OS 级插件隔离、事件订阅、文件/Host 统一能力、工具 Schema、远端媒体与历史迁移均不可以先标记完成。
- **CI 特别说明**：旧 CI #38892957755 的单测与测试代码编译失败是真实日志；当前 16 项设置入口须以本轮单测/编译确认。设备测试结果不作为本轮交付依据。

**进度更新规则**：每项提交必须附源码路径、测试路径及最终 SHA 编译/单测/架构回执；如只修某个子问题，记作增量，不能把 `CODE_PARTIAL` 改为 `CODE_IMPLEMENTED_UNVERIFIED`。原 13 项在闭环前继续列为 13 项。
