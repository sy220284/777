# 神言 V8 · 界面重设计说明

> **性质：全新视觉方向，不是 V6/V7 的改良。** V7 已作废（见 [V7 状态](../v7/STATUS.zh-CN.md)）。本文定义 V8 的视觉语言、界面结构与落地路线。
> **依据：** App 的真实功能与真实使用流程（代码事实 + App 自带文案），不继承 V6 的视觉表达。
> **机读令牌：** [tokens.json](tokens.json)｜**校验：** [resolve-tokens.py](resolve-tokens.py)｜**离线稿：** `mobile/app.html`

## 1. 为什么重做

V6 是「暖墨 · 精密玻璃」：多层半透明材质、壁纸分区取色、实时模糊。它的问题是**表达方式压过了内容**——所有层级都用半透明+高光+阴影表达，界面显得薄、凉、信息密度低；真正的功能（人物、日记、任务、产物、上下文）没有被当成一等公民。

V8 的方向：**阅读优先、质感优先、动作分级**。

| 主张 | 含义 |
|---|---|
| **阅读优先** | 会话与日记是主战场：正文 15px/1.6、中文混排不漂、代码与引用各有一套排版；界面装饰让位给文字 |
| **质感优先** | 宣纸有纸纹与暖光，卡片有真实阴影与高光，浮层有层次；不是纯色块 + 1px 线 |
| **动作分级** | 主动作实心、次动作描边、行内动作纯文字；每屏只有一个主强调色 |
| **状态有话** | 运行中 / 等待批准 / 失败 / 完成，既有色点也有文字；不靠颜色单独表达 |
| **产品语言** | 界面文案取自 App 真实 `strings.xml`，不出现设计说明或"模拟数据"字样 |

**对比度：** 正文类全部 ≥4.5:1（最低一项为暖纸三级文字 4.6:1），强调色在常态与按下两态均 ≥4.5:1，由 `resolve-tokens.py` 自动校验（当前 64 项全过）。

**强调色卡：** 保留 App 现有的八张色卡与它们的持久化 key（`zhusha` / `xianghuang` / `celadon_explicit` / `dailan` / `zitang` / `yanzhi` / `yushi` / `songshi`），只更换显示名与色值；前景色按实际填充色求解，两极取自令牌 `poles`，求解器不允许自带硬编码兜底。

**人物色：** 岚 `#2F6B63`、小晴 `#A9642C`、亦书 `#3A5A8C`、星遥 `#8A3A54`（深色主题各有提亮变体）。人物色只用于头像点、人物条目与该人物的会话标记。

## 3. 材质与光

- **纸纹**：画布叠加 3.5% 的分形噪点（暗色 5%，正片叠底 / 屏幕混合），宣纸不再是死板纯色。
- **暖光**：画布顶部一道极淡的强调色光晕（暖纸 5.5%、夜墨 10%），哑光主题不加光。
- **深度**：卡片 = 抬升面 + 1px 暖边 + 双层柔和阴影；夜墨用内高光替代描边；哑光无阴影，只靠明度差。
- **浮层**：菜单 / Sheet / Dialog 三种语义外观，圆角与阴影分级（`semantic.overlayVariants` 唯一来源）。
- **输入区**：悬浮圆角卡（28dp），双层阴影，距底 12dp，与内容之间留呼吸。

## 4. 排版

| 角色 | 字号 | 行高 | 字重 |
|---|---|---|---|
| hero / display | 30 / 26 | 37 / 32 | 700 |
| title | 20 | 27 | 600 |
| heading | 17 | 24 | 600 |
| bodyStrong | 15 | 22 | 600 |
| body | 15 | 24 | 400 |

| caption | 12.5 | 18 | 400 |

- 界面用无衬线（Outfit + Noto Sans SC 子集，仓库既有）；**人物名与日记标题用衬线**（`--font-serif`），承担"人物感"。
- 数值、路径、ID 走等宽；行高为绝对值，与 Compose `TextStyle.lineHeight` 一一对应，便于 CI 机械比对。

## 5. 几何与动效

- 圆角：小 10 / 控件 14 / 卡 20 / 面板 28 / 浮层 18 / 胶囊 999。
- 间距：4 / 8 / 12 / 16 / 20 / 24 / 32。
- 动效：按压 90ms、选中 160、页面推入 280、Sheet 300、Dialog 220、侧栏 240、进度 320；统一缓动 `cubic-bezier(.2,.9,.25,1)`；按压缩放 0.98；系统减少动效时全部归零。

## 6. 界面结构（按功能，不是按原设计）

### 6.1 HOME · 会话

- 顶栏：抽屉按钮 + 标题（衬线人物名时用衬线）+ 状态副标题（就绪 / 执行中 / 第 N 步）+ 单一右侧动作。
- 顶部**上下文条**：上下文用量、待办数量、记忆连接状态——把真实存在但无处安放的信息收进一处。
- 助手回复：全宽开放阅读，无卡片；段落 12px 间距，列表、引用、代码各一套排版；代码块带文件名头。
- 用户消息：右下浅染气泡，右下角收角，宽度上限 80%。
- 消息元信息与操作行（复制 / 重试 / 分支 / 更多）在气泡外侧，纯文字与 18dp 图标。
- 运行中：顶栏下方一条 2px 柔和扫光；输入区主按钮变为停止。

### 6.2 HOME · 工作

- 目标卡：目标名 + 步数/耗时 + 状态徽标。
- 时间线：左侧状态轨（点 + 线）+ 右侧内容卡。当前步朱砂点与呼吸光环，待批准步琥珀点，完成步降噪为纯文字，失败步用危险色图标与文案。
- 步骤内操作：引导 / 停止这一步 / 去确认 / 忽略。
- 成果：文件样式卡（类型图标 + 文件名 + 大小 + 操作），不用厚重容器。

### 6.3 能力中心 / 定时任务 / 工作区 / 设置

统一的**行列表**语言：图标 + 主文案 + 一行辅助说明 + 右侧状态或箭头，行高 56dp，行间 1px 分隔线，不再卡片套卡片。设置按 4 个分组（外观与体验 / 模型与账户 / 能力与权限 / 系统）组织，危险操作放末尾且只用文字色。

### 6.4 人物图集 / 人物日记

- 人物卡：方形相片 + 衬线名字 + 一行身份 + 右上人物色点；选中态为 2px 强调色描边，不加色块。
- 日记：日期 + 衬线标题 + 行距 1.85 的安静正文；只有这一页把阅读密度放到最低。

## 7. 状态语言

| 状态 | 视觉 | 文案 |
|---|---|---|
| 运行中 | 强调色呼吸点 + 扫光进度条 | 执行中 / 正在生成 |
| 等待批准 | 琥珀点 + 卡片内双按钮 | 等待批准 |
| 失败 | 危险色图标 + 危险色标题 | 失败，可检查 |
| 完成 | 成功色点 + 降噪排版 | 已完成 |
| 取消 | 中性点 | 已取消 |

颜色与文字同时出现，TalkBack 读到的状态词与视觉一致。

## 9. 验收

- 三主题 × 表面角色 × 三级文字对比度自动通过（≥4.5:1）。
- 320dp / 360dp / 393dp 与 100% / 150% / 200% 字体下无截断、无重叠、无竖排挤压。
- 减少透明度、减少动效下层级与可读性不降级。
- 七条主路由与 21 项设置入口全部可达，行为与现状一致，**视觉重做不夹带功能变更**。
- `tokens.json`、Compose 实现、设计文档三处一致，CI 可校验。

## 10. 明确不做的事

- 不改业务契约、不增删功能入口、不恢复已退役入口。
- 不动用户已有的外观偏好数据（色卡 key、主题选择、字号与字重设置）。
- 不声称已同步 Figma / Canva（无可访问设计资产时保持"待同步"）。
- V7 的视觉结论不再作为实现依据；V7 目录仅保留事实底账与复核记录。

## 11. 与前两版的关系

仓库里同时存在两条被否掉的 V7 路线，V8 与它们的差别是**明确的**：

| 维度 | V7-A（材质语法，我方第一版） | V7-B（静纸，并行会话版） | **V8（本版）** |
|---|---|---|---|
| 表面 | 五层材质语法 + 实时模糊 | 两级表面 + 1dp 发丝描边 | 三级表面 + 真实阴影 + 纸纹暖光 |
| 卡片 | 描边 + 高光 + 阴影叠加 | 无阴影 | 双层柔和阴影 + 暖边（暗色用内高光） |
| 图标 | 通用线性图标 | 通用线性图标 | **仓库自绘纸墨品牌图标**（25 枚入口 + 62 枚动作 + 12 枚独立资源） |
| 文案 | 混入设计说明与"模拟数据" | — | **全部取自 App 真实 strings.xml** |
| 质感 | 无 | 无 | 纸纹 3.5% + 顶部暖光 + 人物色 |
| 密度 | 16sp / 1.65，偏松 | — | 15sp / 1.6，贴合现有阅读手感 |

被否的共同原因：前者"薄"，后者"平"。V8 的判断是——**阅读界面的质感来自真实光影与材质，而不是半透明叠加，也不是极致扁平**；两者都把"少"当成目标，丢掉了"精"。

## 12. 吸收并行会话的工程根因（实施前必须解决）

并行会话的代码审计给出了 7 条与视觉无关、但会决定落地质量的根因，V8 路线图一并吸收：

| # | 根因 | V8 的处理 |
|---|---|---|
| G1 | 状态色靠中文文案判定（`statusText.startsWith("执行异常")`） | P0 先把状态改为 phase 枚举驱动，颜色与文案解耦；`semantic.status.*` 令牌只描述语义，不描述文案 |
| G2 | 10 个设计系统组件零调用、45 处裸 `material3.Surface` | P1 起建立"组件归位表"，棘轮基线从 45 逐面递减，每 PR 报数 |
| G3 | 三套左右边缘基准（22 / 14 / 26dp） | P0 令牌层定 `pageGutter` / `sectionGutter` 两个常量，全页只引用它们 |
| G4 | 输入区 320dp 下 48dp 失守（5×48 + 间距 > 可用宽度） | P2 输入区在 320dp 下次要动作收为横向滚动 chip，不压缩命中区 |
| G5 | 中文正文回落系统字体（`contentFont` 只挂 Outfit） | P0 字阶层明确 `body` 必须绑定 Noto Sans SC 子集，字体产物进构建 |

| G7 | 两条 M3 scheme 构造路径（换色卡与默认路径字段不一致） | 依赖并行会话 PR #938 的单一构造器，不重复实现 |
