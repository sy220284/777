## 设计原稿直接核出的高价值遗留问题

- **P1｜壁纸**：#749 加五主题×明暗资源和启用；#751 在 #749 上加十张自由选择。两者均待最终设备验证、明暗覆盖、选中位置/模糊/遮罩/范围控制；不能因图片文件打包就声称附录 O.4/O.7 完全完成。
- **P1｜审批模式 IA**：E8.18 附录 F.2/F.3 要求 Agent 与安全独立审批设置页；当前页面仍把审批模式放在 `settings.permissions`。要先看既有 SceneCatalog 能否新增路由或以真正的二级目的地复用安全导航，不增无效 UI。
- **P1｜真实运行详情**：#749 有进度环/事件，但 Work 计划、审批、工具证据、需求关联是否在 E8.18 设计的统一详情工作流内，要以有真实状态的场景逐屏对拍。
- **P1｜自动化失败策略**：原设计要求失败策略，现 `AutomationUiPort` 缺独立可保存字段。必须先补 Owner 契约与实际 Worker 语义，再开放按钮；禁止伪开关。
- **P1｜人物亲密度**：设计卡有亲密度指标，现 Gallery Owner 没有可核的真实数值；#749 只添加真正的头像/故事状态，不填虚构进度条。
- **P2｜MCP 连接方式**：设计双选；Owner 当前只提供 `ConnectHttp`，不得放一个不执行的第二 Tab。
- **P2｜更新检查与设置密度**：原稿要求设置首页即时检查更新、每组不超过四行；当前多一层，首组五项，需在导航语义与原 Host 回调边界内调整。
- **P1｜全局按钮状态**：源码有 pressed/focus/disabled/loading，不代表所有界面按钮调用者已按业务忙碌状态禁用。必须对每个写入 Owner 的动作做重复触发/取消/撤销回归。
- **P1｜真实无障碍**：各路由缺全域 200% 字号、TalkBack 顺序、键盘遮挡、系统授权回跳、纵横屏与安全区证据。
- **P1｜跨 PR 集成**：#751 依赖 #749，#750 是并行分支；必须顺序集成并验证其与 #750 的相同文件交叉，不可分别 CI 全绿后直接声称合体通过。

## 证据与质量门槛

已有 50 项是**50 个各异的专项检查**，不是 50 次完整 Android 运行；本次只是在 PR 并行开发后重核处理归属和残留。不可保证发现“所有”运行时与视觉问题，真实网络/模型计费/媒体资源下载/Android 权限与设备焦点需要端到端证据。

验收优先顺序：P0（权限/数据/计费）→ P1（入口假操作、数据错位、功能断链、视觉关键结构）→ P2（密度/字级/文案与微交互）。未完成的设计要求必须明确保留，而不是以 UI 展示模拟。
