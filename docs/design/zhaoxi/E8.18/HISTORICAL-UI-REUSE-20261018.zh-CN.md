## 与 #758 需求规格的真实集成

原历史追溯保留 279 个 UI PR 节点、26 组旧版取舍；用户明确取消「需求与证据／工作记录与交付」及独立 `work.requirement_evidence` 场景，**不再列为待还原需求**。移除该项后，原历史 75 场景有效验收范围为 **74 场景**；现行额外 `settings.approval_mode` 合计 **75 Pack Scene + 3 Host Scene**。Work 的计划审阅、任务时间线与文件查看继续保留。

本轮新增的用户路径：
- 侧栏顶部新建当前模式会话、全域搜索；Chat/Work 切换后保留侧栏，历史会话只显示相应模式；当前会话按 Owner 真实身份标示。
- 自动化任务同时按文本、所属模式和实际状态检索；已有任务搜索无结果与根本没有任务区分。
- 设置页面的“检查更新”保持动作型入口，不引入已经淘汰的更新跳转页。

本轮补齐的真实技能管理入口：工具中心 → 插件与技能管理，复用旧 Scene `tools.plugins` 和唯一 `ToolsUiPort`，提供 SKILL.md/ZIP 系统选取、文件大小预检、创建、读取与编辑 SKILL.md、模型自动发现开关、复制 `@skill:ID` 手动调用指令、删除确认及预置安装。**只在 Owner 确认后提示安装/保存成功**；技能对话创建的预填 Work 入口尚未在本批接通，不得宣称完成整个 #571。对应 5 项文件读入边界单测已提交。

尚未满足 #758 的完整交付门槛：虽然 #759 已在源码中接入会话长按/置顶/重命名/批量删除、人物多故事页、Chat→Work 明确选取历史内容、文件批量导出及工作证据等路径，这些动作**仍待真实 Owner 返回、跨页面、失败恢复和 Android 16/17 设备回归逐项签收**；技能通过 Work 对话创建的预填链路及 Chat→Work 原附件交接仍未完整接通。必须先核实对应 Owner/Host 的可用动作和真实授权，再实现按钮；不得用假页、假数值凑数。

## 全屏背景与安全区（截图黑色顶带）

- Android Activity 显式进入 edge-to-edge（内容可绘制至状态栏与导航栏），朝夕背景在 `SceneFrame` 最外层绘制满屏；`systemBarsPadding` 只应用于交互内容，不再裁切整张背景。
- 接入异常页继续避让系统栏；设备验收场景使用与生产一致的绘制顺序，避免截图把顶部空白当作正常设计。
- 该变更属于 UI 布局与窗口显示，不改历史会话、工具、审批的业务 Owner；Android 16/17 实机安全区与三键/手势导航截图仍须按最终 SHA 复验。

- 修正第二层布局：主页 `ModalDrawerSheet` 的背景本身保持全高，不承受全局 `systemBarsPadding`；只有抽屉内部控件使用上下系统安全区。普通页面继续在场景层避让系统栏，避免所有页面逐个改造成孤立的特例。
- Android 主页面烟雾测试新增抽屉顶边为 0dp 的真实布局断言。**该断言只证明 Compose 边界，不代替最终设备像素截图与状态栏配色验收。**
