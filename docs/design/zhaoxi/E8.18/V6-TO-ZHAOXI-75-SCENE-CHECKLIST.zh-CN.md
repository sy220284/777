# 朝夕 E8.18 · 75 场景入口与历史完整需求逐项签收矩阵

**用途：** 配合 [《历代 UI 需求最终还原规格》](V6-TO-ZHAOXI-UI-REQUIREMENTS.zh-CN.md)，将旧 UI 历次明确的真实功能、入口、动作、布局和恢复规则映射到当前新 UI 的每个 Scene。只要某个入口虽有路由、实际未显示对应数据或按钮无法完成真实操作，状态继续记为「待逐动作验收」。

**基准**：当前主线 `ZhaoxiUiPackManifest.fullSceneIds`，程序性核对 **75/75 ID 唯一匹配**；不包含宿主的 `conversation.attachments`、`shell.notifications`、`system.permissions` 三场景，宿主同样需要真实操作回归。当前 Scene ID 不是页面数：包含 7 顶层、内部插槽、二三级页面及独立弹层；不可把一个同样的空页面当作多个不同 Scene。

## 每项验收须记录的字段

按场景维护：**（1）设计稿节点/截图（2）打开入口（3）正常和异常状态（4）全量按钮/控件（5）真实 Owner 与命令回执（6）返回、冷恢复及跨模式隔离（7）Android 16/17 含真实数据的设备录像或截图（8）明确完成状态**。没有 (5) 和 (7) 的不能因为渲染可见就打钩。

**本表当前全部标记“待逐动作验收”，不是声称 75 项均未编写代码。** 已有 #740/#745/#746/#749/#751 的代码实现和专项 CI 可复用，但需要按其实际证据逐项签收；#750/#753/#754/#755 等仍处于独立待验 PR，不可提前当成正式主线完成。

## 实现优先级（与用户日常路径一致）

**P0：** 首页、侧栏、Chat/Work 输入与滚动、历史、模型切换、人物选择/编辑/故事续接、Work 计划/审批/成果、设置入口与更新、草稿/返回；先确保一个普通用户可以从打开 APP 到得到结果完成真实闭环。

**P1：** 群聊、人物手记、自动化新建编辑、工作区/文件、媒体创作与成果、模型/账户/用量/记忆/权限/通知、工具连接的日常完整路径。

**P2：** 全范围大字号、复杂富文本、连续长任务、所有异常/权限/离线/收费结果未知状态、深层恢复、性能/无障碍/壁纸动态对照（P2 不代表可以忽略安全关键项，安全相关拒收永远属于发布门槛）。
