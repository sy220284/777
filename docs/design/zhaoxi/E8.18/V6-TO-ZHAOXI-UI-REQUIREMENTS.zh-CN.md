# 777 → 朝夕：历代 UI 需求最终还原规格（可执行基线）

**性质：产品需求还原，不是 V6 归档，也不是恢复 V6 皮肤。** 本文面向当前朝夕 E8.18 界面重建。以仓库 #1 起至 #738（2026-10-17 删除 V6 UI）之间用户反复提出并已明确取舍的交互、功能入口、布局、行为要求为依据；截止主线快照 ee088165569c512cfaf42aa3414c861f0aa582f1。当前新界面代码和 75 场景审计为对照对象，不把「代码有路由」等同「功能已还原」。

## 0. 裁决原则（防止新 UI 变成空壳）

1. **保留的是能力与用户体验，不是 V6 的旧页面组件。** 朝夕 E8.18 设计稿负责具体排版、视觉和动画；历史 UI 负责补齐缺失能力、入口、状态、操作顺序、导航连续性、数据来源和失败恢复。与 E8.18 已确认设计发生视觉冲突时，保留 E8.18 外观，移植 V6 的功能动作。
2. **以最后一次有效且已进主线的明确取舍为准。** 例：#701 是遮住左滑删除按钮，#720 最终是彻底取消左滑删除；#704 的四项大快捷卡被 #708 轻量同源加号栏覆盖；#652 的工作五阶段和沉浸阅读分别被 #709、#717 删除；#157 的双列图集被 #719 最终单列轻量行覆盖。不可叠加旧版已撤销方案。
3. **UI 只消费真实业务信息。** 会话、人物、关系、故事、群聊、记忆、工作运行、审批、任务、媒体、账户、Token 费用均来自既有 Feature Owner/Port；缺少可信数值时不能以假卡片或假按钮替代。
4. **入口必须真的可用。** 页面可见→点击能到→能看数据→能正确保存/执行→能显示受理/失败/未知→能安全返回、重启恢复。这六个环节缺任何一项，不能叫「已还原」。
5. **按三个层级验收。** （a）路由与按钮静态存在；（b）端口真实调用及状态回执；（c）Android 16/17 含真实数据的视觉与交互。三者分别计数，不能用 75 个场景分支、模拟截图或 CI 绿灯替代（c）。
6. **不借还原理由重建废弃业务。** Work 项目管理、独立旧运行中心、旧后台助手和 V6 沉浸阅读曾被明确撤销；当前 E8 设计新出现同名独立页面时，应核对它承载的是仍然有效的文件、Work 证据或通用消息阅读能力，而不是静默把退役功能复活。

**朝夕当前实现事实**：ZhaoxiUiPackManifest 有 75 个非宿主场景、37 个能力 ID；另 3 个宿主系统场景（附件、通知、权限）。这是 Scene/Slot 清单，不能误报为 75 张完整业务页面。页面并列关系与入口来源必须在每个真实场景另行验证。

## 2. 主界面与侧边栏（最高频，必须按路径闭环）

### 2.1 主界面布局
- 上方：窄且有身份感的顶部区域。Chat 明确当前人物/群聊、故事或会话；Work 显示会话和当前模型/任务身份。模型选择不是模型配置，入口名称与进入位置不得混用（#270、#525）。
- 中间：完整的消息时间线是唯一主体；不能再在 Work 主页堆五阶段仪表盘、独立产出大卡、重复「新会话」标题（#709）。
- 下方：共享 Composer，包含文本输入、当前附件、加号菜单、模式对应的少量高频操作、发送/停止。运行中按钮位置稳定，长中文/大字号不得竖排或把发送挤出屏幕（#289、#294、#694、#704）。
- 空白首页：Chat 不要没有来源的虚假角色图片和轮播欢迎屏，独立会话清楚显示「未选择人物」；空态有用户能执行的自然引导而非大块占位；启动后直接到 App 主界面（#142、#310、#547）。
- 真正的会话身份和导航状态更新**完成后**才切换页面；不能先导航然后再因请求失败弹回去（#618、#663）。

### 2.2 侧栏完整布局与入口
- 顶部：可配置的应用头像/品牌，右侧「新建」「搜索」；搜索图标展开真实搜索框。旧版多余关闭按钮不恢复，关闭依抽屉手势/外部操作；头像预置裁切优先露出头部，支持真实本地头像选择和持久化（#303、#398、#401、#526）。
- 模式：**一个轨道、一枚内部滑块** 的 Chat / Work 切换胶囊，48dp 可触达；切换只改变目标模式和相应历史/快捷能力，不应默认打开某条旧会话，也不能清空在看的设置页。切换后侧栏仍可展开继续挑选（#310、#387、#493、#699）。
- 当前上下文：Chat 显示当前人物/故事或群聊成员；Work 显示当前工作会话/模型/运行状态。要真实、节制，不能给所有会话叠状态卡（#393、#430）。
- 功能快捷入口：Chat 以群聊、人物图集、人物手记、角色定时互动为主；Work 以工作区、自动化、工具/能力为主。原「运行中心」如果需要入口，只指向现行工作执行详情/证据，不得重新创建废弃独立 RunCenter（#174、#270、#393、#698）。
- 会话列表：置顶/最近，当前项标识、工作任务运行状态、必要副标题；历史列表是主要滚动区。搜索应真实过滤相关会话/人物/工作文件/任务域，而非只有一条能输入的空搜索框（#17、#393、#202、#663、#746）。
- 底部：设置必须为固定、清楚的「齿轮+设置」行；连接中的本机工作等状态按真实业务显示（#551）。**#598 已在 #551 之后彻底删除旧远程控制、远程会话、配对和中继**，因此侧栏、设置、搜索、通知与二级页均不得恢复旧远程控制入口；本机 MCP/GitHub/Webhook 等独立能力不属于被删除的远程控制。
- 抽屉是**覆盖主页面滑出**，主体不横移、不被裁成额外圆角卡；**侧栏背景要连续绘制到屏幕顶部及底部（系统栏背后），可点击内容再分别避让状态栏、刘海和手势导航区**。不可通过整体下移抽屉或只给内容列添加底部安全区内边距来冒充全面屏修复；截图出现顶部黑带、底部断色或抽屉未铺满即不合格（#520、#693；详见 §12.1 全局 P0 验收）。
- 会话项**不支持左滑删除**：点击打开，长按弹出重命名、置顶/取消置顶、多选与删除，删除需要确认。批量选择有明确退出、全程不丢当前真实会话（#720）。
- 删除当前会话后去**同模式新独立空白会话**，而不是跳到历史上一条、更不能切到另一模式；历史删除不扰乱当前页面；失败提示与旧会话还原逻辑完整（#618）。
- 从侧栏打开功能 A→详情 B→返回先回 A，再回侧栏/来源页；切换模式时不强制跳回主页面；打开明确选中的会话才进入该会话。系统返回、边缘手势、键盘关闭的优先级不可混乱（#396、#447、#492、#663、#699）。**#492 最终规则**：左右系统边缘滑动都执行返回；普通内容区右滑打开侧栏，侧栏内左滑关闭。#447 早期“系统左边缘返回打开侧栏”被覆盖，不能作为最终验收。

**验收用例**：当前 Chat→侧栏→人物详情→返回图集→返回侧栏→设置→返回侧栏；当前 Work 运行中→切 Chat→再回 Work 原会话仍持续运行；搜索结果直接进人物详情并可逐级退回；新建、删除、批量删除和快速连续点切换不会跳错模式。

## 3. Chat 单聊、群聊与回复（必须保留完整操作，不是一个聊天气泡）

### 3.1 Chat 的身份与生命周期
- 支持无人物的独立普通聊天、已选人物聊天、故事续接、群聊，不能强制所有聊天绑定默认人物。
- 「继续对话」沿用人物、相关故事、关系和上下文；「新对话」清空旧人物/故事/关系绑定，并显示未选择人物；群聊新建与单聊新建明确可选（#148、#260、#310、#525）。
- Chat 不展示 Work 工具控制台、命令行和工程日志；专业能力仍归 Work，不因两模式共享底座而视觉串场（#128、#129、#197、#201、#270）。

### 3.2 消息时间线与正文
- 用户气泡轻量自适应；助手独立阅读面，V6 最终为宽度约 91%、内边距水平 16dp / 垂直 13dp；新朝夕按自身图稿还原具体几何，但必须有相当的长文舒适度和气泡区分（#710）。
- 单聊/群聊共用同一富文本：原始换行不丢、标题/引用/列表/代码块/表格/链接/删除线/选择复制可用；代码块可横滚并独立复制；长表格能横向滚动、按列对齐，不得被外层截断（#553、#710、#754 已并入主线；仍需真机长表/大字号验收）。
- 思考/工作过程与正式答复清晰分层，过程默认轻量/折叠，不把内部命令、路径、JSON、原始工具参数、工程符号刷进普通聊天（#5、#63、#110、#114、#116、#553）。
- 流式回复渐进增长，滚动到末尾时随新内容跟随；用户主动往上翻历史后暂停抢滚，保留「查看最新」入口。键盘展开收缩视口时只跟随原本处于尾部的用户，阅读历史时不可强制跳尾（#464）。停止/失败/完成显示真实状态，不能重复插入同段正文（#138、#553、#740）。**历史可见容量按用户消息与最终助手答复计，不得被工具、推理、进度、系统消息挤占**；接近顶部按可见消息补页，正常浏览无需点“加载更早”，只有失败才出现重试（#439）。
- 回复信息层级：正文优先，必要回合用量是弱说明文字，消息操作在正文外且不抢阅读视线（#544、#710）。

### 3.3 每条消息的准确操作
- 用户消息：长按有「复制、修改」；Chat 任意仍属于当前活动时间线的历史用户消息均可编辑，含图片/附件的结构化内容不丢失。**最终按 #244/#245/#263 的覆盖式编辑**：提交修改后保留之前的对话，原修改点及其后续旧消息退出当前活动时间线，重建分页与后续回复；相关人物状态、记忆、故事和“本会话文件”撤销旧未来，不得让旧内容从缓存/重启/版本切换复活。可切换的助手回复历史版本是另一种操作，**不等于**历史用户消息编辑后仍可切回整条旧未来（#158、#228、#302）。
- 助手消息：复制、朗读、重新生成、历史版本前后切换（存在版本时显示位置/箭头），完整回复显示「创作」；未完成/无可执行能力时不出假按钮（#158、#302、#544、#710、#716）。
- 重新生成成功保留可切换历史版本；失败不清掉原回复。Work 涉及外部副作用的重试不得因为前端按钮而无授权地重跑工具（#136、#158）。
- 消息操作必须精确绑定所选会话和 message ID；切换人物/会话或删除消息后旧菜单失效，不能误操作另一条消息（#705、#740）。

### 3.4 回复建议
- 单人 Chat 有可发现的回复建议图标；**用户主动点击才生成**，不每轮默认额外花 Token。已有候选直接打开，生成中有加载/防重复，失败可再试（#210）。
- 通常提供 1–4 条不同方向、贴近最近多轮真实语境的候选；不强制模板凑满；点击**只填输入框、不自动发送**，可修改；下一轮/换会话及时失效（#154、#218、#729）。**#615 把有实际对话依据的未来约定/提醒/再次联系建议合并到此入口**，不得恢复打开自动化页就自动额外请求模型的独立推荐链，真正创建任务必须用户确认。
- 不复活早期已淘汰的“故事走向/替用户做选择”旧链路（#140、#154、#219）。

### 3.5 群聊
- 能从现有人物选择 2–6 名成员，头像选择可滚动搜索、明确勾选态、保存确认；群聊消息注明说话人物，群内各人物身份、设定和私密关系记忆隔离（#159、#277）。
- 群聊顶部有成员管理、可编辑群公告/剧情背景，允许用户手动编辑，公开背景由群聊真实上下文读取；**#615 删除独立 AI 生成群公告和固定剧情模板**，不自动篡改人物档案（#173、#615）。
- 群聊顶部要有**退出群聊**，且能切到新空白单聊；“新建”明确选择新单聊或新群聊，保留旧群聊记录（#260）。
- 群聊显示连贯的多人物回复，不需要每人每轮说话；避免群聊 UI 变成多列 AI 调试台。人物名称只展示一次：已有发言者标签时应去掉模型正文重复的「角色名：」前缀，复制也不带重复抬头，不能误删正常以人名开头的句子（#172）。

**验收用例**：独立空 Chat→选人物→聊天→保存故事→继续→另开新故事；历史消息修改/版本切换保持对应后续对话；群聊建群→公告→点名→成员编辑→退出单聊；候选建议仅填草稿。

## 4. Work 对话、执行过程与审批（核心区别：能做事、能看清、能恢复）

- Work 顶栏简洁展示当前任务/会话身份和模型；具体技术参数放到二级，不能挤满首页（#270、#525）。历史用户指令支持**Work 自己的编辑执行链**：确认修改点/外部副作用后，恢复当时模型上下文与任务状态，后续旧事件从活动时间线退出；已执行的工具/外部文件副作用只留真实审计证据，既不假装撤销，也不静默重放。模型未配、运行繁忙、历史不可恢复、编辑拒收须显示具体原因并保留用户输入（#602）。
- 主界面是时间线：最新思考（如启用）、正在检查/搜索/修改/执行/联网/设备/委派的**语义步骤**、计划审阅、待回答问题、审批、成果、错误。**#386/#445/#630 后每轮工作与计划调查都优先显示正在核对什么的具体中文进度**；不能因工具回复为空退化成“处理当前步骤”等通用模板，不能把原始命令、路径、推理或 JSON 当用户进度。工具类别/数量放次要位置，不同语义步骤不得误合并。步骤状态分别是进行中、成功、失败/受阻，真实失败在结束后仍保留（#114、#270、#386、#430、#553、#630）。
- 工作步骤能展开/折叠、回看更早节点、保留用户选定的展开状态；持续动态效果只作用于真正 Running 节点，不要整页同时闪动（#239、#326、#430、#724）。
- 计划审阅在聊天时间线可见并能确认、拒绝、复制、重新生成；普通提问采用真实选项/输入确认，审批显示目的、权限风险和有效待审批请求；系统返回不能偷偷当成拒绝（#240、#304、#705、#746）。
- **执行结束 ≠ 用户验收成功**；需要单独展示实际文件、目标步骤、需求与证据、交付版本来源/校验条件、失效/未满足/部分完成状态。工作会话菜单有「工作记录与交付」，能查看完整历史分页和单次工具阶段详情（#730）。
- Work 输入框运行时仍能正常排队新指令及停止任务；只在「运行中 + 有新草稿」展示可关闭的「立即调整」，关闭或草稿清空即回默认排队。不要多一条“下轮追加”选择带和长说明挤压输入区（#694）。
- 工作是按会话独立后台运行：切离、切 Chat、浏览设置/文件不取消、不重复启动、不串结果；重新打开原会话应**重新绑定同进程仍在运行的原任务**，继续显示原审批、进度与消息，禁止错误触发第二次持久恢复或双重执行（#284、#434、#447、#618）。Chat 不投影 Work 后台的子代理/设备/运行占用为自己的状态（#145）。
- Team/Agent 集群如可用，使用专用任务/成员状态与可管理面板；团队成员结果「待核验」不能直接被助手文本当作完成；**#641 规定运行步数只能显示 X/Y 步，不能冒充任务完成百分比**；真正任务进度依据已完成任务数/总任务数。成员输出、负责人/依赖、追加消息、停止单个/全部及失败恢复要能从集群面板操作（#570、#575、#580、#595、#638）。当前审批与工具授权复用既有 Owner（#499、#502、#619）。
- Work 不恢复已删的五阶段导航/独立产出框和旧独立 RunCenter，但**实时进度、Agent、计划、产物、审批、后台任务**必须在时间线、菜单和独立工作详情可达；这是隐藏冗余页面而非删除业务（#698、#709、#730）。
- **Chat → Work 交接（#608/#610）**：在聊天中分页查找并勾选历史发言/图片/文件材料，生成可编辑的工作目标和可公开摘要，经确认后新建有来源关系的 Work 会话，绝不能直接切进旧 Work 会话；源角色私密内容不得越界，失败保留选择，能力未授权要显示真实状态。

**验收用例**：提交任务→计划确认→工具执行→审批/提问→真实成果→证据核验；执行中切 Chat/设置/文件再返回，进度相同且没有重复计费/执行；取消、拒收、权限不足、结果未知都有独立 UI。

### 12.1 Android 全面屏、系统栏与安全区（P0，所有页面通用）

**用户目标**：打开朝夕时，从屏幕物理顶部到系统导航区域背景连续、无突兀黑带或留白；内容不被状态栏、摄像头开孔、圆角、手势条、三键导航和输入法遮挡。**“背景铺满屏幕”与“内容留在安全区域”必须同时满足**，不得把二者混为只加一层内边距。本条适用于 Chat、Work、侧栏、全部二级页面与弹层，不是仅修复一张侧栏截图。

- **窗口与背景层**：Android 16/17 按 Edge-to-edge（边到边）窗口规则处理。App 根背景、当前主题/壁纸、页面及抽屉遮罩必须延伸到可绘制窗口的上下边缘并衔接系统栏区域；切页面、开关侧栏、主题切换、动画过程中不出现系统默认黑底、露出未绘制的顶/底条、突然断色或闪烁。系统自行管理且不可绘制的硬件区域除外，不要求侵入摄像头开孔。
- **内容安全区分层**：标题栏、按钮、滚动列表、底部 Composer、固定“设置”入口等可交互内容根据所在容器正确避让状态栏/刘海/显示屏圆角及导航栏；背景和遮罩不因同一避让而缩短。由根窗口、导航容器、Scene 与内部列表明确分工，**同一种 Insets 不得重复叠加**，避免“整体下移一截”“底部多出一条空白”。全屏背景可伸入系统栏背后，但控件不能被手势条遮挡。
- **侧栏截图对应的拒收项**：抽屉打开时，顶部不能留一整条深色状态栏/窗口空带导致侧栏从其下方才开始，底部也不得出现未绘制区域；覆盖式抽屉从可绘制窗口顶端延续至底端，右侧主页面只被连续遮罩覆盖，不横向挤压、不另加圆角。顶部品牌/关闭或返回动作、底部“设置”按钮必须在安全区内可见可点。**仅在内部 Column 增加 navigationBarsPadding()，但没有解决窗口/抽屉背景覆盖的，不能视为修复**。
- **全页面及弹层一致**：Chat/Work 首页、会话时间线与输入区、搜索、人物图集/详情/编辑/故事、工作区/文件预览、任务、工具、全部设置及各级二级页，均不得在顶/底露出黑带。抽屉、Dialog、Bottom Sheet、选择器、媒体预览、权限返回等叠加层须延伸自己的背景/遮罩到应覆盖的位置，但仍允许 E8.18 设计明确要求的卡片圆角、留边和半屏弹层；不得把“设计留白”误判为系统栏漏底。
- **系统栏外观**：透明或与页面背景视觉连续的状态栏/导航栏处理、状态图标和手势指示器对比度应随明暗主题与壁纸正确变化；三键导航时允许 Android 平台必需的对比度保护层，但不得由 App 再额外制造独立黑条，也不能用隐藏系统栏、强行沉浸式全屏或覆盖系统手势作为修复捷径。
- **键盘与系统交互**：键盘弹出/收回时输入框与提交按钮可见，滚动内容按 IME 正确让位，不出现上下双重内边距或界面整体跳动；左右边缘 Back 手势与内容区开关侧栏沿用 #492 最终规则。横竖屏、不同屏幕比例/字号、刘海或挖孔和导航模式变化时，安全区更新后布局仍连续。
- **验收与证据**：每个可见 Scene/Host 页面至少记录一份对应最新 commit 的真实设备全屏截图并检查顶、底背景与内容可触达；额外用 Android **16 与 17** 分别验证 **手势导航和三键导航**，覆盖 Chat、Work、侧栏打开/关闭、至少一张长列表二级页、设置、Dialog/Bottom Sheet、键盘弹起与收回，并用截图/录屏对拍朝夕 E8.18 设计。登记设备版本、导航模式、主题、页面、复现步骤、修复前后截图和结论。任何系统栏漏底、黑带、双重避让、遮挡或点击不可达都记为 **P0 未通过**；静态截图或单次 CI 通过不可代替真实设备验收。

## 14. 逐页验收字段——用于后续实现 PR，不能省略

每个真实页面及弹层必须补齐以下验收记录：

- **入口**：从哪里进入、什么模式能看到、在侧栏/设置/消息/顶部哪个区域、是否允许搜索或通知直达。
