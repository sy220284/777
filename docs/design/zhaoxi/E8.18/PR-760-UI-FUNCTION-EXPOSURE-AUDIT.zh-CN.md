# PR #760 · 朝夕功能展示与会话生命周期联审

审计对象：朝夕 E8.18 的 75 个非宿主场景、36 项声明能力及 3 个宿主场景。以 `ZhaoxiUiPackManifest`、`ZhaoxiApplicationScenePack`、各 Scene 页面、UI Port 和当前 Session Owner 为代码事实，不将静态声明等同实际功能通过。

## 当前结论

- **入口结构**：75 个场景由唯一场景包声明/分发。检查主要 18 个场景与分发文件内的静态跳转、组件调用和空态；常量 `UiSceneId` 目标未发现超出场景目录的未知目标。动态目的地、实际状态与点击后副作用仍需要设备回归，不能根据代码字符串直接签收。
- **首页**：每个模式只有一个新建入口；聊天/工作模式选择不再主动生成正式历史记录。新建编辑器只有首次实际消息、计划、群聊/人物绑定或其他业务内容成立后才写入正式 Session。无内容旧占位不出现在最近列表或全局搜索。
- **草稿**：未发送文字及附件由现有加密 UI Draft Owner 管理，临时编辑器身份单独登记；侧栏只显示实际拥有草稿的未发送项，可重开。旧版已落盘空白会话只在确有未发送草稿时显示。**不得通过无条件删除旧 `blank` 记录清理磁盘**，否则会丢掉附件、人物、Work 运行及其他跨功能引用。
- **设置**：按已注入的模型表现、价格、用量、记忆等 Owner 条件声明目的地，设置首页只显示被声明可导航的入口。审批模式独立于 Android 系统权限。
- **导航与反馈**：导航动作继续通过宿主路由或对应 Feature UiPort；保留真实受理、失败和加载状态，禁止 UI 构造业务完成态。
- **设备基线**：合并 #762 后两套设备测试曾因 Compose 合并语义查找「设置」和依赖初始 Chat 模式的烟测失败。已改为使用正确语义树，并明确处理初始模式；本次改动必须以 #760 最新 SHA 的 CI 及 16/17 实测为准。

## 75 个场景按体验链路复查

| 场景域 | 场景范围 | 展示与动作应核验的重点 | 代码级状态 |
|---|---|---|---|
| 会话核心 | Chat、Work、页头、时间线、输入区、回复状态、消息操作、编辑、分支、阅读、模型选择、交互文档 | 当前会话身份一致；草稿不生成历史；发送/停止反馈；附件、消息、版本、模型路由与重新进入不串会话 | 已核对路由及核心 Session/Draft 主链；设备待验 |
| 人物与群聊 | 人物选择、图集、档案、画像、编辑、世界书、故事、手记、群公告、回复建议、表达偏好 | 无真实人物不展示假身份；群组有成员或人物绑定就不是空白会话；编辑/删除需真回执 | 已核对接线与有效会话资格；业务内容需真数据 |
| Work | 审批、问答、计划、调整、团队、技能与能力页 | 进行中任务和已写入计划不得当空白清理；审批不得伪完成；后台运行切会话后仍归原任务 | 已核对 Owner 边界和展示入口；并发/恢复待设备 |
| 自动化 | 任务列表、编辑、人物互动 | 新建/编辑/暂停/运行操作必须有真实 Owner 回执；空态有正确下一步；不自动派生新空会话 | 已核对条件路由；真实状态待设备 |
| 媒体与工具 | 媒体创建/结果、MCP、GitHub、插件、技能、工具能力 | 未授权、配置缺失、收费确认、生成中和失败要区分；文件、插件实际来源非假卡片 | 已核对各场景分发与现有入口；外部服务待连接验证 |
| 文件 | 工作区列表、预览、会话成果 | 列表/搜索/预览的路径来源和动作一致；不能把无文件误展示为成果 | 已核对展示分层及回跳；大文件/权限待设备 |
| 设置与管理 | 模型、账户、用量、配额、定价、记忆、权限、外观、通知、系统、存储、诊断、更新 | 有端口才展示入口；价格与用量不能伪造；切换模式不打断设置导航；写入有反馈 | 已修正入口可用性判定；端到端待设备 |
| Shell | 首页、新建、搜索、引导、错误、空态及顶级导航 | 入口去重；无内容不占最近历史/搜索；草稿可恢复；导航目标有效，错误可返回 | 已修正重复/空白展示及真实路由资格；设备待验 |

宿主提供的附件选择、系统权限和通知入口不计入上述 75 场景，它们仍需按宿主自己的入口和回执验收。完整逐场景业务要求与边界，继续以 [75 场景验收清单](V6-TO-ZHAOXI-75-SCENE-CHECKLIST.zh-CN.md) 为准；本记录不修改该清单中的“待逐动作验收”状态。

## 不可直接认定完成的边界

1. **历史旧空壳数据**：UI 已排除没有草稿且没有正式内容的展示项，但旧磁盘会话不会无条件批量删除。需要先确认 Session Events、附件、草稿、人物和 Work 引用，才能做存储清理；现阶段不以隐藏冒充清盘。
2. **75 个业务动作**：静态场景映射、按钮存在和已接端口都不足以证明外部收费、真实插件/GitHub、Android 16/17 的逐动作成功；保留待验。
3. **新编辑器**：临时身份注册和加密 Draft 的冷启动、模式切换、发送转正、旧草稿再开，都必须在同一最新 head 上验证；任何设备或编译失败均不标记完成。
