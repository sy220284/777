# 朝夕 E8.17｜渐进式回复界面与验收基线

> 本文件为 UI Pack 级视觉及交互实施说明。Host、Feature Port、Session EventLog 的架构约束以仓库 UI 3.0/架构权威文件为准。
> Figma 校对目标：<https://www.figma.com/design/oHivuQziUC5AbWET9tJXX9>。文件已建立，尚未完成画板和截图验收。

## 1. 全程同一阅读流

- 模型开始：在用户轮次后创建稳定 `reply:<sourceUserId>:0` 容器，原位显示状态和过滤后的临时预览；正式回复更新该容器，保留此前已完成消息。
- 连续输出：文字增量使用 `ZxRichReply`，对旧纯文本、标题、列表、引用、代码、表格统一解析；不向用户显示模型原始工具指令。
- 执行工具：依据持久事实在同一轮回复下展示 `work-live:<sourceMessageId>` 对应的轻量「执行状态」，默认折叠详细工具记录；结果未知、失败、待审批不得画成成功。不得再显示第二套独立任务卡。
- 阶段成果：实物证据、表格、图表、文本原位呈现；工具回执默认折叠，但可展开阅读。
- 最终结果：正式 assistant 消息进入持久 transcript 后，临时预览停止展示；不制造第二份完成内容，也不丢失已提交的成果卡。
- 已有聊天历史：原先纯文本回复继续采用同一富文本视图，加载历史分页后关联旧成果卡。

## 2. Android 手机交互基线

- 正文以 15sp/23sp 为准，图表/表格/代码分别保持结构化呈现；不允许用未经说明的占位语代替真实内容。
- 回复在底部时自动跟随最后一行；用户上滑后暂停跟随，显示「查看最新回复」，点击后恢复。
- 长回复超过屏幕时末行仍须可见；聊天输入法弹出、字号调整、深色模式、屏幕旋转不得造成错误的强制滚动。
- 生成中保留执行中的细节；完成后可收束为摘要与「执行详情」，收束只改变视觉层级，永久回执仍可查看。
- 高对比与 TalkBack：状态变化有文本标签，避免仅靠颜色指示；防止每个 token 高频播报。
- 动效：新内容轻淡入、状态图标平滑切换、详情展开过渡；动效统一走朝夕主题接口并尊重系统减少动画。

## 3. 数据与安全

- `LocalStreamingPreviewStore` 仅是内存中的当前请求预览，严格按 sessionId / requestId / mode / 运行状态隔离。
- `Session EventLog` 仍是工具执行及提交内容唯一事实源；`UiDocumentSessionStore` 承担成果版本更新及历史读取，不建立第二事实库。
- 文档动作必须经原 Feature Owner 受理；历史冷分页默认只读，不复活过期审批或权限。
- 新界面从中立 `ui-contract` 接入，Android UI Pack 不依赖 App 私有 Runtime。
- 当前流预览上限为最近 65536 字符，每 100ms 至多尝试一次普通预览更新；超长生成仍可能裁掉更早的临时文本，完整内容依赖持久提交的阶段/最终消息。后续应单独验收超长回答的前缀连续性。

## 6. 2026-10-18 体验优化实现规则

- **阶段与预览去重**：\`uncommittedReplyPreview\` 仅从请求内预览剔除已确认的持久阶段文字前缀；支持按空行、换行或紧接方式合成的累计输出，以及只包含增量的提供方。无法证明重复的片段原样保留，不得依据相似词删除内容。
- **阅读尾随**：当前回复仍在屏内时，只补偿新增长度造成的底部溢出；进入屏外才定位末项。**用户主动拖拽**离开尾部后停止追随，程序自身滚动不得误判为用户退出；「↓ 查看最新回复」复用同一末行可见逻辑。持久阅读锚点使用追随意图，避免在程序调整中错误保存退出状态。
- **阶段视觉**：阶段消息继续属于同一稳定回复容器，后续阶段压缩为 2dp 上下间距并隐藏重复头像；用户消息保留原气泡布局，助手结果仍使用统一正文排版。
- **动态状态**：三个小圆点采用相位交错的轻量淡入淡出动效，同时暴露「正在生成回复」的无障碍状态描述；动效随 Compose/系统动画倍率运行。正文文字仍以纯文本可读性为第一优先级，不对每个 token 逐字施加大范围位移动画。
- **覆盖**：JVM 回归验证「累计预览 + 多阶段」「晚到的旧预览」「增量单独输出」；设备侧仍须人工确认持续输出超过一屏、阅读旧消息暂停尾随、点击返回最新及 TalkBack 播报频率。
