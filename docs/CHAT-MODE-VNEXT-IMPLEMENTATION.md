# 777 聊天模式 VNext：人物真实性、记忆、交互与质量整体迭代

> 状态：执行中。以主线 + PR #604 V4 人物基线为输入；本文件是一份可核验的实施契约，尚未实现的功能不得记为交付。当前 Figma Starter MCP 限额阻断画布写入，界面以 Compose 代码为权威实施入口，待额度允许时同步到既有 Figma 文件。

## 产品目标与非目标

目标：角色身份可信、人物独立选择、故事知识连续、长时记忆可追溯、群体互动自然；在合法请求正常运行、少额外 Token 与单一 Owner 的条件下交付。
不扩充人物卡为人物运行时容器；不叠加第二记忆库、第二 Session owner 或新的常驻 Agent；不因风格规则误报而阻断正常对话；不以虚假成功或人工构造的 CI 证明验收。
普通聊天保持轻量链路，未绑定角色时不注入人物运行时。

## 实施先后与依赖

### A · 事实正确性与 V4 统一（P0）
- A1：用户编辑、原作事实、AI候选与自动推断采用统一的写入权限；所有同ID新增/覆盖/导入/合并链路逐个审计。当前已改 `PersonaAutoFillService.mergeGeneratedCharacterFacts` 的模型同ID覆盖与自行宣称 CANON/USER_CREATED 的逻辑。
- A2：在当前 V4 字段的真实消费者全部替换、回归后无损退出旧字段；独立行为参数由 Chat 运行时保持，不回写档案事实。
- A3：明确区分故事阶段、场景钟表、事件已发生、人物实际知晓。先定义可持久恢复的阶段顺序/授权解锁契约；无顺序资料时维持保守精确匹配，严禁靠 `act-2` 这种字符串猜测解锁等级。解锁成功后保留此前已获得的知识，故事分支回退时必须恢复其分支的知识水位。
- A4：`CharacterLoreEngine` 的剧情阶段/剧透权限应从独立授权来源传入；所有单聊、群聊、主动消息、人物检查共同遵守人物视角。不得在无授权状态下单纯把 `maxSpoilerLevel` 默认值提高。
- A5：同名身份、版本故事、当前活跃会话、后台延迟保存、显式删除互相覆盖的实测。

### B · 记忆与连续性（P1）
- 沿用 Shared Memory、Chat 日记、ChatContextState 和事件历史，统一声明稳定事实/经历/临时状态/人物主观看法的选择与失效规则。
- 基于明确词面线索快速召回；复杂同义、指代、因果追问使用现有可用的语义能力，不在每轮追加模型请求。
- 旧记忆可历史查询，但被修正或撤销的版本不得重新成为当前事实；跨故事和群聊权限按人物/故事/受众隔离。
- 以短问答、代词回指、相同事件多次变化、断线编辑、分支撤销、100–300 轮长聊为测试集。

### C · 角色自然决策（P1）
- 复用 Attention/Behavior/Evolution/Life 各既有组件，将本轮信息、人物已知事实、独立目标与行动成本综合形成可解释的临时行为投影，不创建持久化的并行“角色大脑”。
- 允许反驳、坚持、拒绝、主动、沉默、修改判断；重大人格变化必须有经历来源，短期心情仅影响当下。
- 对至少三种核心价值不同人物进行同事件多轮对照；关注选择差异、后续连续性与是否反复套模板。

### D · 群聊与主动消息（P1–P2）
- 群聊保留 2–6 人和预算上限；本轮后续发言者应按真实已提交的成员发言调整状态；支持沉默/插话/冲突，同时继续防止单聊 PRIVATE 与 SHAREABLE 日记外泄。
- 主动消息由已有 Automation 单一调度 Owner 管理，根据未完约定、生活节拍、实际消息价值选择是否发送；不复制调度器。

### E · 响应性能、错误与用户操作（贯穿）
- 主回复、摘要、自动整理、建议、修复的使用量独立记录；采集固定路由/模型下的 tokens、缓存命中、首字时间、尾延迟、额外请求比例。
- 少量日常交互优先确定性更新，重要状态变化才增加模型分析；减少重复 stable prompt 和事实拼接；优先保持供应商缓存前缀稳定。
- 将输出检查明确分为必须纠正的确定性错误、可轻量补救的文本问题和无需阻塞的风格偏差；风格调整不吞掉已可用的合法回复。
- 编辑、重生成、改变模型档位、流式中断、切换故事、恢复队列的操作始终受单一 Session/Run owner 控制；错误要可诊断、可重试且不丢失用户输入。

### F · 闭环验证
- 程序：21 预设、V4 用户编辑/AI补全/合并/JSON/Markdown/Word、阶段知识与剧透、日记私密和撤销、群聊承接、任务/模型 route 冻结。
- 环境：同一 Head 的 Kotlin 单测、architecture gates、ARM64 APK、x86 APK、Android 16/17；真实联网/套餐配额/长时用户体验不冒充 CI。
- 质量：相同模型和输入下的 100–300 轮角色对照、角色差异评估、错误记忆率、隐含召回和实际 P50/P95 请求成本。先有基线才承诺改善百分比。

## 用户端交互和 Figma 对齐

沿用既有 Android Compose 主题、导航、输入、BottomSheet 和 Design System，拒绝另建平行 UI。
1. **聊天页**：顶部明确显示普通/角色/群聊身份、所属故事和已生效的阶段；仅在加载/处理/失败等影响用户行动的状态出现轻量反馈；流式未完成时显示可恢复操作，不用隐形状态代替成功。
2. **人物页**：默认“身份、核心性格、重要经历、关系、价值取舍”，高级抽屉显示剩余事实、来源、原作知识、适用阶段和关联事实；AI 新事实先显示候选及可信度，不自动标成作者确认。
3. **故事页**：阶段显示人类可读名称并支持选取当前阶段；区分阶段进度与实际角色知情，阶段修改要有保存/生效反馈；保留手动输入技术ID的高级入口，不强制用户理解ID。
4. **群聊页**：清楚表明消息发送对象、当前发言者和消息部分失败；允许进入人物单聊而不携带未获公开的信息。
5. **人物日记与纠正**：用户能够定位当前有效经历、历史版本和取消后的变化，显示权限与来源，相关恢复失败提供可诊断提示。
