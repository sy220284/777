## C. 选定方案 07 的完整工作包与落地顺序

### 阶段 0：冻结基线与安全 P1（#854、#855）
- **CLAIM**：`LocalSubagentInboxRecoveryScan` 对匹配 job 的 claim payload 解码失败强制中止（保留 checkpoint/event，不续跑）；其他 job 不误阻塞，合法空消息可读。测试坏版本、缺失/空内容、跨 job、长分页和有序重复消息；补 SQLite 进程死亡恢复设备测试。
- **MEDIA GC**：在持有数据库写事务期间判断全部 session 的非 deleted 记录是否仍引用文件；保留被共享文件，最后一次引用消失才删除。坏 JSON 解码必须 fail-close。按 v1 schema 采用扫描保护，后续在真实数据量测后单独改 indexed ownership，不在安全热修中冒险 schema 升级。
- **停机线**：出现付费结果找不到文件、不可解释的副作用重放、真实旧会话丢失则立即阻止发布并回退改动；禁止用“文件行数减少”签收。

### 阶段 1：存储真实设备验收与 Release 保护（#853、#318、#781）
- 旧正式 APK 覆盖升级：保留历史单聊、群聊、Work、轮转/压缩 JSONL、图片附件和待结算任务。迁移前后对账 session IDs、事件序号/时间、媒体 hash、模型历史、任务 ID、外部副作用 receipt。
- 进程故障矩阵：旧→新迁移、恢复 stage、INSTALLING/WAL checkpoint、容量耗尽、重复启动、业务 WAL/SHM、仅空库 WAL；恢复界面可达，任何未知结果不隐式重试写工具。
- #781 复核：当前已有删除失败的 tombstone/pending 补偿，新增“删除前主动终止 Work、磁盘删除失败、再进入会话”测试，决定是否补用户级重试/恢复语义。
- P50/P95 测量：指定 Android16/17 设备型号、内核页面、APK SHA、夹具 SHA、内存 PSS、冷热查询和压测回合数；区分物理真机/模拟器。Page Matrix attempt2 四组合绿，attempt1 Android16/16KB LOW_MEMORY 属非稳定故障，保留长压测复验。
- #318：仓库管理员设置 main Ruleset、required `CI / merge-gate` 和禁止 direct push；做红 PR/绿 PR/直推三项真实阻断试验。**当前插件不能改仓库管理员保护设置，必须待账号操作后复查，不得宣称完成**。

### 阶段 2：一致备份/恢复与产品语义（#856、#848）
- 在未支持前，所有“会话备份”入口标明包含 session SQLite/attachments，但不包含 media-studio 独立成果原件和 DB；不得写“完整全应用备份”。
- 与 #848 合并 Owner 设计 manifest（version、数据域、相对路径、sha256、byteCount、correlationId）、同批快照一致性、可用剩余空间检查与 fail-close 缺文件策略。不得在用户有现存权威数据时覆盖导入。先完成真实图片/音频/视频、下载媒体和跨会话共用验收，再开放“完整备份”标签。
- 迁移/恢复任何失败都保留原 ZIP、数据库和可独立验证的 hash 清单；设置和文档展示恢复限制。

### 阶段 3：执行与界面拆责（#859、#858、#857、#817）
- **Work**：把 `run()` 中模型请求循环、Goal transition、ToolReceipt、lease/projection cleanup 分成具有明确输入/输出的不可变阶段；每次只分出一个可测试单元，不重建 RunRegistry 或 EventLog。故障/权限/未知 side effect 保真。
- **Team**：按成员生命周期、收件/ACK、任务板版本、消息交换、证据/结算、恢复投影六域划分 Port；消息和 result 仍写同一个 Team owner；测试并发 start/stop、进程中断、交叉 owner 等待。
- **Chat/UI**：先从 `LocalConversationSurfaceBody` 提炼无权威写入的纯 UI 元件/状态投影，隔离手势、弹层、输入、历史列表，再收敛 Harness/Settings；对双入口提交幂等、音频 A→B→A、进后台/回前台、导航、视觉无退化回归。
- **root package**：40 个直接 Kotlin 文件逐一登记当前依赖消费者，只迁移真实职责混合的类型，不能按名称或数量机械拆。千行数和耦合度作为趋势，不当成“必须拆到某行数”的交付条件。

### 阶段 4：技能、人格、元数据（#860、#817、#842）
- **技能**：明确手选 > 用户固定 > 动态目录匹配，installed SKILL.md front matter 做唯一可变激活数据，内置 12 条仅可解释提示/兼容映射。显式 `@skill` 按模型上下文预算分页/摘要并保留主动工具获取全量，不能静默丢关键说明；验证 route/token/长技能/user-only。
- **人格**：Preset catalog 904 行与约 75 KB 改为受版本控制的结构化资源，保持 ID、语义、排序及旧数据兼容；快照/反序列化/安装升级/缺损恢复测试齐备后移除硬编码，不造第二来源。
- **FEATURE**：19 个文件约 1.54 MB，拆成生成热索引与冷历史/审计证据；从单一权威配置生成，添加增量一致性和退役边界测试。不可因为体积而删除验收历史和来源追溯。

- 所有集成在 `main` 同一 SHA 重新核对，附持久化副作用、媒体、UI、性能和故障证据；禁止将旧 SHA 的绿灯“继承”为新代码的签收。
