## 发布的硬性门禁（必须保持）

1. 发布候选必须与 GitHub main 的完整 push CI 验证提交一致或经已验证的不影响产物变更等价规则确认。
2. scope、static-gates、architecture-3-gates、unit-tests、build-arm64、device-artifacts-x86、Android 16、Android 17、merge-gate 均须通过；仅 PR CI 不具备签发资格。
3. 正式 `RELEASE_KEYSTORE` 与 `RELEASE_KEY_PASSWORD` 必须有效，签名别名与 APK 校验通过；拒绝未签名、签名不稳定或无法安装升级的 APK。
4. 发布版本从最高未退役的正式 tag 单调递增，发布资源必须包含 APK、SHA256 和更新清单；增量资源按原工作流判定是否可用。
5. 发布前检查本次快照确有二进制变更。保留发布失败的明确错误和独立回滚能力，不手动伪造 CI、跳过签名或伪造视觉证据。
