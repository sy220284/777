# 777 离线跨功能验收及证据门禁

## 执行范围

本批次针对 **不需要真实外部账号、付费模型、物理设备辅助技术或真实长期等待** 的可重复场景扩充测试。依托现有 `unit-tests`、Android 16/17 `instrumented` 和 `static-gates`，避免新增第二套运行时或自行模拟生产结果。

- 会话 + 项目：历史会话在项目目录重置后必须拒绝丢失项目规则；含历史会话引用的项目不可删除。
- 会话 + 事件：1024 条消息与工具噪声交织，日志分段轮转后冷重启，分页必须不丢、不重、不乱。
- 自动任务：多线程并发创建任务，冷恢复全部保留；同 ID 多次删除、重建、恢复时旧 Worker 不能结算。
- 设备可重复测试继续使用仓库现有 Android 16/17 仪器化矩阵，覆盖项目确认、错误反馈、输入法、手势、可访问性基础扫描等。

## 427 末级功能索引

`docs/ACCEPTANCE-MATRIX.json` 严格记录功能树的 427 个末级节点；`static-gates` 中的 `check-acceptance-matrix.py` 检查：

1. 功能树所有末级节点和索引逐条一致，禁止漏行、重复和静默漂移；
2. 已标记 `automated_partial` 的节点必须指向存在的 Kotlin `@Test` 方法；
3. 没有证据的节点保持 `unverified`，禁止将“有测试文件”解释为全功能验收通过；
4. 本索引不提供“完成”选项，最终验收必须有独立设备/性能/人工体验等证据。

更新功能树时应同步索引；增加新的测试用例后补充具体叶节点的 `evidence`。CI 通过代表**索引与自动化证据引用有效**，绝不代表 427 项测试通过或人工验收结束。

## 仍需独立实测的环境

真实 ChatGPT/OAuth 和供应商套餐、实际远程主机和 GitHub/MCP 授权、真实通知系统权限与 TalkBack、跨天定时准确性、长周期/大规模真实设备性能等保留待验收。必须在每项独立提供可审计的设备型号、系统版本、代码 SHA、操作、日志及结果，才能签收。
