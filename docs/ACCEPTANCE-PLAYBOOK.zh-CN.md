# 777 离线跨功能验收及证据门禁

## 执行范围

本批次针对 **不需要真实外部账号、付费模型、物理设备辅助技术或真实长期等待** 的可重复场景扩充测试。依托现有 `unit-tests`、Android 16/17 `instrumented` 和 `static-gates`，避免新增第二套运行时或自行模拟生产结果。

- 会话 + 项目：历史会话在项目目录重置后必须拒绝丢失项目规则；含历史会话引用的项目不可删除。
- 会话 + 事件：1024 条消息与工具噪声交织，日志分段轮转后冷重启，分页必须不丢、不重、不乱。
- 自动任务：多线程并发创建任务，冷恢复全部保留；同 ID 多次删除、重建、恢复时旧 Worker 不能结算。
- 设备可重复测试继续使用仓库现有 Android 16/17 仪器化矩阵，覆盖项目确认、错误反馈、输入法、手势、可访问性基础扫描等。

## 仓库可执行证据索引（与功能树分离）

`docs/FEATURE-TREE.zh-CN.md` 是功能清单的权威来源，当前为 **427 个末级功能**，不因测试环境限制删减产品功能。仓库 CI 验收索引 `docs/ACCEPTANCE-MATRIX.json` 仅保留 **126 个具备直接 `@Test` 证据引用的功能条目**，状态统一为 `automated_partial`；其余 **301 个功能节点没有收录为仓库验收项**，不计为本次 CI 必须执行或必须签收的测试，也不能据此视为功能已验证。

`check-acceptance-matrix.py` 检查全部证据条目均出自功能树、无重复且顺序正确、所指 Kotlin `@Test` 方法真实存在。新增可执行测试时再将对应节点加入索引。不会为了凑齐功能树叶节点而增加空的 `unverified` 验收项。

以下验收条件**移出仓库 CI 验收范围**：真实 OAuth/供应商账号及收费额度、实际外部 GitHub/MCP/远程主机授权、物理设备 TalkBack 等辅助技术、厂商通知/后台策略、跨天长周期性能与电量观察。它们可以另行现场验证，但不能阻止仓库内可重复测试验收。具有本地模拟或 Android CI 可验证的相关安全、恢复、协议和权限行为仍执行现有自动化测试。

**边界**：126 项仅有局部可执行断言，完全签收数量仍为零；301 项未列入仓库索引的产品功能既没有被判失败，也没有被判成功。CI 绿灯只代表本次选中的代码与测试检查通过。

## 2026-10-09 后续审计批次：扩大离线可执行证据

- 新增 `OfflineCrossFeatureAcceptanceTest.queuedDeletionCannotResurrectProjectReferenceAfterRestart`：会话入队→项目关联受保护→迟到会话入队→删除→冷重启→项目可删除，核验历史会话删除屏障和项目关联之间的真实持久化边界。
- 基于仓库**已存在的具体测试方法**补录自动化部分证据，优先覆盖 Chat/Work/群聊、自动化日程、Webhook、会话分页、模型协议及配置、内存回滚、工具路径安全、权限与恢复。
- 索引中 `automated_partial` 只代表该功能某个不变量已被 `@Test` 检验；其他功能仍保留在功能树中，不以占位验收条目拖累仓库 CI。
- 测试的合格结论取决于最新 head 的 JVM/Android 16/17 等被选中的门禁成功结果；不可依赖过去 commit 的通过记录。

**二次代码审计校正**：撤销 11 处跨功能间接关联（例如模型预算等待不等于 UI 拒绝发送反馈、最终回复去重不等于工具结果回填、事件日志读取不等于运行中心工具活动时间线、Webhook 状态向下兼容不等于接收校验）。保留 126 个直接部分自动化证据条目；其余 301 个功能叶节点不再作为本仓库 CI 验收项目。证据必须直指本功能的一项真实行为或不变量；不因测试名中有相似名词就记账。

**注意**：索引校验对测试方法的静态存在性负责，尚未进行逐方法的覆盖率证明。真实 OAuth、外部付费、物理设备无障碍体验仍需外部环境。
