# Chat 统一运行逻辑（对话事件、状态、注意力、记忆和执行）

> 对应 PR #666。本文描述可从源码核对的职责边界和运行路径，而不是给角色增加固定台词、动作和回复模板。

## 一份原始事实，若干可再生成的投影

1. **事实原本**：当前故事/分支的用户与角色原始消息和持久化事件日志。模型归纳、日记、角色内心推测不具备篡改用户实际表达的权力。
2. **事件与证据**：ChatSceneEvent 提供时间和地点的确定性变化；ChatContinuityEvidence 提供最近事件、决定和待续事项的消息来源与稳定 eventId（旧记录在归一化时补齐）。历史保留，完成意味着从“仍待续”投影中退出，而非删除历史消息。
3. **当前人物状态**：ChatCharacterState 的身体、情绪、主观印象、关系和当下行动，只描述目前成立的情况；事件重要度 NONE/MINOR/MAJOR 不应阻止证据明确的字段清理。模型省略字段保留现值，显式空值是状态清理信号。
4. **对话注意力**：ChatContextState.attention 记录最近用户主题和明确暂停的话题。它是分支局部状态，随已完成对话更新，不改变事实、人物意愿或行动。弱回复延续原真实表达，而不是直接将待续列表当成用户新需求。
5. **请求级投影**：ChatTurnContextPolicy 为普通角色生成、回忆、剧情摘要筛选与定时主动互动提供统一语义入口。仅投影本轮所需的旧事件；当前硬场景优先保留。不能把存储中“未完成”解释成“每轮必须主动提起”。
6. **后台归并**：LocalChatContextRefreshCoordinator 读取 durable Pending，按事件顺序向同一模型 Planner 更新状态，校验会话、分支 generation、processedThroughSequence 和写入依据；成功批次推进游标，失败保留待处理原文。

## 每轮工作顺序

用户提交 → 持久化用户原话 → 提取当前用户意图/分支身份 → 按优先级投影人物与事件上下文 → 角色自由生成 → 场景连续性检查 → 持久化角色回复 → 追加场景事件和 Pending → 更新注意力状态 → 异步状态对账/日记 → 按版本确认并推进 Pending 游标 → 后续消息直接从已确认状态投影。

**信息优先级**：当前用户实际指令与明确纠正 > 最近已发生的原始对话 > 现场硬事件与真实行动 > 与本轮有关的已确认事实、承诺和旧经历 > 人物稳定性格与世界知识。人物主观印象要保留主观来源，不伪装成用户客观事实。

## 事件结清约束

- Planner 对新状态只写变化；如果结清旧待续事件，提供 `resolvedContinuityIds`，ID 必须来自该故事当前有效的待续事件清单。
- 系统不能只凭“好”“答应你了”文字删除随便一件旧事；要求模型未继续保留该事件、指向相应 eventId，并通过双方对话依据检查。
- 已完成历史不会从原始对话消失，另一次明确提起仍可回忆；事后纠正使用更近的事实和事件版本。
- 不因为轮数或模型 token 数让真实承诺自动到期；只让不相关事实暂时不参与当前回答。

## 生成入口的一致性

- 直接聊天和群聊成员经由 `ChatTurnRunner`/`CharacterRuntimeProjector` 使用统一选择策略。
- 普通角色与未绑定角色的故事摘要经同一策略筛选。
- 定时主动消息读取触发意图相关的待续事件/人物计划，不能凭旧的生活事件重复找借口。
- 角色卡、剧情世界知识仍由人物知识边界控制；“注意力筛选”不得覆盖明确的人设设定或变成固定表现脚本。

## 执行与诊断原则

- 单聊后台归并采用一个执行任务 + 一个合并待运行信号的单通道所有权；新用户消息排队不取消正在整理的批次，新信号只替换尚未启动的下一个任务。前台编辑、切换或明确停止可以取消两项任务。
- Pending 原文持久化，当前会话分支版本检查阻止旧推断写入新分支。成功处理一个批次后，失败重试预算应复位。重新载入单聊会话时，根据 processedThroughSequence/pendingThroughSequence 恢复归并调度，不依赖下一条用户输入。
- `chat/post-turn` 的 `updated`、`stale-discarded`、`parse-failed`、`session-busy` 等事件是排查积压的证据；不能从快照中有 Pending 直接推断为永久卡死。

## 回归矩阵与仍待设备验证的环节

- 话题暂停后连续弱回复不重新召回旧待续；明确重提时允许找回；否定句、保密请求不误判为换话题。
- 双方确认同一个约定时精准结清；含多个同类事项时，错误 eventId 或模糊答复不能误删。
- 场景口语“到了才讲”不写成地点，旧档案恢复依据旧有效事件；已发生移动/合法时间推进可正常更新。
- NONE 重要度仍处理明确结清、取消、清理，而不是强制维持旧状态；人物真实情绪/行动变化保持连续。
- 群聊、分支恢复、主动互动和历史导入复用上述投影，不携带另一故事的旧状态。

**未由静态代码验证的项目**：多模型真实 100+ 轮对话对照、持续弱网下后台队列与设备实际耗电、App 进程死亡后不打开应用情况下的系统级后台唤醒、Android 16/17 设备行为、主线近期并行 PR 合并冲突。当前仅实现重新打开会话时恢复 Pending，不承诺后台服务被系统杀死后自动常驻运行。这些必须以专项日志、CI/设备测试证据为准；本文件不将其标为已通过。

## 2026-10-13 架构收敛（非平行新状态库）

- `ChatContinuityEventIdentity` 只做有明确对象的旧文本事件别名匹配；检索相似性不得裁决两个事件是同一承诺。结清仍要求稳定 eventId、Planner 指明、原始双方证据三方一致；多个问题只允许有明确主题的确认。
- `ChatStatePatchAuthority` 是唯一字段级权限入口：NONE/MINOR/MAJOR 表示长期记录价值，不阻止证据明确的字段更新。NONE 新增状态需真实原话，明确清理允许通过；有效关系阶段仍由独立事件证明。
- `ChatUnifiedTurnContext` 是普通、群聊、主动生成的最终上下文组装口。每个 `ChatContextPart` 保留 LIVE/HISTORICAL/RECALL/INSTRUCTION 来源；多次入口传递保留来源，不允许把全部上游动态内容改标成 LIVE 绕过本轮话题选择。
- `LocalChatPostTurnJobOwner` 将原来新请求取消旧归并改为正在执行与待执行信号分槽管理。会话从磁盘恢复后，由 `LocalForegroundSessionLoader` 触发 `LocalChatComposition.resumePostTurn`，重新调度已持久化的未处理批次。
- 长期回忆与日记读取阶段也使用同一请求级历史可见性策略；所有过滤只作用于本轮 Prompt，不清除持久原始事实。

验收仍以**最新 GitHub CI + 原始长聊回放 + 设备现场**三种独立证据为准。不得用旧提交通过记录替代新提交验收。
