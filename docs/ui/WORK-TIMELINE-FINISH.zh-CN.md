## 前后台连续输出补充（2026-10-20）

本轮核对发现：原 Work 执行和持久消息已经由会话绑定的独立协程持有，但流式预览受当前可见会话限制，返回时若没有新片段就不能恢复；已有过程行还会隐藏空白阶段的等待指示。失败/停止记录在持久历史中存在，却被展示层两次过滤。前台服务只提升进程优先级，没有持有锁屏任务所需的 CPU 唤醒。

修复沿既有边界收敛：

- `LocalStreamingPreviewStore` 只保存仍活跃请求的有界预览，`LocalRuntimeStateStore` 初始化和切换会话时选择可见投影；后台增量与可见性无关。相同会话的新请求淘汰旧身份，旧片段和迟到清理不能覆盖新请求；请求最终退出回收，包含预检失败和上下文溢出恢复。
- 共享模型请求执行器使用真实尝试事件投影等待/重试；没有正文时仍显示状态，不再因存在旧工具步骤而隐藏。最终正文和工具回执继续来自 SessionEventLog，不依赖页面订阅或流式缓存。
- Work 展示已存的“执行失败”“本轮已停止”消息；Chat 的系统消息过滤保持原契约，系统提示词不作为可见正文暴露。
- 自动跟随使用读者主动拖动形成的阅读意图；大量后台输出、热窗口淘汰、被后续事件取消的滚动不再因旧尾行测量缺失而退出跟随。主动读历史时保留位置并持续提供回到最新入口。
- `LocalExecutionService` 在真实活跃回合/任务期间持有一个共享 `PARTIAL_WAKE_LOCK`；最后任务释放、启动提升失败和服务销毁都释放。重复步骤不叠加引用，无任意任务总时长限制；不点亮屏幕，不另建执行者。

平台边界：CPU 唤醒不绕过 Android Doze 网络限制，也不能使被强行停止的进程继续运行；断网/未知副作用继续遵守既有真实状态与恢复规则，不因返回页面自动重放工具。

验证涵盖 JVM 的预览切换、后台新增、重试恢复、迟到请求和运行时挂接；Android 的生命周期停止/恢复、热窗口批量更新、读历史不抢滚动、真实 PowerManager 唤醒获取/释放以及等待/重试显示。生命周期测试使用真实 Compose 与 LifecycleRegistry，唤醒测试使用平台对象；不冒充真实手机熄屏/VPN/厂商省电长时验收。

功能树无需新增节点：本次完善既有“流式回复、状态指示和过渡动效”“前台服务和 Android 后台执行”“后台结果到前台状态同步”，归属及入口不变，新增唤醒适配仍由现有 Service 唯一持有。
