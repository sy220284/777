# 模型协议与数据链路修复

本次修复以既有 28 个预置模型和 Chat Completions / Responses 传输为范围。

- Chat Completions 的 HTTP 200 SSE error 不再视为空白成功。length、content_filter 和未知终止原因不再视为完整生成；非流式 length 同样拒绝。
- 流式工具调用按 index 合并并保存厂商扩展字段，包括 Gemini extra_content.google.thought_signature。非流式历史继续保留原始扩展字段。
- Responses 函数调用必须具备 call_id、name 和合法 JSON object arguments；不生成随机工具 ID，不把损坏参数降级为空对象。
- Responses 续轮以经过风格过滤的 canonical content 更新 native assistant message，同时保留 reasoning 和工具调用顺序。未知媒体 block 显式拒绝，不静默丢弃；图片 detail 得以保留。
- HTTP Call 的生命周期覆盖 execute、响应体读取和 SSE。协程取消直接取消 Call，避免首个响应头之后阻塞读流；取消不重分类为可重试网络错误。
- 子代理工具执行通过协程上下文绑定不可变 profile，视觉工具使用该 profile 的 model/base URL/协议/凭据。前台默认路线保持当前配置；缓存键增加 profile ID，避免不同来源混用视觉结果。
- 工作与子代理尊重显式 TOOL 图片模式；不支持视觉的模型仍明确拒绝，不声称视觉工具可以赋予纯文本模型视觉能力。
- MiniMax 的图片直传与视觉工具均采用 10,000,000 字节上限，已有每轮并发/总量预算不变。
- 预置 Claude Sonnet 使用官方当前 ID claude-sonnet-5-5。已有用户自定义配置不被静默改写。
- 客户端能力标签只列已接入的文字和图片，并明确提示音视频尚未开放；原有官方模型能力目录保留，便于后续实现。
- GPT-5.6 默认推理模式不发送 temperature；Sol/Luna 的 API Key Responses 路线省略采样参数以保留默认推理。Chat 路线继续以 reasoning_effort=none 支持其工具/采样限制。
- ChatGPT 套餐 namespace 补齐必需的 description；完整 strict schema 适配另由独立 PR 处理。
