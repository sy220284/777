## 后续必须设计完整而不是局部打补丁

### C1：热索引与冷证据分层（基础修复已实现，压测待签收）

继续把 EventLog 保留为唯一事实源。热索引只保留未结图、活跃 Job、近期读写所需键和准确 `throughSequence`，越过容量时不清空增量游标。已结束图/Job 的历史事实仍可按 execution/jobId 从 EventLog 或经 Session Owner 维护的有界持久索引读取。任何冷查询均不得把失败/未知副作用判为成功。测试连续查询同一超过阈值的已结会话，第二次无新事件时扫描数量不得等于完整历史长度。

### UI-01：动作消费属于会话权威事实（基础修复已实现，设备验收待签收）

将一次性文档命令的稳定键与 `SendText` 同时传到 Work 受理 Owner，在同一持久入队/受理边界写入提交事实及回执；重复命令返回原结果。展示层只投影此事实，不再用 `remember` 的局部 submitted 充当业务状态。拒绝、草稿准备及显式允许再次提交都保留原语义。测试消息详情/顶栏双入口连续提交、关闭重开、A→B→A 和重启后的同 revision 受理计数恰为一次。

### S1/S3：旧 ZIP 隔离转换与可达恢复模式（基础入口已实现）

旧 ZIP 不直接混入活动 Session。先隔离解包，用原版导入/校验机制构造旧权威会话文件，再进入同一只执行一次的文件→SQLite 规范化入口；检验 event sequence、cursor、媒体哈希、会话数和工作恢复状态。活动用户数据存在时提供明确的替换/保留/取消选择，禁止无提示覆盖。保持迁移和恢复的持久意图在数据库 Owner，失败保留原件；必要时从设置/启动恢复界面取消未开始安装的计划。区分未安装、正在安装和已完成，部分安装时不能直接继续应用暴露混合库。

## 验收矩阵

- 旧发行 APK 覆盖升级：单聊、群聊、Work、JSON 备份、副本、轮转及压缩事件段；恢复后事件序号/模型历史/附件引用一致。
- 迁移与恢复：中途 SIGKILL、合法空库 WAL/SHM、带业务数据 WAL、存储空间耗尽、重复启动、删除全部会话后恢复。
- 策略与扩展：同验收成功、明确失败、steering/取消、Goal A→B、MCP 源与清单双写故障、注册→下一步暴露→真实调用。
- UI：同表单两个入口重开、同槽位音频 A→B→A、prepareAsync、Android17 后台暂停。
- 恢复索引与性能：>4096 历史事实、0 未结图，三次相同查询的 appliedEvents/decodedRows；真实 SQLite 长会话 P50/P95、内存峰值。
- 所有高风险修改最终在 #850 同一 HEAD 上完成 JVM、架构门禁、ARM64/x86、Android 16/17、Page Size Matrix 和真机条件验收。跳过的 lane 不能称为通过。
