# 双色球历史数据与模型研究

本仓库用于保存双色球历史开奖数据、模型版本、滚动盲测、随机对照与奖级评估结果。

## 设计原则

- 只增加能够解决已验证瓶颈的功能，不为复杂而复杂。
- 简单方案能达到同等或更好效果时，不引入额外模型层级。
- 新模块必须先证明候选池或概率预测存在增益，再看奖级；不能只靠偶发大奖晋级。
- 旧历史用于研究与筛选，新增真实开奖的独立前向表现权重更高。
- 没有检测到高于随机基线的有效信号时，模型必须降低集中程度，不允许强行输出高置信判断。

## V4.5.1 核心改动

V4.5.1不增加新的号码预测模型，只增加一个与随机理论基线直接比较的总开关。

随机选择12个红球时，每期平均应包含：

`6 × 12 / 33 = 2.181818` 个真实红球。

每期开奖前，V4.5.1统计目标期之前最近250期V4前12候选的实际平均命中：

- ≥ 2.181818：允许使用V4.5高奖集中策略；
- < 2.181818：认为近期候选池没有表现出高于随机基线的增益，回退V4.3分散策略。

实现见 `models/v4_5_1/signal_gate.py`，配置见 `models/v4_5_1/config.json`。

## 随机性/时间信息检查

新增 `tools/signal_radar.py`，对V4前12候选做时间顺序打乱检验。2000次打乱结果：

- 前12平均命中：`p≈0.2455`，未证明时间信息增益；
- 前12含4+：`p≈0.0595`，接近但尚未形成稳固证据；
- 前12含5+：`p≈0.5355`，无优势；
- 前12含6：`p≈0.26`，无稳固优势。

结果见 `backtests/v4_5_1/signal_radar_shuffle.json`。

## V4.6 已淘汰路线

更快重训练、快慢模型动态切换、V4候选池内快模型重排、加强逻辑回归正则都没有同时改善长期奖级与新增55期，因此不进入主模型。详细过程见 `docs/V4_6_EXPLORATION.md`。

## 下一步

1. 不继续微调V4.5.1的250期窗口，先保持冻结。
2. 优先验证真正能提高“前12含5+真实红球概率”的新信息；只有通过真实顺序、打乱历史和独立前向三重对照才允许进入预测器。
3. 下一阶段先做概率校准：让33个红球输出可解释概率，并检验概率是否真的比18.18%随机基线更准。
4. 若概率校准仍无增益，则不增加复杂状态模型；继续维持低置信分散策略。
5. 如取得可靠开奖设备、球组批次等独立外生数据，再单独验证其增量价值。

> 彩票开奖具有高度随机性。当前结果只代表历史研究表现，不证明未来可稳定预测或保证中奖。
